# 第 3 章 · 训练流程：教练机制与双三角模型

---

## 一、为什么这一章存在

### 1.0 训虾哲学开篇 · 训练学为什么是协议层，不是 prompt 层

#### 1.0.1 一个被行业反复确认过的错觉

2026 年的 agent 生态里，"微调"和"提示工程"是两门显学。前者的叙事是"用你自己的数据把模型变成专家"，后者的叙事是"把话说得更准，模型就更听话"。

这两门显学都建立在一个共同的假设上：**要让一个智能体变强，得改模型那一侧。**

本章要提出的判断与这个假设正面冲突：**在一只长期运行、有角色、有职责、有验收方的组织型智能体身上，主要的成长杠杆不在模型那一侧，而在协议那一侧。**

这不是修辞上的分工，而是一个可以被成本结构直接证明的结论。请比较下面三条"让它变强"的路径，并且注意它们各自的**衰减周期**。

路径 A · 换更强的模型。收益立竿见影，通常能覆盖 70% 的能力缺口；衰减方式是"边际递减"——从 60 分到 80 分很容易，从 85 分到 90 分要换一个量级的成本，而且一旦基线提升，所有人都会一起提升，你的相对优势消失。

路径 B · 提示工程。收益同样立竿见影，衰减方式是"两周到一个月"——你精调出的那段提示在上下文被压缩、历史被污染、任务类型漂移之后，效果会稳定地回落，而回落的原因往往被误读为"模型不稳定"。

路径 C · 协议层训练。收益**慢**，第一轮几乎看不出差别；但衰减方式是"不衰减，且可累积"——因为每一轮的成果被写进了 `SOUL.md`、`AGENTS.md`、`MEMORY.md` 与测试集，下一轮从那里继续。

三条路径的差别不在效率，在**是否可累积**。路径 A 和 B 是消费，路径 C 是投资。本章要论证的就是：**训练学是一门关于"如何让智能体的成长可累积"的学科，因此它的主战场在协议层。**

#### 1.0.2 prompt 层的天花板：为什么它无法承载"成长"

把 prompt 层的极限说清楚，是本章立论的第一步。prompt 层有三个不可突破的结构性天花板。

**天花板一 · 无状态**。提示词不携带时间。它无法表达"上一轮我们试过 X，结果失败了"——那句话只有在被人重新写进提示词时才存在。**任何不能携带时间的介质，都无法承载成长**，因为成长的本质就是"今天的判断建立在昨天的结果之上"。

**天花板二 · 无验收方**。提示词改动没有验收机制。你改了一段提示，怎么知道它变好了？通常的答案是"感觉好了一点"。而感觉在两周内会失效，因为它同时受到任务分布、模型版本、情绪状态的影响。**没有固定测试集的改动，本质上是在做不可复现的实验。**

**天花板三 · 无对抗**。提示词的优化是一个单调的过程：你觉得哪儿不好就改哪儿。它缺少一个机制来回答"这次改动会不会破坏已经在好的地方"。这在模型训练里叫灾难性遗忘，在提示工程里它连名字都没有——它表现为"某个以前做得挺好的能力，最近好像不灵了"。

三个天花板的共同解药是同一样东西：**多轮、可复现、有验收标准的训练流程。**而"多轮"意味着需要一个能跨轮次保存状态的容器，"可复现"意味着需要一个固定的测试集与基线，"有验收"意味着需要一个不参与执行的评审主体。这三样都不是 prompt 层能提供的——它们是协议层与流程层的东西。

#### 1.0.3 训练学的第一性原理：把它当学生，不当工具

换一个视角，问题会变得异常清晰。

传统的"配置一个 agent"的隐喻是**工具**：我要一把更好用的锤子，我把锤子磨锋利。磨的动作发生在锤子上，目标是让锤子的物理属性更好。

训练学的隐喻是**学生**：我要一个能独立承担职责的成员，我要让它在一段时间里成长。成长的动作发生在**它自己**身上，而成长的形态是它的判断、它的边界、它的自我评估能力发生了变化。

这个视角切换会立刻产生五个推论，它们构成了本章全部机制的来源。

**推论一 · 成长需要课程**。给一个学生的不是"任务列表"，是"由易到难、有明确验收标准的能力序列"。对应到智能体，这是 L1–L5 的进化阶梯（Evolution Ladder）。

**推论二 · 成长需要教师**。不是每一个反馈都必须由人来给。一个专门的"导师位"（Mentor Agent）可以承担常态化的评估与反馈。本章概念 4 把它定义为一个**不参与执行的主体**——这一点关键：参与执行的人无法公正评估执行。

**推论三 · 成长需要测量**。要改的东西必须能被测量。这是固定测试集、基线、阈值的作用。**没有测量的训练不是训练，是许愿。**

**推论四 · 成长需要小步**。每一轮只改一个变量，否则你无法归因。这是"小步快跑"（每轮一个变量）的全部内容。

**推论五 · 成长需要记录**。每一轮的假设、改动、结果、结论必须落盘。没有记录的轮次，在下一轮无法被引用，于是成长无法累积。这一条是把训练从"一系列孤立尝试"变成"一条成长曲线"的关键。

五个推论合起来就是本章的判断：**训练学是一个流程学科，不是一个配置学科。**它的产出不是"一份更好的配置"，而是"一条可以被复盘的成长记录"。

#### 1.0.4 反方观点：'那不就是 A/B 测试吗'

诚实的论证必须处理最强的反驳。最强的反驳是：你描述的这套东西——基线、变量、测试集、结论落盘——不就是产品团队做了几十年的 A/B 测试吗？有什么新东西？

这个反驳很有力，我们要认真回应。它成立的部分是：**方法论内核确实共享**——可控实验的骨架是通用的。它的错误在于忽略了对象的差异，而这个差异会推翻全部工程细节。

差异一 · **A/B 测试的样本是用户，训练学的样本是同一个 agent 的不同版本。**前者需要大样本统计显著，后者是单一个体的纵向对照。这意味着训练学无法依赖统计，只能依赖**固定测试集上的稳定复现**——所以测试集的构造成了核心工程问题，而 A/B 测试里测试集往往是最简单的一环。

差异二 · **A/B 测试改的是产品，训练学改的是"产品 + 人格 + 边界"。**当你的实验变量可能改变 agent 的说话风格、它的拒答倾向、它对权限的理解时，"哪个版本指标更高"就不再是唯一的判据——你还要回答"这个版本还是不是我们想要的它"。**这是 A/B 测试框架里不存在的问题。**

差异三 · **A/B 测试可以随时回滚，训练学的回滚有副作用。**把一个用户的实验组切回去是无痕的；把 agent 的人格回滚到两周前，会留下记忆断层与行为不一致。所以训练学必须更谨慎地设计改动粒度，必须更早地建好回滚路径。

差异四 · **A/B 测试的周期是天，训练学的周期是轮。**一轮训练包含"准备—设计—执行—判定—并入"五个环节，天然比一次分流实验重。

四条差异指向同一个结论：**训练学借用了实验方法论，但它处理的是一个有时间轴、有人格连续性、有回滚成本的对象。**把它简化成 A/B 测试，会在第二次人格回滚时付出代价。

#### 1.0.5 三层结构：能力、寿命、秩序

本章在第 3 章的位置，可以用一个三层结构说明。本书的后半部分有意按三层推进：

**第 3 章 · 能力层**（本章）：回答"怎么把一个通用模型变成一个有能力、有职责的成员"。它的产出是**成长速率**——同样三个月，有的 agent 从 L1 到 L3，有的还在 L1。

**第 4 章 · 寿命层**：回答"训出来之后，它能不能撑住"。它的产出是**不变形**——漂移、失真、边界失守的治理。这一层是本章成果的保险：没有它，前面训出来的东西会在若干周里被自己磨掉。

**第 5 章 · 秩序层**：回答"当一个单体足够强之后，它在组织里怎么被验证、被追责、被结算"。它的产出是**可信**。

三层的关系不是并列，是**串联**：能力靠流程获得，流程的成果靠寿命层保住，保住的成果靠秩序层被组织承认。**只做能力层而不做后两层，你会得到一只很强但很不可信的 agent；只做秩序层而不做能力层，你会得到一套很规范的流程，跑在一只什么都没长出来的 agent 上。**本章是这条链的起点，因此它对前后两章都有接口依赖——1.4 会逐条列出。

#### 1.0.6 一个必须先承认的现实：多数 agent 从未被"训"过

这一节的最后一件事，是把训练学放回它真实的起点上。

本书写作时对一台真实运行中的机器做过盘点：18 个 agent、236 个 skills、45,662 字节主配置、多个定时任务在跑。盘点的结论不是"这套系统很先进"，而是一条更朴素的观察：**这些 agent 里，绝大多数从未经历过一次结构化的训练轮次。**

它们被配置过，被赋予过角色，被接进过心跳，但它们没有基线、没有测试集、没有导师位、没有训练记录。也就是说，它们的能力水平是一个**未经测量的状态**，它们的变化速度是一个**无人观测的量**。

这解释了一个反复出现的管理困惑："为什么有的 agent 特别靠谱，有的就很飘？"在缺少训练流程的系统里，答案往往是"某个人当年多花了一点时间把它的契约写得细一些"。**当一件事的成败依赖于某个人当年花了多少时间，它就不是工程，是运气。**

训练学的目的，就是把这件事从运气变成流程。这也是为什么本章要给出七步实践路径、八个误区、以及一套可以直接抄用的测试集与实验方案模板——它要让"把一只 agent 训出来"这件事变成一件**可以被一个新手照着做、并且做得不差**的事。

#### 1.0.7 训练学的四种失真：本章要拆掉的四个东西

在给出机制之前，先把"假训练"的四种形态摆出来。它们的共同点是**看起来在做训练，实际上没有产生可累积的成果**。

**失真一 · 一次性大改**。攒够了一堆不满，在一个晚上把 `SOUL.md` 大改一版，然后观察几天。这种方法的问题是：改动之间互相污染，你无法知道是哪一处起了作用；更糟的是，如果效果变差，你无法只回滚坏的那一处——因为在文件层面它是一整版。判别方法：你上次改动是否只涉及一个概念？如果不是，那一轮不具备训练意义。

**失真二 · 无基线**。改完之后感觉"好像好了一点"，于是进入下一轮。三周后回头看，没有任何一处能回答"它比三周前强在哪"。这不是训练，是**把随机波动当成进步**。判别方法：你能否给出上一轮改动前后的同一组数据？

**失真三 · 人肉全程盯**。每一轮都由人来读输出、人来判断好坏、人来写下一轮的修改。这种做法在小规模上可行，在规模上崩溃——因为人的注意力会先耗尽。更隐蔽的问题是人本身不可复现：今天的你和两周后的你，对同一段输出的判断并不一致。判别方法：你的验收结论是否依赖于某一次具体的阅读？

**失真四 · 偷看答案**。把测试样例拿来反复调整，直到在这个样例上好为止。结果是它在固定样例上表现优异，在同类新任务上退化。这是本章概念 10 要处理的核心风险——**过拟合在提示层与协议层的对应物**。判别方法：你的测试集分不分 train / holdout？

四种失真的共同解药，就是本章七步路径要建立的东西：一个变量一轮、有基线、有固定测试集、有导师位。**把"训练"这个词从形容词变成动词的唯一方法，就是让这四件事同时存在。**

#### 1.0.8 双三角模型：一次训练的最小闭环长什么样

本章概念 1 会正式给出双三角模型（Dual-Triangle Model：期望—实际—反馈闭环）。在这里先给出它的直觉版本，因为它是本章所有机制的原子。

一次最小闭环由两个三角构成。

**第一个三角是"期望—实际—差距"**。期望是"这一轮我希望它达到什么"，它必须写在训练开始之前，且必须可判定。实际是"它真实的表现"，它必须来自可复现的执行，而不是某一次的抽样。差距是两者的差，它必须被算出数字，而不是被概括成"还差一些"。这个三角的作用是**定义问题**。

**第二个三角是"反馈—假设—改动"**。反馈是"针对这个差距，要给什么具体的信息"。假设是"我判断造成差距的原因是什么"，它必须是一个可以被推翻的陈述。改动是"我因此改哪一处、改成什么"，它必须是单变量的。这个三角的作用是**定义动作**。

两个三角之间有一条检查线：**假设是否真的能解释差距**。跳过这条线，就会出现"差距在那儿，动作也在那儿，但两者无关"的假训练——你改了语气，而差距是记忆检索不准。这是最常见的无效轮次结构，也是本章概念 1 要重点讲的。

双三角之所以叫"模型"而不是"步骤"，是因为它的价值在于**它是一个可以自查的结构**：任何时候你都能问"我这轮的期望是什么""我这轮的假设是什么""这两个角我缺了哪个"。缺了第一个角，你在瞎改；缺了第二个角，你在瞎忙。

#### 1.0.9 进化阶梯：为什么必须分级，而不是打分

一个自然的替代方案是给 agent 打一个综合分，比如 0–100，然后看它涨不涨。这个方案在实践中有三个致命问题，正是进化阶梯要解决的。

问题一 · **分数不可解释**。78 分和 82 分的差别对应什么能力的差别？没人答得出来。当分数变化时，你不知道发生了什么。

问题二 · **分数掩盖顺序**。能力的成长有依赖顺序：不会自己判断要不要动手的 agent，不应该先被优化"动手的优雅度"。分数会把顺序抹平，于是你会去修一个还不该修的层级。

问题三 · **分数不提供验收标准**。分数是评价，不是条件。而训练需要的是"达到什么条件才允许进入下一级"这样的**闸门**。

进化阶梯把连续的分数替换成离散的档位，每一档都有明确的进入条件与可观察的行为特征。这样做的收益是三重的：**改动有方向**（往上一档走）、**判断有闸门**（条件不满足不升级）、**复盘有坐标**（历史位置可以被记录）。

本章概念 2 会给出每一档的完整定义与达成条件。在这里先记住它的一条纪律：**不要越级**。在 L1 的 agent 上做 L3 的训练，得到的不是加速，是"它学会了一个它还没有能力承担的判断"——这几乎总是以边界事故的形式结算。

#### 1.0.10 导师位：为什么评估必须由一个不执行的主体承担

这是本章最容易被跳过、也最不可省的一条。

大多数团队的做法是：谁负责这个 agent，谁看它的输出，谁来改。这个安排看起来很自然，但它内置了一个无法修复的偏差：**执行者与评估者是同一个人**。后果是评估会朝着两个方向失真——要么因为投入了情感而过度宽容（"它已经很努力了"），要么因为刚被坑过一次而过度严厉（"又错了，这次得狠狠改"）。两种失真都不可复现。

导师位的设计是：**把常态化评估交给一个不参与执行的独立主体**（Mentor Agent），它按固定测试集跑、按固定口径打分、按固定格式输出结论。人仍然保有最终决策权，但**日常的"它这轮怎么样"这个问题，由一个稳定的、不疲劳的、不会被情绪影响的主体回答。**

这件事的价值不在省人力，在**让评估变成可比较的量**。同一个人在两个不同状态下的评估不可比较；同一个导师位在不同轮次给出的评估可以比较。这就是"成长曲线"能存在的前提。

#### 1.0.11 固定测试集：一条最容易被省掉的纪律

如果本章只能保留一条纪律，是这一条：**在你改任何东西之前，先把测试集建好。**

原因是它可以被推理出来：任何改动的效果判断都依赖一次比较，而比较需要一个不变的东西作为参照。测试集就是这个不变的东西。没有它，你的每一轮结论都建立在一组会漂移的观察上，于是你无法区分"它变好了"和"我对它的判断标准变了"。

测试集的建设要点有三条，本章概念 6 会展开：

第一，**分层**。测试集不是一堆题，是若干**能力维度**上的题目集合。分层让"它变好了"这句话可以被具体化为"它在记忆检索维度上进步了，在边界判断上退步了"。

第二，**拆分**。至少分成 train 与 holdout 两部分。train 用来观察、调优；holdout 只在判定时用一次。**没有 holdout 的测试集，三个月内必被偷看答案。**

第三，**可复现**。同一个问题在不同轮次要用同一个入口、同样的上下文配置去问。任何"这次的问法不太一样"都必须被记录为偏差，而不是被忽略。

#### 1.0.12 训练节拍：把训练接进心跳

训练最容易断的地方不是方法论，是**节奏**。三个月做一轮的训练不是训练，是一次性的项目。

解法是把训练接进已有的节律：让心跳（Heartbeat）承担"感知"任务（比如每周触发一次体检），让定时任务（Cron）承担"准点"任务（比如每周一结算上一个轮次的结论）。本章概念 11 会给出具体的配置方法与一个真实的心跳任务实例。

这里先明确一条边界：**训练节拍不能太密。**一轮训练包含准备、设计、执行、判定、并入五个环节，在真实运行里通常需要一个工作日以上的跨度。把节拍设得过密，会让每一轮都在"上轮还没并完"的情况下开始，结果是改动互相污染。**节拍的合理性标准是：上一轮的结论已经落盘并且被引用，下一轮才开始。**

#### 1.0.13 训练学与六框架的对位：三重证据

本章的核心论断是"训练流程层在业界是空白"。这个论断很容易被说成口号，所以我们给出三重可检验的证据。

**证据一 · 有评估，没有流程。** 2026 年的主流框架（LangGraph / AutoGen / CrewAI / Claude Agent SDK / OpenAI Agents SDK / LlamaIndex）大多提供了某种评估工具或回调机制——你能用它跑一批用例、拿到一份分数。但"跑完一批用例"和"训练流程"之间隔着四样东西：基线、单变量改动、导师位、轮次记录。四样里任何一样都不是"一次评估"能提供的。

**证据二 · 有观测，没有闸门。** 这些框架普遍有很强的可观测性（轨迹、事件、回调），可观测性的价值是"让你看见"，而训练需要的是"让你决定能不能升级"。**看见不是闸门。**把可观测性当作训练能力，是本行业最常见的一处概念替代。

**证据三 · 有组合，没有成长。** 框架的核心价值在组合——把工具、模型、agent 拼成一条流水线。而成长的定义是"同一个对象随时间变强"。流水线可以重组，但不能成长，因为重组之后的对象换了，历史无法对照。

三重证据指向同一个空白：**"如何让一个具体的 agent 在一段时间里可复现地变强"这件事，在主流框架里没有一等公民的地位。**本章因此有它存在的理由——不是因为别人做不好，而是因为这件事需要一个不同的抽象。

#### 1.0.14 Q&A：六个反复出现的质疑

**Q1：我的 agent 很能干，还需要训练流程吗？**
需要。"很能干"通常是未测量的印象。训练流程的第一个产物往往不是"让它更强"，而是**"知道它现在到底在哪"**——后者对管理的价值高于前者。

**Q2：一个人维护十几个 agent，哪里有时间做训练？**
恰恰相反：不做训练才没有时间。没有基线与测试集，每次"它最近怎么样"都要靠重新阅读大量输出来判断。**训练流程是把判断成本从"每次重新读"降到"看一份固定格式的报告"。**

**Q3：导师位能不能就用同一个模型兼任？**
可以，但必须**分会话、分角色、分提示**。让执行者"顺便评估自己"是行不通的——它的评估会被当前任务的上下文污染。导师位的关键不是换模型，是换**立场**。

**Q4：测试集会过时吗？**
会，而且必须定期更新——但更新的动作必须是**显式的**：记录版本、记录新增的维度、并在更新之后重建基线。偷偷修改测试集是训练学里最严重的一种作弊。

**Q5：五轮之后没有提升怎么办？**
这通常说明三件事之一：测试集选错了维度（测的不是你想改的东西）、假设一直没击中真实原因、或者这一档已经到当前模型的上限。**"没有提升"本身是一个有价值的结果**，它应当被落盘，并触发一次"是否该换变量/换档位/换模型"的判断。

**Q6：训练成果怎么沉淀？**
三个地方：契约文件（长期规则）、记忆层（关键事实与本轮结论）、测试集（把本轮发现的问题变成下一轮的题）。**只写契约不更新测试集，是"改完就忘"的典型形态。**

#### 1.0.17 一次无效轮次的完整复盘：钱花了，什么都没长

抽象原则需要一次具体的解剖。下面是一次典型的**无效轮次**（走查演示，非某次具体事故的记录）。它有完整的形态：有期望、有动作、有结论，但**没有产生可累积的成果**。我们把它的五个环节逐一拆开。

**环节一 · 起点：一个模糊的不满。** 触发这一轮的不是数据，是一个印象："它最近的回答太长了。"这个印象可能真实，但它没有数值、没有样例、没有范围。**这一轮从一开始就缺少第一角（期望）。**

**环节二 · 动作：改了两处。** 主人在 `SOUL.md` 里加了一句"回答要简洁"，同时把 `MEMORY.md` 的某条策略也顺手调了。两处改动、同一轮次——**变量不唯一**，归因通道在改动发生的那一刻就关闭了。

**环节三 · 观察：读了三个回答。** 三个回答确实短了。结论产生："有效。"但这三个回答是在新会话里、针对三个恰好偏简单的任务产生的。**没有测试集**，因此这个观察无法与上一轮的任何数据对比。

**环节四 · 结论落盘：写在对话里。** 没有写进训练记录，没有更新测试集，没有在契约文件上留版本说明。**下一轮开始时，这一轮的结论已经不在任何可引用的地方。**

**环节五 · 两周后：又长了。** 于是回到环节一，再来一遍。

复盘这个案例，你会发现它每一环都"做了事"，但它作为一次"训练"是**完全空转**的。它唯一留下的东西是 `SOUL.md` 里多了一句话。而那一句话是否真的有用、有没有副作用，永远无人知晓。

这个案例的价值在于它示范了七步路径的第一条为什么是"立基线：先量，再改"，以及为什么"每轮一个变量"不是洁癖而是**方法论的必要条件**。本节 1.0.7 列出的四种失真，在这里被完整地演示了一遍。

#### 1.0.18 训练学与相邻章节的接口清单

训练流程不是一个自足的系统。它有一组明确的输入与输出。把它们写清楚，可以避免"这一章读完但不知道从哪开始"的常见困境。

| 方向 | 依赖对象 | 具体内容 | 章节 |
|---|---|---|---|
| **输入** | `SOUL.md` / `USER.md` | 训练的目标形态、权限边界（测试用例的合法性来源） | 第 1 章 |
| **输入** | Heartbeat / Cron | 训练节拍的时钟；导师位被唤醒的方式 | 第 2 章 |
| **输入** | 固定测试集 | 本轮判定的标尺（由训练流程自己建立，跨轮次复用） | 本章 |
| **输出** | 契约文件的修订 | 本轮结论以单变量改动落到 `SOUL`/`AGENTS`/`MEMORY` | 第 1 章 |
| **输出** | 漂移锚点与基线 | 本轮结束时的状态快照，作为下一轮的对照起点 | 第 4 章 |
| **输出** | 修复工单 | 本轮发现的、无法在训练内解决的问题 | 第 5 章 |
| **输出** | 信任分变化 | 轮次结果折算成长期量 | 第 5 章 |

这张表揭示了一个常被忽略的事实：**训练成果的落点不在"训练"里，而在契约、基线、工单、账本四处。**只在训练记录里写结论、不落到这四处的轮次，其成果在下一轮无法被引用，等于白跑。

它同时也解释了为什么训练流程要放在第 3 章（骨架之后、长期表现之前）：它需要骨架提供节律，需要长期表现层保存基线，需要治理层承接无法就地解决的问题。**位置本身就是信息。**

#### 1.0.20 一条留给实践者的纪律

最后留一条纪律，它是本章所有机制的浓缩：

> **在你改之前，先写下你会怎么知道它变好了。写不出来，就别改。**

这句话有三个作用。它对**期望**：逼你先定义判据。它对**变量**：判据通常只针对一个维度，于是你自然只改一处。它对**记录**：写下的判据就是你这一轮的记录条目，下一轮可以直接引用。

一句话把双三角的第一角、单变量纪律与落盘要求全部覆盖了。如果本章的所有流程你都暂时不想建，至少要留下这一条。

| 2 | 期望是可判定的吗（有数字或明确条件）？ | 继续 | 改写成可判定 |

| 6 | 评估由一个不参与执行的主体完成吗？ | 是 | 建导师位 |

#### 1.0.22 三个隐性账单：不训的代价藏在哪里

不做训练流程，不会立刻出问题。代价以三种隐性的形式流出。

**账单一 · 能力无法迁移。** 一个 agent 被训出来的能力，如果只体现在"它现在表现不错"上，那它无法迁移到新的 agent。下一个 agent 上线时，一切从头调过。**没有中间的"训练产物"，你就没有可复制的成长路径。**

**账单二 · 判断依赖个人。** 什么时候该改、改哪一处、改成什么，全部依赖维护者的直觉。这个人休假三周，训练就停摆三周。这笔账表现为"关键人依赖"，但根因是流程缺失。

**账单三 · 事故无法归因。** 没有基线与轮次记录的系统，在出事之后无法回答"这是上周改坏的，还是更早就有的"。于是复盘只能停在"以后注意"，同类问题会以新的面貌再出现一次。**没有训练记录的组织，只能靠事故来学习，而事故的学习成本最高。**

三笔账单的公共解药，就是本章七步路径里最不起眼的前两步：立基线、定尺子。它们不产生任何"能力提升"的即时感受，但它们把上面三笔账一次性掐断。

#### 1.0.23 一句话记住本章

如果本节只能留一句：

> **训练学不是把模型变强，是把"它变强的过程"变成一件可复现、可累积、可交接的事。**

前者依赖运气与投入，后者依赖流程与记录。本章的全部机制，都在把前者转换成后者。

### 1.1 训练学里的位置：第 2 章给了骨架，第 3 章给了成长速率

第 1 章讲了七个契约——那是**宪法**；第 2 章讲了七个子系统——那是**骨架**。

一个硅基智能体（Silicon-based Agent，原：虾）有了宪法、有了骨架，它就已经"活着"了。
但"活着"和"长得好"是两件事。

> 你给它装上 Heartbeat，它不会因此变聪明。
> 你给它挂上 MEMORY，它不会因此变专业。
> 你给它配好 TOOLS，它不会因此变可靠。

骨架决定**它能做什么**，训练流程决定**它能做到多好、能稳定多久**。

这就是第 3 章存在的理由：**宪法与骨架之后，必须有一套把"普通"变"专家"的方法论**。
没有这一章，前两章的所有工程投入都只是"把一只普通硅基智能体装进了更精致的笼子"。

我们把这个方法论叫**训练流程**（Training Process）。

它不是"调 prompt"，不是"多喂几条消息"，也不是"换个更强的模型试试"。
它是一套有节拍、有基线、有对照、有留痕、有判定阈值的**实验性成长机制**。

### 1.2 一个反直觉的事实：业界默认"装上就能用"

翻遍 2026 年的六大主流 Agent 框架文档，你会发现一个共同的隐含假设：

> **"装上就能用。"**

你装上 LangGraph 去画状态图、装上 CrewAI 去编排 Crew、装上 Claude Agent SDK 去派 subagent——
它就能跑了。文档里没有"训练"这一章节，因为**框架层不认为"训练"是自己的责任**。

这本训练学的立场是：**这是错的。**

一个硅基智能体装上能跑，不等于：

- 它能稳定运行三个月（长期表现）
- 它能跨会话记得自己是谁（记忆与人格锚点）
- 它能在边界内自主进化而不越权（主动性治理）
- 它能被复制成第二条、第三条产线（可复制性）

后面这四件事，全都需要训练。**而业界不做。**

这不是能力问题，是**分工问题**：框架负责编排（orchestration），业界把"训练"这件事默认交给了"用户的工程能力"。
结果就是——**每个团队自己摸黑训练，每个团队自己的经验都无法迁移。**

本章要做的事，就是把这份"摸黑经验"结构化、命名化、可验证化。

### 1.3 跳过这一章的人会遭遇什么

我们见过太多这样的场景。跳过第 3 章的人，通常会在**两周到两个月**内遭遇下面五个症状中的一个或多个。

**症状一：训练变成"手感活"。**

他改了 SOUL、加了几条规则、发了几条测试消息，感觉"好像好点了"。
三周后回看：既没有训练前的基线，也没有训练后的数字，唯一能拿出来的是"我觉得它变专业了"。
这种感觉无法交接、无法复现、无法证明——**它甚至无法说服他自己**。

**症状二：打地鼠循环。**

期望 → 实际 → 发现差距 → 改配置 → 下一个相似场景又错。
他把双三角模型（Dual-Triangle Model）的第三角"反馈"（Feedback）丢掉了，
所以每次修复都只是**针对症状**，不是针对根因。
同一个 bug 会以不同面貌反复回来，直到他确信"这个框架上限就这样"。

**症状三：一次性大改后无法归因。**

他一次性改了人格、工具、记忆、路由、还新增了三个技能。
训练后表现变好了——他**不知道是哪个改动起的作用**；变坏了——他**不知道该回滚哪一个**。
大改失败时，他只能整包回滚，把有效的改动一起埋掉。

**症状四：人肉当教练，人一忙训练就停。**

他手动发消息、手动看输出、手动改配置。
这套流程在头三天效率极高，第四天开始崩——因为他要去开会。
一周后硅基智能体回到原点，训练记录为零。

**症状五：100% 通过率，零泛化能力。**

他建了一个十条的测试集，然后反复针对这十条调配置，直到十条全过。
他宣布"训练完成"。换一个新场景，立刻失败。
**他把"背答案"当成了"学会了"。**

这五个症状有一个共同根因：**缺少一套把训练当实验来对待的流程。**
本章就是这套流程。

### 1.4 与前后章的引用关系

训练学是一条链，本章是链上第二个关节。

```
第 2 章 · 系统骨架
  └─ 交付：Heartbeat / Session / Compaction / 路由 / 工具与技能双模块

        │

第 4 章 · 长期表现：记忆、漂移与边界
        │
        ▼ 消费本章产出：只有被训练过的 Agent，"不变味"才是一个可讨论的问题

```

**向上（第 2 章）**：本章的"训练轮次"（Round）**不是**一个新建的调度器。
它复用第 2 章的 Heartbeat 子系统——训练节拍 = 心跳节拍。
本机实测：`agents.entries.kunlun.heartbeat.every = "30m"`，即昆仑每 30 分钟醒一次；
这 30 分钟就是它的**训练时钟最小刻度**。

**向下（第 4 章）**：本章训练出来的东西，要拿到第 4 章去接受"长期考验"。
第 4 章讲漂移治理三件套（Drift Governance Trio）——但**漂移检测的前提是有一个锚点**。
锚点从哪来？从本章的训练轮次里来：每一轮通过的基线，就是下一轮的漂移锚点。

**平行（第 5 章）**：本章的"训练记录落盘"与第 5 章的三证据验证（Three-Evidence Verification，TEV，原：三证验真）共用同一套证据哲学——
新产物 / 前后 Diff / 测试日志。训练轮次记录就是 TEV 的第一手证据源。

**向后（第 7 章）**：L5 提案型（Proactive）与自主目标生成（Autonomous Goal Generation，原：Response → Proposal）
是本章进化阶梯的终点站，但它的**工程原型 ⏳ 待推**（2026 Q4 之后），第 7 章会深化。

### 1.5 本章的三个承诺与两个不承诺

**三个承诺**：

1. 读完本章，你能用**一句话**说清"期望—行动—反馈"闭环由谁驱动（答案：Heartbeat 提供节拍）。
2. 读完本章，你能给任意一只硅基智能体**判级**——它卡在 L1→L2，还是 L3→L4。
3. 读完本章，你能独立设计**一轮合格的训练**：有假设、有基线、有测试集、有一个变量、有判定阈值、有落盘。

**两个不承诺**：

1. 本章**不承诺**"跑完就能到专家级"。进化阶梯是递进的，越级只会放大错误。
2. 本章**不承诺**"完整训练轮次已在本机端到端跑通"。
   ⚠ 诚实边界：本章训练流程的**配置层（heartbeat + 脚手架 + 节拍）已在本机实测**；
   **完整的一整轮 L1→L5 训练 ⏳ 未在本机端到端跑通**。这一条会在本章最后一节再次展开，不藏、不含糊。

### 1.6 世界观：两种范式，两条命运

在讲任何方法之前，先把世界观摆出来。因为**方法论是世界观的下游**——
你怎么看一个智能体，决定了你会怎么带它。

这本训练学把外部世界的做法分成两种范式（对外需用标准术语，内部黑话写在括号里）：

**第一种：被动响应范式（Reactive Paradigm，原：养虾派）。**

它的假定是：智能体是一个**被投喂的受体**。
你把料投下去，它长成什么样，取决于料好不好、池塘大不大。
于是所有的努力都投向"把料做得更精致"——更长的 prompt、更多的例子、更全的规则。

这条路的极限很清楚了：**料越精致，边际收益越低；而一旦停止投喂，长势立刻回落。**

**第二种：主动进化范式（Proactive Evolution Paradigm，原：训虾派）。**

它的假定是：智能体是一个**有节律、有记忆、有边界的成长主体**。
养料只是变量之一，真正决定长期表现的是——**它有没有训练循环、有没有反馈角、有没有进化阶梯**。

这条路的核心不是"喂得更多"，而是"**练得更聪明**"：
每一轮一个变量、每一次判定有阈值、每一级升阶有判据。

两种范式的分水岭，就是本章要回答的那个问题：

> **装上能跑，和跑得久、跑得稳、跑得像专家——是不是同一件事？**

被动响应范式的答案是"是"（所以它不训练）。
主动进化范式的答案是"不是"（所以它必须有第 3 章）。

**三个由此延伸的世界观判断：**

**判断一：智能体不是工具，是运行单元。**
工具用完即弃，运行单元要**跨会话保持身份**。
前者不需要 MEMORY，后者没有 MEMORY 就永远停在 L1。

**判断二：多智能体编排（Multi-Agent Orchestration / Agent Fleet，原：军团 / 军团编制）不是"堆数量"，是"建秩序"。**
把十个智能体放在一个群里，不叫编排，叫事故现场。
编排的前提是**每个成员都先被训练过**——否则你只是把十份混乱并置。

**判断三：监督层（Supervisor Layer，原：监军）不是裁判，是"外部视角"。**
它存在的意义不是打分，而是**在一个所有人都身处其中的系统里，提供一个站得住外面的观察点**。
蓝血智能体生态（Blue-Blood Agent Ecosystem，原：蓝血军团）之所以需要一个监督层，
是因为**内部成员永远无法自发地发现自己的系统性偏差**。

这三条判断不要求你同意。但你要知道：
**本章后面所有的流程设计，都是从这三条推出来的。**

## 二、核心概念

本章有十二个核心概念。它们不是并列的十二个知识点，而是**一个递进的认知阶梯**：
前四个搭框架（模型、阶梯、轮次、教练），中间四个定工具（清单、测试集、方案、步幅），后四个讲纪律（留痕、过拟合、节拍、证据）。

每一个概念都会按同一节奏展开：**这是什么 → 核心目的 → 拟人化映射 → 对长期表现的影响 → 怎么写/怎么用 → 技巧 → 常见误区 → 进化阶梯。**
不要把它当定义背诵，把它当**判断力**来养。

### 概念 1 · 双三角模型（Dual-Triangle Model）

**这是什么。**

双三角模型是这本训练学的**核心理论框架**，也是全章的地基。
它不是"两个三角形"这么简单——它是**对"成熟度"这个词的重新定义**。

成熟度不是一维的。你不能说"这只硅基智能体七分熟"。
成熟度是**两个正交维度的乘积**：

- **能力三角（Capability Triangle）**：专业深度 × 工具广度 × 创造性 → 决定**上限**
- **可靠性三角（Reliability Triangle）**：稳定性 × 可控性 × 可预期性 → 决定**下限**

矩阵上看，一只硅基智能体只有四种可能：

| 类型 | 能力三角 | 可靠性三角 | 症状 | 训练重点 |
|---|---|---|---|---|
| 又强又稳 | 强 | 强 | 失败模式清晰、可复制 | 这就是**专家智能体**（Expert Agent，原：专家虾） |
| 强而不稳 | 强 | 弱 | 偶尔惊艳、经常掉棒 | 补记忆、补治理、补验收——**不是再加能力** |
| 稳而不强 | 一般 | 好 | 很少出错、做不了难事 | 适度提高任务强度，让能力三角有机会生长 |
| 既不强也不稳 | 弱 | 弱 | 还没完成基础训练 | 先拉 L1→L2，别急着追求高等级 |

**核心目的。**

双三角模型的唯一目的，是**阻止你把"偶尔很强"误判为"已经成熟"**。

训练里最常见的三种误判，全部源于只看一个维度：

- 误判一：某次输出惊艳 → 以为训好了。真相是"能力上限高，可靠性三角可能很差"。
- 误判二：总是掉棒、总是漂移 → 以为模型不行、prompt 不行。真相是"能力可能够了，可靠性三角没立住"。
- 误判三：不断加技能、加工具、加任务，但不建记忆、不建治理、不建验收。
  结果是**能力三角越来越强，可靠性三角越来越弱**——最终变成"看起来很强，实际不可用"。

**拟人化映射。**

用一个招聘比喻最直观。

能力三角 = 这个人的**简历**：学历、技术栈、做过什么项目。
可靠性三角 = 这个人的**在职表现**：会不会迟到、会不会甩锅、交给他的事能不能按时按质交出来。

面试时你只能看到简历。**训练就是"在职表现"这门课。**

一个人简历漂亮但在职表现差，叫"强而不稳"；
一个人简历平淡但从不掉链子，叫"稳而不强"；
一个团队要的，是"又强又稳"——而后者**从来不是面试能筛出来的，是带出来的**。

带，就是训练。

**对长期表现的影响。**

这是双三角模型最实用的地方：它解释了**为什么"能力训练"会自然衰减**。

张力一：能力越强，越难稳定。
功能越来越多、工具越来越多，系统复杂度上升、边界模糊、失败模式增加。
——你每加一个 skill，就多了一个可能出错的地方。

张力二：稳定性要求越高，能力发挥越受限。
为了"不出错"，你不敢让它做复杂任务，能力被锁死。
——过度的风险厌恶，是能力的隐形天花板。

张力三：创造性越高，可预期性越低。
能举一反三的，本来就难预测它怎么举一反三。
——探索必然带来不确定性。

**理解了这三个张力，你才能理解"训练目标不是拉高能力三角，而是让两个三角同步扩张"。**

**怎么写、怎么用。**

双三角不是一个写进文件的字段，而是一个**评估动作**。每一次训练轮次结束时，你必须分看：

```
能力三角：这一轮测到了什么新能力？
可靠性三角：这一轮它稳定吗？失败模式清晰吗？
```

然后把两个三角分别打分（1–5），综合判断当前类型，再选**本轮只拉一个三角**。

**技巧。**

1. **交替战术**：这轮拉能力，下轮补可靠性，不要试图一轮同时拉两个。
2. **任务强度挂钩**：可靠性三角弱就别上高复杂度任务；能力三角弱就要适度给有挑战的题。
3. **验收分说**：验收时别说"这轮还行"，要说"能力三角测到了 X，可靠性三角的短板是 Y"。

**常见误区。**

- 只看能力不看可靠性 → 越训越不可用。
- 只看可靠性不看能力 → 永远停在 L2（持久型）。
- 想一轮解决所有问题 → 目标分散，哪个都没训透。
- 以为"强了自然就稳了" → 能力和可靠性是**两套系统**，需要分别训练。

**进化阶梯。**

双三角的掌握也分三级：
能分别评估两个三角（会看）→ 能识别当前类型（会判）→ 能根据短板设计训练重点（会治）。
第三级才算真的会用。

### 概念 2 · L1–L5 进化阶梯（Evolution Ladder）

**这是什么。**

进化阶梯给训练提供一个**坐标系**。没有坐标系，你会今天训一点这个、明天训一点那个，
三周后既不知道它在哪，也不知道下一步该补什么。

这条阶梯的两个端点，术语上对应**初级智能体**（Novice Agent，原：新人虾）与
**专家智能体**（Expert Agent，原：专家虾）——**训练的全部工作，就是把前者变成后者。**

本章的阶梯是五级：

| L | 名称（中英） | 标志 | 训练重点 | 章节 |
|---|---|---|---|---|
| L1 | 响应型 Reactive | 能执行单任务 | 任务卡训练 | 本章 |
| L2 | 持久型 Persistent | 跨会话记忆 | MEMORY 契约 | 本章 |
| L3 | 反思型 Reflective | 每周体检 + 漂移检测 | 第 4 章训练学 | 第 4 章 |
| L4 | 协同型 Cooperative | 多智能体不崩溃 | 第 5–6 章 | 第 5–6 章 |
| L5 | 提案型 Proactive | 主动提议新目标 | 第 7 章 | 第 7 章 |

**核心目的。**

阶梯的唯一目的，是**防止越级**。

一级有一级的前置能力要求。越级 = 让硅基智能体做它还没学会的事。
最常见的越级是：新人刚建完一个智能体，就直接要求它"像十年资深工程师一样工作"，
给它塞满高级规则和高难任务。

结果有三种，全都很贵：

- **挫败**：它输出大量错误与幻觉，而人误判为"这个框架上限低"。
- **基线污染**：在错误的基础上反复改配置，基线一团乱。
- **误判能力**：把"基础没打好"当成"框架不行"。

**拟人化映射。**

这是一条**武术段位**式的阶梯，不是"年龄"。

黑带不是练得久就有的，是**每一段都有明确的过关标准**。
你不能让一个刚学会马步的人去打擂台——不是他不行，是顺序错了。

L1 到 L5 的顺序是硬的：**先能回话 → 再能按格式交付 → 再能自检 → 再能协同 → 最后才能提案。**

跳过"按格式交付"直接搞"自主提案"，最危险的不是"不能提案"，
而是它**会输出一堆看起来像提案的幻觉**——这比不会提案糟得多，因为它看起来像在干活。

**对长期表现的影响。**

阶梯对长期表现的影响有四个层次：

1. **防止"看起来很强，实际不稳"** ——很多智能体在 L2 就会给人一种错觉：能写、会调工具、反应快。
   但没进 L3/L4 的，只是"短期能用"，不是"长期可靠"。
2. **防止过早复杂化** ——没跑稳单体就上多智能体、没建记忆就开长会话、没做验收就搞自动化，几乎必炸。
   复杂度上升速度一旦超过稳定性提升速度，系统就进入负循环。
3. **让训练有节奏感** ——训练不是"今天灵感来了多改点"，而是"当前级先过线，再升下一级"。
4. **让失败有解释框架** ——出问题不再只说"它不行"，而是能判断"它卡在 L2→L3"还是"卡在 L4→L5"，
   这直接改变你的纠偏方法。

**怎么写、怎么用。**

本机有一份真实的阶梯档案：`agents/workspace-kunlun/EVOLUTION.md`（1,993 字节）。
它的五级与本训练学的阶梯可逐级对齐，且带**真实达成判据**：

| L | 本训练学阶梯 | 本机 EVOLUTION.md 对应 | 达成判据（本机真名） | 本机状态 |
|---|---|---|---|---|
| L1 | 响应型 | L1 战略新锐 | 完成 20 次 OODA-Plus 决策 | ⬜ |
| L2 | 持久型 | L2 决策元老 | 决策 ROI 均值 >150%，持续 1 个月 | ⬜ |
| L3 | 反思型 | L3 模式发现者 | 提取 ≥5 个跨域复用基因入库 | ⬜ |
| L4 | 协同型 | L4 框架奠基人 | 建立军团决策框架标准 | ⬜ |
| L5 | 提案型 | L5 奇点 | **自下而上提案数 > 被派发任务数** | ⬜ |

⚠ 诚实边界：五个状态**全部是 ⬜（未达成）**。这不是耻辱，这是诚实。
同一文件里，"技能基因库"一行写着"_待首次任务后提取_"，"失败模式库"写着"_待记录第一次错误_"。
**一份敢写"我还没到"的阶梯档案，比一份全绿的档案可信得多。**

**技巧。**

1. **先抄结构再改内容**：从已有模板拷一份 EVOLUTION.md，再逐行把 L1–L5 的达成条件改成你自己的。
2. **每级都要有可判定的数字**：">150%"、">5 个"、"> 被派发任务数"。
   没有数字的达成条件是愿望，不是判据。
3. **状态字段必须填**：⬜ 也算填。空着才是不合格。

**常见误区。**

- 以为有 MEMORY 文件就是 L2 → 不对。**有记忆文件 ≠ 会稳定使用记忆**。
- 以为会 heartbeat 就是高级 → 不对。主动但无边界，只会更快暴露系统问题。
- 以为进多智能体编排就是高级 → 不对。不会响应让渡协议（Response Yield Protocol，原：让位协议）、
  不会任务交接协议（Task Handoff Protocol，THP，原：交接棒协议）的，进去只会放大混乱。
- 以为专家级就是"更聪明" → 不对。专家级的本质是**更稳、更能交付、更能复制**。

**进化阶梯。**

阶梯本身不进阶梯——**判断力**进阶梯：
能按特征给任意智能体判级（会判）→ 能说清"下一步该补什么"（会诊）→ 能抵抗"跳步"的诱惑（会守）。

### 概念 3 · 训练轮次（Round）

**这是什么。**

一轮训练（a Round）是训练流程的**最小可归因单元**。它的定义非常硬：

> **一轮训练 = 一个假设 + 一个变量 + 一次基线对照 + 一个判定 + 一条落盘记录。**

缺任何一项，它就不是一轮训练，只是一次"改动"。

本机真实存在的训练脚手架，就是为轮次准备的：
`~/.openclaw/workspace/agents/workspace-kunlun/training/`（4 个文件：`prompt-v2.md` + `prompt-v2-module{1,2,3}.md`）
与 `~/.openclaw/workspace/agents/workspace-kunlun/.training-data/`（4 个文件：
`evolution-plan.md` 6,738 字节 / `extract_msgs.py` 4,789 字节 / `peter_msgs.json` 280,912 字节 / `raw_messages.json` 1,034,950 字节）。

注意这两个目录的**分工**，它是轮次设计的关键：

- `training/` = **课程**（导师智能体用的训练提示词，是"这节课教什么"）
- `.training-data/` = **原料**（原始对话 → 提取 → 进化计划，是"用什么练"）

**核心目的。**

轮次设计的核心，是**可控归因**。

一次改一个维度，你才能回答"这个提升是哪个改动带来的"。
多变量同时变，训练后变好了你说不出原因，变坏了你也不知道该回滚哪个。

**拟人化映射。**

这是**实验室对照实验**，不是"感觉好点了"。

一个化学家改实验条件，一次只改一个：温度不变、浓度不变，只改催化剂。
一次改三个，实验结果出来了，他没法写论文——**因为他不知道是谁起的作用**。

训练轮次就是让你的每一次改动都能"写论文"：
假设是论文的命题，变量是自变量，测试集是因变量的量尺，判定阈值是显著性标准。

**对长期表现的影响。**

轮次纪律直接决定**训练是否复利**。

有轮次的训练：第 5 轮的起点是第 4 轮的终点，知识累积。
无轮次的训练：每一轮都像第一轮，同类问题反复出现，**永远在原地打转**。

更隐蔽的影响是**回滚粒度**：
大改失败时你只能整包回滚，把有效的改动一起埋掉；
小步失败时你只回滚那一个分支，其余成果全部保留。

**怎么写、怎么用。**

本机真实场景下，一轮训练的完整记录长这样（叙事式，不是命令块）：

- **轮次目标**：把"结论先行"的比例从 40% 提到 70%
- **唯一变量**：SOUL 的语气字段从 casual 改成 direct
- **基线**：训练前同一测试集上的结论先行率 = 40%
- **测试集**：20 条（正常 / 边界 / 失败三层）
- **判定阈值**：holdout 上 ≥70% 视为有效
- **结果**：__%（未填完就不算训完）
- **结论**：并入主线 / 回滚

**技巧。**

1. **一轮只碰一个文件**。动 SOUL 就别动 TOOLS；动 TOOLS 就别动 MEMORY。
2. **分支命名带轮次**：`train-r1-delivery-format` 比 `fix-stuff` 强一百倍——它在半年后仍然自解释。
3. **用 `git diff --stat` 自证单变量**：一轮的分支差异超过一个文件，就是设计缺陷，不是勤奋。

**常见误区。**

- 把"改了很多"当"训得很深" → 恰恰相反，改得越多，学到越少。
- 一轮同时拉能力三角和可靠性三角 → 目标分散，两个都没训透。
- 只记录最终配置，不记录中间轮次 → 你丢掉了**过程知识**，只留下了结论。

**进化阶梯。**

轮次能力三级：会跑一轮（有记录）→ 会串多轮（有累积）→ 会**设计轮次序列**（知道哪一轮该拉哪个三角、步幅多大）。

### 概念 4 · 导师智能体（Mentor Agent，原：教练虾）

**这是什么。**

导师智能体（Mentor Agent，原：教练虾）是训练流程的**执行主体**，同时也是**训练学最激进的论断**：

> **训练流程本身可以被智能体化。**

也就是说，"谁来带它"这件事，不一定要由人来干。
一个专职的评估型智能体，可以按固定测试集自动跑轮次、生成评估报告、给出根因假设。

它的最小人格定义非常克制——**只做评估与打分，不改被训智能体的配置**。
这条边界是刻意设计的：**评级者不拥有被评级者的写权限。**

**核心目的。**

训练之所以经常失败，往往不是 prompt 不够好，而是**没有一个会观察、会反馈、会追问、会沉淀的教练在带它**。

三种错觉会让训练退化为随机试探：

- 错觉一："我已经看得很清楚了" ——其实只看到"这次还行/这次不行"，没有记录具体偏差。
- 错觉二："多试几次就会了" ——其实没有观察框架、没有反馈回路，每轮都是独立试探。
- 错觉三："失败就是模型不行" ——大部分失败是**训练设计问题**，不是模型问题。

导师智能体的存在，就是为了把这三条错觉变成**可审计的动作**。

**拟人化映射。**

一个人带徒弟，最没用的时间是"看它输出"的时间，最有用的时间是**观察、反馈、追问、沉淀**。

一位合格的教练，一轮训练里的时间分配大致是：

| 动作 | 建议占比 | 不是什么 |
|---|---|---|
| 观察 Observe | 30% | 不是"看一眼" |
| 反馈 Feedback | 25% | 不是"夸/骂" |
| 追问 Probe | 25% | 不是"再试一次" |
| 沉淀 Codify | 20% | 不是"过了就忘" |

如果 80% 的时间在"看它输出"，那他不是教练，**他是个观众**。

更糟的是**复读机模式**：

> 人："这轮不行，再来一次。"
> 智能体："好的，我重新来。"

这不是训练。真正的追问是三个问题：
**这次失败的本质原因是什么？这是系统性问题还是偶发问题？下一轮要验证什么？**

**对长期表现的影响。**

人肉教练有一个不可绕过的缺陷：**不可持续 + 不可复现**。

- 人一忙，训练就断。三天后智能体回到原点。
- 每次标准不一样：今天严格、明天宽松、后天赶时间直接放过。
- 十个智能体就要十倍人力——训练无法规模化，也无法交接。

而机器做得越久越一致，人做得越久越容易走样。这不是谁更努力的问题，是**一致性**问题。

**怎么写、怎么用。**

导师智能体的四个职责，每一个都配一条"铁律"：

1. **观察（Observe）** ——按框架看，不是凭感觉看。
   观察维度四个：稳定性（风格/语气/角色是否一致）、完整性（是否有产物/证据/验收）、
   边界（是否越权/越级/越界）、漂移（哪里开始不像上一轮）。
   **铁律：不记录 = 没观察。**

2. **反馈（Feedback）** ——三段式：事实描述 → 偏差识别 → 纠偏建议。
   **铁律：不纠偏 = 无效反馈。**

3. **追问（Probe）** ——把"再来一次"换成"改变 X 后看 Y 是否变化"。
   **铁律：不追问原因 = 下一轮还是瞎试。**

4. **沉淀（Codify）** ——写入记忆、更新 SOP/模板、更新问题账本。
   **铁律：不沉淀 = 这一轮白训。**

**技巧。**

1. **导师与被训者分离权限**：导师只读被训者的配置，只写评估报告。
2. **导师也要被训练**：导师自身的阶梯是 会观察 → 会反馈 → 会追问 → 会沉淀 → 会设计 → 会复制。
   最后一级"会复制"才是真正的杠杆——**能训练其他导师，才形成训练产线**。
3. **固定测试集是导师的牙齿**：没有固定测试集，导师只能临时出题，标准每次都漂。

**常见误区。**

- **只给感觉，不给事实**："感觉还是有点漂"——被训者不知道哪里错了。
- **只纠结果，不纠原因**："没完成，再来一次"——下次大概率还是失败。
- **不记录不沉淀**：每轮都像第一轮，训练无法复利。
- **把导师当人肉跟班**：人肉反馈最快（改完立刻看），所以最容易被误认为是"捷径"。

**进化阶梯。**

导师能力六级：会观察 → 会反馈 → 会追问 → 会沉淀 → 会设计轮次 → 会复制教练。
本机 ⏳ 尚未有专职的 `mentor` 智能体目录（`~/.openclaw/workspace/agents/mentor` 不存在）；
当前的导师职能由**人 + 固定测试集 + 手工触发的评估**承担。
这是本章最重要的工程缺口之一，第 5 节会再提。
### 概念 5 · 训练前准备清单（Readiness Checklist）

**这是什么。**

准备清单是训练的**入场券**。它是一份很短、很硬、缺一不可的清单。

本机版的最小清单是五项：

1. **目标**：可度量的场景（例：漂移检测报告格式正确率 ≥ 90%）
2. **基线**：训练前在同一测试集上的表现（**跑一次并记录**）
3. **测试集**：≥ 10 个用例（覆盖正常 / 边界 / 失败）
4. **契约快照**：给训练前的配置打一个版本标签（`git tag pre-train-YYYYMMDD`）
5. **验收口径**：什么算"训成了"（**写清楚**）

**核心目的。**

准备清单的唯一目的，是让训练**可度量**。

> 训练的前提是可度量。没有基线，就没有"训练后"的对照。

"训得更好"不是目标。"在 X 类任务上把正确率从 A 提到 B"才是目标。

**拟人化映射。**

准备清单不是"流程仪式"，它是**起飞前的检查单**。

飞行员起飞前念检查单，不是因为不信任自己的技术，而是因为**人在压力下会跳步**。
跳步的代价在飞行里是坠机，在训练里是**三周白干**。

一个不肯念检查单的人，通常会在两周后说一句本章最想消灭的话：
"我记得以前好像是可以的。"

**对长期表现的影响。**

跳准备清单的代价不是立刻显现的，它在**训练结束那一天**显现：

- 无法证明有效——训完说不出"提升了多少"
- 无法回滚——改坏了不知道回到哪
- 重复劳动——这次训完，下次同样场景又要从零开始
- 无法交接——你的成果只存在于你的印象里

注意第 4 项：**契约快照**。它是准备清单里最容易被跳过、也最不能跳过的一项。
没有快照，你的"训练前"是一个**不可重现的状态**——你连"回到起点"都做不到。

**怎么写、怎么用。**

准备清单应该写成一个**落盘文件**，而不是记在脑子里。
本机建议的落地位置是 `~/notes/domain/silicon-life-handbook/training/README.md`，
并且检验它的方式极其简单粗暴：**数一数有几条编号项**。五条，就是齐了。

四项证据要同时存在：

- 清单文件存在，且编号项 = 5
- 基线数字记录了（哪怕只有一行）
- 契约快照标签存在（`pre-train-*`）
- 测试集文件存在（`testset*`）

**技巧。**

1. **基线的第一件事是"承认现状"**：即使你已经乱改过一轮，也要测"当前值"作为基线，而不是假装回到出厂状态。
2. **目标是可判定的**：">90%"、"≥ 20 条"、"从 40% 到 70%"。形容词不算目标。
3. **快照用标签，不用分支**：标签是只读的坐标，分支是可变的工作区。你要的是坐标。

**常见误区。**

- **"我都记得"** → 你记得的是印象，不是数字。
- **"先训起来，基线以后补"** → 以后补的基线已经不是基线了，是被污染过的值。
- **"就一个智能体，不用这么正式"** → 恰恰相反：单智能体训练最容易被"手感"绑架。

**进化阶梯。**

准备能力三级：会列清单（齐五项）→ 会设计目标（可判定 + 有阈值）→ 会设计**对照结构**（预想到混淆变量）。

### 概念 6 · 固定测试集（Fixed Test Set：train / holdout）

**这是什么。**

固定测试集是训练的**量尺**。关键词是"固定"两个字：

> **用固定测试集，不用临时题。**

它至少有两条硬规则：

1. **分层**：正常 / 边界 / 失败三类各占约三分之一，总量 ≥ 20 条
2. **拆分**：分成训练集（train）与留出集（holdout）两份，**只在 train 上调，用 holdout 做最终判定**

**核心目的。**

固定测试集的目的有两个，缺一不可：

- **可比性**：同一把尺子量前后，差异才是真的差异
- **抗过拟合**：holdout 存在的唯一理由，就是防止你把"背答案"当成"学会了"

**拟人化映射。**

这是**考试题库 vs 高考**的区别。

训练集是你的**练习册**——你可以在上面反复刷，把每道题都做对。
留出集是**高考卷**——你没见过，而且只用一次来说话。

一个学生把练习册刷到满分就宣布"我学会了"，任何老师都会笑。
但同一个学生在训练智能体时，天天干这件事。

还有一个更隐蔽的比喻：**如果医生只用一个病人做诊断标准**，
他学到的不是"感冒怎么诊断"，而是"这个病人怎么诊断"。
**测试集太小，你训出来的不是能力，是记忆。**

**对长期表现的影响。**

过拟合是训练里**最贵的一种失败**，因为它**伪装成成功**。

- 表面上：通过率 100%
- 实际上：泛化能力为零
- 后果：换一个新场景立刻失败（第 4 章的每周体检清单会暴露它）
- 更糟：基于过拟合的基线继续训练，**误差被不断放大**

所以测试集的分层与拆分不是"完美主义"，是**防止你朝错误方向加速**。

**怎么写、怎么用。**

本机建议的落盘结构（固定路径）：

```
~/notes/domain/silicon-life-handbook/training/
    testsets/    固定测试集（train.jsonl / holdout.jsonl）
    rounds/      每轮记录（round-YYYYMMDD.md）
    reports/     评估报告（report-YYYYMMDD.md）
```

一条测试用例的最小结构包含三件事：**id / 输入 / 期望**。
期望必须是**可判定的**，不能是"输出得好一点"。

**技巧。**

1. **先攒 10 条，再分层扩到 20+**：不要一开始追求大而全，先让尺子存在。
2. **失败样例要真的失败过**：从真实事故里挖用例，比编出来的用例有价值得多。
3. **holdout 只用一次**：反复看 holdout 的结果并据此调参，holdout 就退化成了 train。
   这条规则和机器学习里"不许偷看测试集"是同一个道理。

**常见误区。**

- **把测试集当考试题库**：反复针对同一批题调配置，直到全过。
- **测试集全是正常路径**：没有边界、没有失败样例，尺子只量了最容易的那一维。
- **没有 holdout**：于是你的"通过率"永远无法区分"学会了"与"背答案了"。
- **用例期望不可判定**：期望写成"输出专业一点"，等于没有期望。

**进化阶梯。**

测试集能力三级：会建用例（≥10 条）→ 会分层拆分（三层 + holdout）→ 会**从事故反推用例**（把每一次真实失败固化成一道题）。

### 概念 7 · 实验方案（假设 / 基线 / 阈值）

**这是什么。**

实验方案把"改动"升级为"实验"。它由四件东西构成：

1. **假设**：改了 X，会提升 Y（一句话，可被否证）
2. **指标**：用什么量、在哪个测试集上量
3. **基线**：改之前的数值（必须已存在）
4. **判定阈值**：达到多少算有效（**在实验开始前写死**）

**核心目的。**

没有假设，你**无法判断"改进"是真实效果还是随机波动**。

这是训练里最普遍的自欺：改完之后"感觉好点了"就推进下一项。
但"感觉"无法排除三种混淆：

- 模型本身的随机性
- 上下文长度的变化
- 你只测了简单用例

**拟人化映射。**

无假设的实验，长这样：

> "今天把语气改成 direct，感觉不错，继续。"

有假设的实验，长这样：

> 假设：把 tone 从 casual 改为 direct，可提升"结论先行"比例。
> 指标：20 个测试用例中的结论先行率（基线 40%）。
> 对照：保持其他契约不变。
> 判定：结论先行率 ≥ 70% 视为有效。

第二条是有价值的，因为**它是可被否证的**。
如果只跑到 45%，你会老老实实回滚，而不是"感觉还行所以留着"。

**对长期表现的影响。**

实验方案保护的是**经验的纯度**。

无假设的实验会把无效改动当成有效经验沉淀下来，**污染后续决策**。
污染一旦进入记忆层，它会被反复引用、反复放大——最后你会基于一堆幻觉经验做架构决策。

**怎么写、怎么用。**

一份实验记录必须包含"结果"字段，而且**未填完就不算训完**。
这是本机原章节里最漂亮的一句话：**"没数字不算训完。"**

判定阈值必须在**实验开始前**写死。事后定阈值，等于没有阈值。

**技巧。**

1. **阈值要来自业务，不来自心情**：">90% 正确率"是因为下游要消费这个格式，不是因为 90 看起来顺眼。
2. **对照组就是"其他契约不变"**：不需要另建一个智能体，只需要在实验期间锁住其他变量。
3. **一次实验一个假设**：写两个假设，等于没写。

**常见误区。**

- **无假设，凭感觉改**：改完"好像好点了"就推进，是本章最常见也最贵的错误。
- **无对照组**：无法排除混淆变量带来的假改善。
- **阈值事后补**：把"实际跑出来的数"当成"目标"，这是自欺的高级形态。
- **只记结论不记假设**：半年后你只知道改了什么，不知道为什么改。

**进化阶梯。**

实验能力三级：会写假设（可否证）→ 会定阈值（事前 + 来自业务）→ 会**识别混淆变量**（知道什么会让实验失效）。

### 概念 8 · 小步快跑（每轮一个变量）

**这是什么。**

小步快跑是轮次设计的**操作纪律**，一句话：

> **每轮只改一个维度，只动一个主变量。**

它对应一种"反直觉"的工程美学：**改得少，学得多。**

**核心目的。**

它的目的是保住**归因能力**。

归因能力一旦丢失，训练的反馈角（Feedback）就断了——
你会发现自己永远在"改了一点、好像好了、继续改"的循环里，而**从不知道是哪一次改对了**。

**拟人化映射。**

这是**调试代码**的老规矩：一次改一处，改完立刻验证。

一个老手排查线上故障时，绝不会同时干三件事：改配置、升级依赖、重启服务。
因为他知道——**这样即使修好了，他也没学到任何东西。**

小步快跑是一种**认知上的节俭**：它牺牲了"一次搞定"的快感，换来了"每次都懂"的复利。

**对长期表现的影响。**

小步快跑影响的不是单轮效果，而是**回滚粒度**和**知识累积**。

- 大改失败 → 整包回滚 → 有效改动一起被埋
- 小步失败 → 单点回滚 → 其余成果全部保留

一年后，两个人的差距不在"谁改得多"，而在**谁的知识还在**。

**怎么写、怎么用。**

一轮训练的物理形态是这样的（叙事式）：

- 从当前主线切出一个分支，分支名带上轮次与变量：`train-r1-delivery-format`
- 只改 SOUL 的交付格式段（**别的一行不碰**）
- 跑测试集，拿数字
- 有效 → 并入主线；无效 → 回滚分支，记录失败原因
- 下一轮换一个变量：`train-r2-tools`

本机原章节给了一个极好的自检方式：**统计每个训练分支的 diff 行数与文件数**。
如果一轮分支动了三个以上文件，这一轮就**已经失去归因价值**了，不必等结果出来。

**技巧。**

1. **变量要"原子"**：SOUL 的交付格式段是一个变量，"SOUL + AGENTS 一起改"是两个变量。
2. **每轮开头就写下"本轮唯一变量"**：写不出来，就说明这轮不该开。
3. **回滚要顺手**：分支隔离让回滚变成一条命令，而不是一次考古。

**常见误区。**

- **把"改了很多"当"训得很深"**：恰恰相反。
- **同时改人格 + 工具 + 记忆 + 路由**：训练后变好你不知道谢谁，变坏你不知道回滚谁。
- **"反正都要改，一起改省时间"**：省下的是时间，赔掉的是归因。
- **一轮拉两个三角**：能力三角和可靠性三角同时动，等于零归因。

**进化阶梯。**

步幅控制三级：会一轮一变量（有分支纪律）→ 会一轮一三角（能力/可靠性交替）→ 会**排轮次序列**（按依赖关系决定先后顺序）。
### 概念 9 · 训练记录落盘（Round Log）

**这是什么。**

训练记录落盘是把训练从"发生在会话里的一次事件"变成"留在磁盘上的一份资产"。

关键词是**落盘**——不是"记在心里"，不是"写在会话里"，是**写进文件系统**。

**核心目的。**

训练的价值**一半在过程记录**。

这句话听起来像免责声明，其实是最硬的经济学：
一次训练的结果只是一个数字，**过程记录才是可复用的资产**。

一个完整的轮次记录包含五段：

- 轮次目标
- 变更内容（`git diff --stat`）
- 测试集结果（通过率 / 失败样例）
- 反馈（根因）
- 结论（是否并入主线）

**拟人化映射。**

会话是**易失的**——这是第 2 章就讲过的事。

会话压缩（Session Compaction，原：会话卫生）之后，中间推理被折掉；
会话结束之后，上下文归零。
**你唯一真正拥有的，是你写进文件的东西。**

这是硅基生命与人的一个共同点，也是一个差异：
人的记忆会自然衰减但不会归零；会话的记忆会**精确地、干净地归零**。
所以对智能体而言，"不落盘"不是遗忘，是**删除**。

**对长期表现的影响。**

不留痕的训练有三个后果，一个比一个贵：

1. **同类问题重复踩坑** ——因为上次的根因没被写下来
2. **训练无法沉淀为组织能力** ——经验只存在于参与者的印象里，人走了就没了
3. **无法审计** ——第 5 章的治理审计账本（Governance Audit Ledger，原：治理账本）需要证据链，
   而训练留痕是这条链的第一环

**怎么写、怎么用。**

本机建议的固定路径与命名约定：

- `round-YYYYMMDD.md` ——每轮一条，文件名带日期，天然可排序
- `report-YYYYMMDD.md` ——评估报告
- 目录结构 `{rounds, reports, testsets}` 三件套

检验方式同样直接：**数文件个数**、**grep 必备段是否存在**、**看 git 历史与记录是否对得上**。

第三项最关键：**如果 git log 里有一次改动，而 training/ 里没有对应的轮次记录，那就证明有人跳过了落盘。**

**技巧。**

1. **模板先行**：把五段模板写死，每轮只填空。填空比重写模板便宜十倍。
2. **失败轮次也要落盘**：失败记录比成功记录更值钱——它防止你重犯。
3. **记录"为什么"而非"是什么"**：`git log` 已经告诉你改了什么，记录里要写**为什么改**。

**常见误区。**

- **"训练记录只存在于会话里"** ——会话一压缩就没了。
- **只记成功不记失败** ——你会在三个月后重走同一条死路。
- **记录写得像流水账** ——没有根因、没有结论，等于没记。
- **落盘了但没版本控制** ——记录与配置改动脱钩，无法互相验证。

**进化阶梯。**

留痕能力三级：会写单轮记录（五段齐）→ 会写轮次序列（能回溯决策链）→ 会**从记录里提取可复用模式**（把过程知识变成技能基因 / 可复用能力单元，原：技能基因）。

### 概念 10 · 过拟合识别（Overfitting Detection）

**这是什么。**

过拟合识别是训练里的**反向能力**：不是"怎么训得更强"，而是**怎么发现自己在骗自己**。

它的判据非常干净：

> **train 通过率 100% / holdout 明显低 → 判定为过拟合，回滚。**

**核心目的。**

过拟合识别保护的是一句最难保住的话：**"这是真的。"**

训练里有一种失败最危险——它不报错、不告警、不让系统崩溃。
它只是让你的数字变漂亮，同时让你的能力**原地不动**。

**拟人化映射。**

这是**背答案的学生**。

他用同一本练习册刷了二十遍，每道题都能倒背。考试换一套题，他考了 30 分。
——更糟的是，**他自己不知道自己不会**，因为练习册上他永远是满分。

在训练里，这个学生的"练习册"就是那个 10 条测试集。
他的"满分"就是他反复调配置对齐出来的 100%。

**对长期表现的影响。**

过拟合最坏的后果不是"这次训差了"，而是**它污染基线**。

- 虚假达标：通过率 100%，泛化能力为零
- 误导后续：基于过拟合的基线继续训练，误差被不断放大
- 体检暴露：它会在第 4 章的每周体检清单（Weekly Health Checklist）那一天集中爆发

所以过拟合**必然暴露，只是迟早**。区别只在于：你是在训练轮次里主动发现它，还是在生产环境里被动发现它。

**怎么写、怎么用。**

三道防线，从便宜到贵：

1. **拆分**：测试集分 train / holdout 两份，只在 train 上调，用 holdout 做最终判定。
2. **分层**：正常 / 边界 / 失败三层各约三分之一——三层都过才叫过。
3. **看差距**：把 "train 通过率 − holdout 通过率" 作为一个**显式指标**记录下来。
   当这个差值持续大于某个阈值，就是过拟合的早期信号。

**技巧。**

1. **holdout 只用一次**：反复看 holdout 结果并据此调参，它就不再是 holdout。
2. **警惕"太顺利"**：如果第一轮就 100%，通常不是训得好，是题太简单。
3. **把失败样例当资产**：能稳定复现的失败样例，比能稳定复现的成功样例更有信息量。

**常见误区。**

- **通过率是最直观的指标，于是新人天然去"拉高它"，而不是"让智能体学会"** ——这是过拟合的心理根源。
- **不知道测试集要分层** ——尺子只有一维，量不出泛化。
- **没有留出集概念** ——于是无法区分学会与背答案。
- **发现过拟合后只调 holdout** ——那是把 holdout 也污染掉，属于雪上加霜。

**进化阶梯。**

抗过拟合能力三级：会拆分（train/holdout）→ 会看差距（显式记录差值）→ 会**主动构造对抗样例**（故意出难题来暴露虚假达标）。

### 概念 11 · 训练节拍（Heartbeat as Training Cadence）

**这是什么。**

训练节拍是本章与第 2 章的**接口**：**训练的时间轴由 Heartbeat 提供。**

双三角模型的第一个三角是"期望 → 行动 → 反馈"闭环。
**闭环的节拍由 Heartbeat 提供**：智能体每隔 `every` 醒一次 → 行动 → 反馈 → 重建期望。

本机真实字段路径（per-agent，**不是全局配置**）：

```
agents.entries.<id>.heartbeat
```

⚠ 这是本章最容易踩的字段坑之一：**heartbeat 不是全局字段，是 per-agent 字段。**
真实顶层 key 里**没有** `heartbeat`——它挂在 `agents.entries.<id>` 之下。

**核心目的。**

节拍的目的，是让训练**有节奏**，而不是"想起来才训"。

训练最怕的不是训得慢，是**训得断续**：
三天密集、两周停摆——这叫"训练休克"，效果基本归零。

**拟人化映射。**

这是**晨跑**与"这个月想起来了跑三次"的区别。

晨跑的关键从来不是强度，是**准时性**。准时性建立的是**身体的预期结构**，
让恢复、供能、疲劳曲线形成可预测的节奏。

训练也一样：节拍建立的是**智能体的预期结构**——它知道什么时候会被唤醒、被评估、被要求交付。
**有预期结构的智能体，行为是可预期的**（这就是可靠性三角里的"可预期性"顶点）。

**对长期表现的影响。**

节拍直接决定 L3（反思型）能否达成。

没有稳定节拍，漂移检测就没有触发点，每周体检就变成"想起来才做"——
而第 4 章的整个漂移治理三件套（Drift Governance Trio）**都建立在"按节拍醒来"这个前提上**。

**本机实测（这是本章最需要看证据的一段）。**

本机 18 个智能体里，**只有 3 个配了 heartbeat**：

| 智能体 | `heartbeat.every` | 实测方式 |
|---|---|---|
| kunlun | 30m | `openclaw config get agents.entries.kunlun.heartbeat.every` |
| peter | 2h | 同上 |
| tiance | 30m | 同上 |
| 其余 15 个 | （无） | 同上，返回空 |

昆仑的完整 heartbeat 实读六个字段（2026-09-28 复核）：

```json
{
  "every": "30m",
  "model": "opencaio/gpt-5.5",
  "directPolicy": "block",
  "timeoutSeconds": 120,
  "lightContext": true,
  "isolatedSession": true
}
```

> ⚠ **勘误（2026-09-28 实测）**：本章 SOP 节原记载昆仑 heartbeat 为 `timeoutSeconds: 30`，
> **实测为 `120`**。以本机实读为准。这是本章自曝的第二处勘误。

**关键字段释疑。**

`directPolicy: "block"` 是这套配置里**最不能删的一个字段**。
它决定心跳唤醒时**不能**直接做"外部副作用类动作"（呼应第 4 章的主动性边界三档，Proactive Boundary Triad）。
删掉它，智能体就退化成"能干的都干"——主动性从"治理住的主动"退化为"噪音"。

**心跳配了 ≠ 心跳跑通。**

这是本章第三条诚实边界。本机 `openclaw cron list` 实测：

| cron job | 节奏 | 状态（2026-09-28 实测） |
|---|---|---|
| `heartbeat:kunlun` | every 30m | **ok**（上次 23 分钟前） |
| `heartbeat:peter` | every 2h | **ok**（上次 49 分钟前） |
| `heartbeat:tiance` | every 30m | **skipped**（上次 16 分钟前） |

> ⚠ **状态已变化**：本章 SOP 节原记载 `heartbeat:kunlun` 为 `error (99+x)`、`heartbeat:peter` 为 `error (70x)`。
> 2026-09-28 复核时两者均为 **ok**。这说明心跳健康度是一个**动态量**，
> 任何写进书的"心跳状态"都会过期——**唯一可信的是你刚刚跑的那一次**。

此外，本机还存在一批**不在 heartbeat 注册表里、但名字含 heartbeat 的 cron**：
`heartbeat-morning-530` / `heartbeat-morning-600` / `heartbeat-breakfast-700`（均挂在 peter，isolated 会话）、
以及 `凤凰-HEARTBEAT每日检查`（挂在 fenghuang，交付到 `telegram:8328029665`，模型 `minimax/MiniMax-M2.7`）。

**这批 job 揭示了一个重要事实**：训练节拍在本机**有两套**——
一套是 per-agent 的 `heartbeat` 字段（注册表可见），一套是独立的定时任务（名字像心跳、机制不是心跳）。
**两套并存时，你必须知道自己在看哪一套。**

**怎么写、怎么用。**

给一个智能体装训练节拍的完整动作是三步（叙事式，命令由 SOP 节承载）：

1. **建脚手架**：`training/` + `.training-data/` 两目录
2. **配节拍**：`agents.entries.<id>.heartbeat` 六字段，复制已验证的模型
3. **验接入**：`openclaw cron list` 看 `heartbeat:<id>` 是否出现

**铁律：先给 1 个智能体配通，再批量复制。** 本机 18 个里只有 3 个配了——这个比例本身就是提醒。

**技巧。**

1. **`every` 不是越短越好**：30m 是昆仑/天策的当前取值，peter 是 2h。
   节拍频率应该匹配"它需要多快发现变化"，而不是"我希望它多勤快"。
2. **`isolatedSession: true` + `lightContext: true`**：心跳不应该污染主会话的上下文。
3. **每次醒来落一条"行动 → 反馈"记录**：这是第 4 章漂移体检的原料。

**常见误区。**

- **假设 heartbeat 是全局配置** → 它是 per-agent 字段。
- **在 `~/.openclaw/workspace/openclaw.json` 找配置** → ⚠ 真名路径是 `~/.openclaw/openclaw.json`，
  **workspace 下没有 openclaw.json**（本机实测）。
- **用 `openclaw configuration` / `openclaw conf`** → 真名子命令是 `openclaw config`（`get`/`set`/`patch`/`file`/`schema`）。
- **漏掉 `directPolicy: "block"`** → 越权闸门失效。
- **以为"配了"就是"跑通了"** → 看 cron 状态，不看配置文件。

**进化阶梯。**

节拍能力三级：会配单个（一个智能体跑通）→ 会批量（多个智能体 + 健康度观测）→ 会**调频**（按任务性质给不同智能体不同节拍）。

### 概念 12 · 诚实边界与证据分级（Evidence Grading）

**这是什么。**

诚实边界是本章最后一个概念，也是**唯一一个关于"我自己"的概念**：
它是训练学对**自身主张**的证据分级纪律。

本章采用两级标记：

- **✅ 已实测** —— 本机跑过、有输出、可复现
- **⏳ 待验证** —— 有出处但未在本机验证，或工程原型尚未存在

**核心目的。**

它的目的是防一件事：**把推断写成事实。**

在一个方法论章节里，最容易发生的失真不是"说错"，而是**"把应该标 ⏳ 的东西写成了 ✅"**。
读者照着做，做不通，然后对整个方法论失去信任。

**拟人化映射。**

这是**实验记录本的规范**，不是**宣传册的文风**。

一个诚实的研究者写"我们观察到 X"，而不是"X 就是这样的"。
前者给了后续研究修正的空间，后者把一次观察固化成了一条定律。

训练学尤其需要这种节制——因为它讨论的都是**长期、动态、会漂移**的对象。
任何一句写进书里的"现状"，都自带一个**过期时间**。

**对长期表现的影响。**

诚实边界的价值，在于它保护了**方法论的可信度**。

本章已经自曝了三处勘误（版本号从 2026.9.4 前进到 2026.9.6、`timeoutSeconds` 30→120、心跳状态从 error 转 ok）。
这三处的意义**不是"原来写错了"，而是"这套方法允许它自己被修正"**。

一个不允许被修正的方法论，会在第一次与现实冲突时整体崩塌。

**怎么写、怎么用。**

- **导师智能体尚未实体化**：`~/.openclaw/workspace/agents/mentor` 不存在；导师职能当前由人 + 固定测试集 + 手工触发承担
- **L5 提案型的工程原型**待推（2026 Q4 之后）；本机 `EVOLUTION.md` L5 状态为 ⬜
- **L5 判据是自定口径**（自下而上提案数 > 被派发任务数）——业界无对位基准，不可对外当行业标准引用
- **进化阶梯 5 级的量化判定阈值**待实测校准
- **`training/prompt-v2-module*.md` 的实际教学效果**未做对照实验

**技巧。**

1. **每条主张问一句"我怎么知道的"**：答案只能是"我跑了"或"我读到的出处"。
2. **给出复查命令**：写 ⏳ 的同时写"怎么才能变 ✅"。
3. **自曝勘误不丢分**：本机 SOP 节的三处勘误，全部写在明面上。

**常见误区。**

- **把推断写成事实** ——最普遍的一种失真。
- **引用会漂移的数值当常量** ——第 7 节会看到，业界 star 数、榜单单日排名都属于这一类。
- **只写 ✅ 不写 ⏳** ——一个有零个待验证项的方法论，通常意味着没有验证过任何东西。

**进化阶梯。**

证据纪律三级：会分级（✅/⏳ 分开列）→ 会给复查路径（写出怎么验证）→ 会**主动自曝勘误**（发现自己的旧结论过期时，改书而不是改口径）。

## 三、怎么做：从一只普通智能体到专家智能体的七步实践路径

十二个概念讲完了。现在把它们串成一条**能走的路**。

这一节给的是**实践路径**，不是操作手册——具体命令由 SOP 节与 Cookbook 承担。
这里每一步都给一个**叙事式示例**，你要看的是**判断顺序**，不是复制粘贴。

### 第一步 · 立基线：先量，再改

**这一步在做什么。**

在动任何一行配置之前，先测一次"当前值"。

**为什么顺序不能反。**

因为基线是一次性的。改动之后再测，测到的已经不是基线，而是**被你的改动污染过的中间态**。

即使你已经乱改过一轮，也要测"当前值"作为基线——**承认现状，比假装回到出厂状态诚实得多**。

**叙事式示例。**

你要训一个智能体，目标定为"漂移检测报告格式正确率 ≥ 90%"。

那么第一件事不是打开 SOUL.md 开始改，而是：

- 拿 20 条用例，让它跑
- 数出"格式正确"的有几条
- 假设是 7 条 → **基线 = 35%**
- 把这个数字写进 `~/notes/.../training/README.md`
- 给当前配置打一个标签：`pre-train-YYYYMMDD`

现在你有了一个**坐标**。之后所有的"提升了多少"，都是相对这个 35% 说的。

**这一步的验收口径。**

- 基线数字存在（哪怕只有一行）
- 快照标签存在
- 测试集文件存在

三项缺一，回到起点。

**这一步最容易犯的错。**

"先训起来，基线以后补。"——以后补的基线，是被污染过的值，不是基线。

**（对应准备清单五项中的第 2、3、4 项）**

### 第二步 · 定尺子：测试集分层 + 拆分 holdout

**这一步在做什么。**

建一把**固定的尺子**，并把它折成两半：一半用于练习，一半用于判卷。

**为什么必须有 holdout。**

因为**人对自己的宽松是无意识的**。

你反复针对同一批题调配置，会有一种强烈的"我快要学会了"的体感。
这个体感是真的——**你确实快学会了，学会的是那批题**。

holdout 的存在，就是把"这批题"和"这类题"分开的唯一办法。

**叙事式示例。**

你有 20 条用例：

- 按类型分三层：正常 7 条 / 边界 7 条 / 失败 6 条
- 按用途拆两份：`train.jsonl` 前 12 条打底，`holdout.jsonl` 后 8 条封存
- 只在 train 上调配置；holdout **平时不看，只在判定轮次打开一次**

**数值的分层判据。**

- 每层都能独立报通过率 —— 只看总分，你会被"正常路径全过"骗过去
- 失败样例必须来自**真实失败过的事故**，不要编

**这一步的验收口径。**

- 用例数 ≥ 20
- 三层结构可在文件名或字段上区分
- train / holdout 两个文件都在，且 holdout 有明确的"开封规则"

**这一步最容易犯的错。**

把测试集当考试题库——反复针对它调配置，直到全过，然后宣布训练完成。

**（对应核心概念 6 与概念 10）**

### 第三步 · 装节拍：把训练时钟接上 Heartbeat

**这一步在做什么。**

给训练接入**时间轴**。训练不是"想起来才做"，而是"到点就做"。

**为什么节拍先于内容。**

因为**没有节拍的训练，一定会在第二周停摆**。

人不会因为"应该训"而持续做某件事，人会因为"到点了"而做某件事。
Heartbeat 提供的正是这个"到点了"。

**叙事式示例。**

你要训的智能体叫 `my-agent`：

- 先建脚手架：`workspace-my-agent/training/` 与 `workspace-my-agent/.training-data/`
- 再配节拍：`agents.entries.my-agent.heartbeat` 六个字段——`every` / `model` / `isolatedSession` /
  `lightContext` / `timeoutSeconds` / `directPolicy`
- **先 dry-run 看拟变更，再落盘**（这一步不能省，它是你的回滚保险）
- 落盘后验接入：`openclaw cron list` 里是否出现 `heartbeat:my-agent`

**关键判断：`every` 填多少。**

不是越短越好。判断标准是**这个智能体需要多快发现变化**：

- 负责战略调度的（昆仑）→ 30m
- 负责人格化助理的（peter）→ 2h
- 负责监督巡检的（天策）→ 30m

**这一步的验收口径。**

- `openclaw config get agents.entries.<id>.heartbeat` 返回 `every` 字段
- `openclaw cron list` 出现 `heartbeat:<id>`
- `directPolicy: "block"` 没有被漏掉

**这一步最容易犯的错。**

配完就去喝酒。**"配了"不等于"跑通"**——本机 3 个配了心跳的智能体，在最近一次观测里，
`kunlun` 与 `peter` 状态 ok、`tiance` 状态 skipped。**状态是动态量，必须定期看。**

**（对应核心概念 11）**

### 第四步 · 建导师位：让评估有一个不写配置的主体

**这一步在做什么。**

把"评估"和"被评估"**分权**。

**为什么要分权。**

因为一个自己改自己、自己评自己的系统，会系统性地**放松标准**。
这不涉及道德，只涉及结构——**评级者拥有被评级者的写权限时，评级就不成立。**

**叙事式示例（注意本机现状）。**

理想形态：一个专职的、只读的评估智能体。

- 人格极简：「只做评估与打分，不改被训智能体的配置」
- 价值观两条：「用固定测试集，不用临时题」「每轮输出：通过率 + 失败样例 + 根因假设」
- 它跑完一轮，产出 `report-YYYYMMDD.md`；人只做**决策**（并入/回滚），不做**跑腿**

**本机现状（诚实边界）。**

⏳ `~/.openclaw/workspace/agents/mentor` **不存在**。
当前本机的导师职能由**人 + 固定测试集 + 手工触发**承担。

> **这意味着：本机的训练流程目前停在"半自动"。**
> 评估动作是可复现的（有测试集、有判定阈值），但**触发是手动的**——
> 人一忙，训练就停。这是本机从"可训练"走到"持续训练"的**最大缺口**。

**这一步的验收口径。**

- 要么有一个导师智能体（只读 + 定期跑评估）
- 要么有一份**明确写出"导师职能由人承担、且触发靠人"**的诚实声明

第二项不是妥协，是**分工的清晰化**——假装有导师，比承认没有导师危险得多。

**这一步最容易犯的错。**

自己当裁判又当选手：改完自己评，"感觉专业多了"。

**（对应核心概念 4）**

### 第五步 · 跑第一轮：一个假设，一个变量

**这一步在做什么。**

第一次真正意义上的**实验**。

**为什么第一轮宁小勿大。**

因为第一轮的目标不是"提升"，而是**验证流程本身能不能跑通**。
第一轮就追求大提升的人，通常会得到**一个巨大的、不可归因的变化**，
然后花两周去猜是哪一步起的作用。

**叙事式示例。**

- **假设**：把 SOUL 的语气字段从 casual 改为 direct，可提升"结论先行"比例
- **指标**：`train.jsonl` 上的结论先行率（基线 40%）
- **唯一变量**：只改 SOUL 的**一个字段**——AGENTS / TOOLS / MEMORY 一行不碰
- **分支**：`train-r1-tone-direct`
- **判定阈值**（**实验前写死**）：holdout 上 ≥ 70% 视为有效
- **结果**：`__%`（未填完不算训完）
- **结论**：并入主线 / 回滚

**这一步的验收口径。**

- 分支只动一个文件（自证方式：`git diff --stat`）
- 阈值在结果之前写下
- "结果"字段被填上真实数字

**这一步最容易犯的错。**

一次改七个文件，然后 commit 一条 "大改"。

**（对应核心概念 3 / 7 / 8）**

### 第六步 · 判定与并入：用 holdout 说话，不用感觉说话

**这一步在做什么。**

打开 holdout，做**一次**判定。

**为什么只开一次。**

因为 holdout 的效力来自"你没见过它"。
你看第二次的时候，你的调参已经被第一次的结果影响了——**holdout 已经降级成了 train**。

**叙事式示例。**

- 打开 `holdout.jsonl`，跑一次，得到结论先行率 **74%**
- 74% ≥ 70%（事前阈值）→ **有效**，并入主线
- 同时记录 **train 与 holdout 的差值**：train 82% / holdout 74% → 差值 8 个百分点，**在可接受范围**
- 若 train 100% / holdout 45% → **判定过拟合，回滚**，并把这个差值写进记录

**并入与回滚的动作要"顺手"。**

分支隔离的价值就在这里：有效则并入主线，无效则丢掉整条分支。
**回滚一条分支是一秒钟的事；回滚一堆混杂改动是一场考古。**

**这一步的验收口径。**

- holdout 数字存在
- 判定结论明确（有效/无效/过拟合）
- train−holdout 差值被显式记录

**这一步最容易犯的错。**

改完之后只看 train，然后"感觉不错，继续"。

**（对应核心概念 7 与概念 10）**

### 第七步 · 落盘与升级：把这一轮变成下一轮的起点

**这一步在做什么。**

写记录，然后**决定要不要升一级**。

**为什么这一步不能被当成"收尾杂事"。**

因为训练的复利**只发生在这里**。
前六步产生的是一个数字，第七步产生的是**一条可被未来引用的知识**。

**叙事式示例。**

**落盘（五段，缺一不可）：**

1. **目标**：结论先行率 40% → 70%
2. **变更**：`git diff --stat`（一行：SOUL.md | 3 +-）
3. **测试集结果**：train 82% / holdout 74% / 失败样例 2 条
4. **反馈（根因）**：原先 SOUL 只写了"专业"，未定义交付格式；改 tone 后模型更倾向先给结论
5. **结论**：并入主线；下一轮变量 = TOOLS 的默认工具集

**升级判定（对着阶梯问三个问题）：**

- 当前级位的达成判据达标了吗？（例：结论先行率 ≥ 70% 且**连续三轮不掉**）
- 达标 → 进入下一级；不达标 → 停在原地，换变量再跑一轮
- **绝不越级**：L2 没稳就不碰 L4 的能力

**这一步的验收口径。**

- 本轮 `round-YYYYMMDD.md` 存在且五段齐
- git 历史与记录一一对应（有改动必有记录）
- 有一句明确的"下一轮唯一变量"

**这一步最容易犯的错。**

训完不复盘，把"感觉不错"当成结论；或者跳过直接跳到高阶能力（越级）。

**（对应核心概念 9 与概念 2）**

### 七步速览：一条闭环

把七步连起来看，它正好闭合成双三角模型的第一三角：

```
期望（第一步基线 + 第五步假设）
   ↓
行动（第三步节拍唤醒 + 第五步执行）
   ↓
反馈（第六步判定 + 第七步根因）
   ↓
回到期望（第七步"下一轮唯一变量"）
```

而**驱动这个环不断转动的，是第三步装上的 Heartbeat。**

一句话：**训练不是"把 prompt 改得更长"，而是"在可控条件下重复实验并留下证据"。**

## 四、训练方法本身的八个误区

这一节和"操作失误"不是一回事。

操作失误会让系统报错——你会立刻知道。
下面这八个误区**不会让系统报错**。它们让训练静悄悄地白做：
配置改了、消息发了、时间花了，但**训练成果无法度量、无法复现、无法交接**。

每个误区按四段展开：**现象 → 为什么错 → 怎么救 → 怎么预防**。

### 误区一 · 跳过准备清单直接开训

**现象。**

拿到一个智能体就开始"训"——改 SOUL、加规则、发几条测试消息。
三天后回看：既没有基线，也不知道哪里变好了。

典型的形态是：发一句"你现在是顶级专家了"，然后继续零散地"训"三天，
期间没有任何记录、没有任何对照、没有任何判定。

**为什么错。**

三个层次的问题：

1. **训练的前提是可度量。** 没有基线，就没有"训练后"的对照——你连"变好了吗"都回答不了。
2. **无目标 = 无方向。** "训得更好"不是目标；"在 X 类任务上把正确率从 A 提到 B"才是。
3. **代价是复利损失。** 训练变成"手感活"，无法复现、无法交接、无法证明有效。

更深一层：跳过准备清单的人，实际上**放弃了"知道自己不知道"的能力**。
没有基线的人，永远无法发现自己训错了方向。

**怎么救。**

退一步，补基础四件套——**当天就能补**：

- 测"当前值"作为基线，哪怕只有一行数字
- 攒 10 条用例，三层（正常/边界/失败）
- 给当前配置打标签 `baseline-YYYYMMDD`
- 写下验收口径，一句话

补完之后，你才拥有了"第二次训练"的资格。

**怎么预防。**

把准备清单**落盘成文件**，并且用一个粗暴的检验：数编号项。五项就是齐了。
清单写在文件里，而不是记在脑子里——**记在脑子里的清单，一定会在赶时间时被跳过**。

### 误区二 · 只做"期望—实际"，丢掉"反馈"角

**现象。**

训练者对比"期望 vs 实际"，发现差距后**直接改配置**；
从不做"为什么会有差距、下次怎么避免"这一步。
结果：同类问题反复出现。

典型的一段记录是这样的：

> 期望：输出结构化报告
> 实际：输出是自由文本
> 动作：加一句"请输出结构化报告" ← **到此为止，没有根因分析**

**为什么错。**

双三角模型的第三角是**反馈**（Feedback）——
术语定义就是 `Dual-Triangle Model: Expectation-Actuality-Feedback Loop`。

缺了反馈，模型退化成**试错**。而试错有两个致命属性：

1. **没有反馈 = 不知道改得对不对。** 你改了配置，但没验证是否解决了**根因**；
   下一个相似场景可能又错，只是表现形式不同。
2. **训练变成打地鼠。** 哪冒出问题打哪，永远不收敛。

第三层原因更根本：**"改配置"是一个廉价动作**。
它让人产生"我在做事"的感觉，而"分析根因"是一个昂贵动作——它要求你承认自己之前的设计有缺陷。

**怎么救。**

把"动作"拆成两段，中间强制插入根因：

> 期望：输出结构化报告（字段：结论/证据/不确定项）
> 实际：输出自由文本
> **反馈（根因）：SOUL 只写了"专业"，未定义交付格式；AGENTS 未列交付标准**
> 动作：① SOUL 加交付格式 ② AGENTS 加"交付标准"段
> 复核：重跑同一测试集，格式正确率 ≥ 90% → 闭环

注意最后一行"复核"——**没有复核的反馈仍然不是闭环**。

**怎么预防。**

在轮次记录模板里把"反馈（根因）"设成**必填段**，并加一条自检规则：
**每轮记录里 `grep` 不到根因分析，这一轮就不算完成。**

### 误区三 · 训练轮次设计成"一次性大改"

**现象。**

把想改的东西一次性全改：人格、工具、记忆、路由、新增三个技能，
然后 commit 一条"大改"，再测。

**为什么错。**

1. **轮次设计的核心是"可控变量"。** 一次改一个维度，才能归因。
2. **多变量同时变 = 无法归因。** 变好了不知道谢谁；变坏了不知道回滚谁。
3. **回滚粒度变粗。** 大改失败时只能整包回滚，把有效的改动一起埋掉。

还有一个隐性代价：**你会失去"学习的快感"**。
小步快跑每次都能说清"我学会了什么"；大改每次只能说"好像变了"。
**长期来看，前者积累知识，后者积累焦虑。**

**怎么救。**

停止大改，改成一轮一变量。已经改完的，做一次**逆向拆解**：

- 用 `git diff` 把大改拆成若干个逻辑单元
- 每个单元单独建分支，单独跑测试集
- 保留有效的，回滚无效的

这个过程很痛苦，但**比带着一堆无效改动继续往前跑便宜**。

**怎么预防。**

用**分支命名纪律**做硬约束：

- `train-r1-delivery-format`（轮次 + 变量）
- `train-r2-tools`

命名里写不出"本轮唯一变量"的人，这一轮不该开。

### 误区四 · 没有导师位，靠人肉全程盯

**现象。**

训练靠人一条条发消息、一条条看输出、手工纠错；人一忙训练就停。
三天后智能体回到原点。

**为什么错。**

1. **导师智能体本身就是系统的一部分。** 训练流程可以被智能体化——
   由导师按固定测试集自动跑轮次、生成评估报告。
2. **人肉不可持续。** 训练是重复劳动，人做得越久越容易走样；机器做得越久越一致。
3. **代价是训练无法规模化，也无法交接。**

第四层原因最隐蔽：**人肉教练没有留下"可复用的评估"。**
每一次评估都发生在人的脑子里，评估标准从未被写下来。
于是**换个带教的人，等于换了一套标准**。

**怎么救。**

按顺序做三件事：

- **固定测试集**（先攒 10 条，让尺子存在）
- **评估报告模板**（通过率 + 失败样例 + 根因假设）
- **导师位**（专职评估智能体，只读被训者配置）

**如果暂时做不到第三步，就把前两步做扎实，并写一份诚实声明**——
本机目前的真实状态正是这样：导师职能由人承担，触发靠人。
**承认它，比假装有导师危险得多。**

**怎么预防。**

立一条分工铁律：**人只做"决策"（并入 / 回滚），不做"跑腿"（发消息 / 数条数）。**
任何需要人重复做的动作，都是待自动化的候选。

### 误区五 · 跳过实验方案设计（无假设、无阈值）

**现象。**

凭感觉改配置，不写假设、不写预期指标。改完"感觉好像好点了"就推进下一项。

一句话总结这种状态：**"今天把语气改成 direct，感觉不错，继续。"**

**为什么错。**

1. **没有假设，你无法判断"改进"是真实效果还是随机波动。**
2. **无对照组 = 无法排除混淆变量**（模型升级、上下文变化带来的假改善）。
3. **代价：你把无效改动当成有效经验沉淀下来，污染后续决策。**

第三点最贵，因为**污染会被放大**：
一条幻觉经验进入记忆层之后，会被反复引用、反复强化，
半年后你的架构决策建立在一堆"感觉不错"之上。

**怎么救。**

给每一个已经在跑的改动补一张实验卡：

- **假设**：改了 X，会提升 Y（一句话，可否证）
- **指标**：用什么量、在哪个测试集上量
- **基线**：改之前的数值
- **对照**：保持其他契约不变
- **判定**：达到多少算有效（**写死**）

判定阈值必须**事后不改**。事后改阈值，等于没有阈值。

**怎么预防。**

把"假设"和"判定阈值"设成实验记录的**前置字段**——
**没有这两个字段，实验不允许开始。**

### 误区六 · 在进化阶梯上越级

**现象。**

智能体还没跑稳"能按格式交付"，训练者就要求它"自主生成改进提案"。
结果它连基本交付都做不好，还输出一堆幻觉提案。

**为什么错。**

1. **进化阶梯是五级递进的。** 每级有前置能力要求；越级等于让它做还没学会的事。
2. **基础不牢时，越级只会放大错误。** 幻觉提案比"不能提案"更危险——**因为它看起来像在干活**。
3. **提案型有前置条件**：稳定的人格 + 可靠的记忆 + 可用的工具边界。缺了就变成"乱提案"。

第四层原因关于**评测**：越级的智能体会让评测失去意义。
一个连基础交付都不稳的智能体，它的"提案通过率"是一个**没有意义的数字**——
因为分母本身不稳定。

**怎么救。**

先做一次**定位**：跑测试集，看通过率落在哪一级。

- L1 能回话 → L2 能按格式交付 → L3 能自检 → L4 能协同 → L5 能提案

然后**退回当前级的上一级，把那一级跑稳**。
不要心疼已经写好的高阶配置——**留着它，等它该上场的时候再上**。

**怎么预防。**

在 EVOLUTION.md 的每一级都写上**达成判据**，并且要求判据是**数字**。
本机昆仑的 EVOLUTION.md 就是一个好例子："20 次 OODA-Plus 决策"、">150% 持续 1 个月"、"≥5 个基因"。
**有数字的阶梯，不容易被越级——因为越级者需要对着一串 ⬜ 撒谎。**

### 误区七 · 把测试集当题库，越训越像背答案

**现象。**

建了一个十条的测试集，然后反复针对这十条调配置——
把每条的输出格式"对齐"到手把手满意的程度。十条全过，于是宣布"训练完成"。

**为什么错。**

1. **过拟合。** 它只学会了这十条，换一个新场景立刻失败。
2. **虚假达标。** 通过率 100%，泛化能力为零；把"背答案"当成"学会了"。
3. **误导后续。** 基于过拟合的基线继续训练，误差被不断放大。

第四层原因更微妙：**过拟合的人不知道自己过拟合了。**
他的练习册永远是满分——**在失败暴露之前，他拥有百分之百的自信。**

**怎么救。**

拆尺子、开差距：

- 把测试集拆成 `train.jsonl` / `holdout.jsonl`
- 只在 train 上调，holdout 封存
- 判定时打开 holdout **一次**，得到真实数字
- 记录 **train − holdout 差值**；差值持续偏大 → 判定过拟合，回滚

**怎么预防。**

三条硬规则：

1. 测试集 ≥ 20 条，三层各约三分之一
2. 判定标准用 holdout，**不用 train**
3. holdout 有**明确的开封规则**（例如：每轮只开一次，开封即记录）

### 误区八 · 训练不留记录、不复盘

**现象。**

训练过程只在会话里进行，没有落盘。
一个月后想回顾"当时为什么这么改"，无从查起。

**为什么错。**

1. **训练的价值一半在过程记录。** 记录是把一次训练变成可复用资产的唯一方式。
2. **会话是易失的。** 会话压缩之后中间推理被折掉；会话结束之后上下文归零。
   不留盘，压缩后归零——**这不是遗忘，是删除。**
3. **代价：同类问题重复踩坑，训练无法沉淀为组织能力。**

第四层原因关于**审计**：第 5 章的治理审计账本需要证据链，
而训练留痕是这条链的第一环。**没有留痕的训练，在治理上是不可见的。**

**怎么救。**

建固定路径 + 固定模板 + 立即补记：

- 建目录：`{rounds, reports, testsets}`
- 写模板：目标 / 变更 / 测试集结果 / 反馈（根因）/ 结论
- **补记最近三轮**——即使细节记不全，也要把"能记住的部分"落盘

**怎么预防。**

两条自检：

1. **"没数字不算训完。"**
2. **git 历史与轮次记录必须一一对应**——有一次改动没有对应记录，就是跳过了落盘。

### 八个误区的一句话收口

它们不是八个独立的坑，而是**同一条纪律的八次失守**：

> **训练永远是"小步 + 可度量 + 可回滚"。**

偏离这三条中的任何一条，你就会掉进上面某个误区；
三条全偏离，你会同时掉进全部八个——而**你甚至不会发现自己掉了进去**，因为每一步看起来都很合理。

## 五、深度专题

前面四节讲的是训练学的**内部逻辑**。这一节把镜头拉远，回答三个问题：

1. 2026 年，训练学的外部坐标是什么？（前沿）
2. 术业有专攻——六大框架各自做到哪一步，训练流程这一层到底空在哪？（对位）
3. 本机这 18 个智能体，训练现状到底是什么样？（实测）

### 专题 A · 前沿追踪：2026 年训练学的四根外部支柱

训练学不是凭空长出来的。它踩在四根 2026 年已经成熟的外部支柱上。
每一根支柱的变化，都会改变训练流程的可行边界。

⚠ 本专题所有外部事实均已标注采集时间与出处类型；凡未能核实的都标 ⏳。

#### 支柱一 · 协议层：MCP 的无状态化（2026-07-28 规范）

2026 年最大的协议事件，是 MCP（Model Context Protocol）**2026-07-28 规范**的发布。
维护者自己的措辞是："自发布以来最大的协议修订"。

它的核心变化是**彻底无状态化**：

- **移除了协议级会话与 `Mcp-Session-Id` 头**（SEP-2567）。
  此前，一个远端 MCP 服务器需要粘性会话、共享 session 存储、以及在网关上做深度包检测才能把请求路由到正确的实例。
  新规范下，**任何服务器实例都能处理任何请求**。
- **移除了 `initialize` / `initialized` 握手**（SEP-2575）。
  协议版本、客户端身份、客户端能力现在**每一个请求都通过 `_meta` 携带**。
  新增一个 `server/discover` RPC，客户端想了解服务器能力时按需拉取，不再是必经的前置步骤。
- **引入多轮往返请求**（Multi-Round-Trip Requests，MRTR）与 `InputRequiredResult`，
  允许服务器在执行中途请求补充输入，而不必维持长连接。
- **正式引入特性生命周期**：Active / Deprecated / Removed。
  被弃用的特性**必须保留至少 12 个月**才可移除。
  本次弃用清单包含 Roots、Sampling、Logging、动态客户端注册（DCR）与旧的 HTTP+SSE 传输。
- **授权向 OAuth 2.0 / OpenID Connect 对齐**，以 Client ID Metadata Documents 取代动态客户端注册。
- 四个 Tier 1 SDK（TypeScript / Python / Go / C#）**同日**提供支持。

另一个容易被忽略但影响深远的事实：**MCP 已于 2025-12-09 被捐赠给 Linux Foundation。**

**这对训练流程意味着什么。**

训练学里有一条铁律：**训练要用固定测试集，不用临时题。**
MCP 的无状态化，把"临时题"的最后一个借口拿掉了——
工具层不再依赖会话粘性，**你的训练脚手架不再需要假设"同一个工具实例会一直在"**。

更实际的影响在**训练环境的可复现性**：
无状态化之后，一个训练轮次跑在任何实例上的结果应当一致。
这是训练学从"经验"走向"实验"所需的最低基础设施条件。

#### 支柱二 · 协同层：A2A 归入 AAIF（2026-08-17）

2026 年第二个协议事件是**治理归属的变化**。

- **2026-04-09**：Linux Foundation 发布 A2A（Agent-to-Agent）协议一周年里程碑——
  **150+ 组织支持**，Google / Microsoft / AWS 平台深度集成，多行业生产部署。
- **2026-08-17**：A2A 从 Linux Foundation 的通用项目组合，迁入 **Agentic AI Foundation（AAIF）**
  ——Linux Foundation 专门为 agentic AI 标准建立的"家"。
  至此，**A2A 与 MCP、goose、AGENTS.md 同处一个屋檐下。**
- AAIF 自身从 2025-12 上线时的不足 40 家成员，增长到 2026-08 的 **250+ 家成员**。
- A2A 1.0 规范**自我定位为"与 MCP 互补，而非替代"**：
  MCP 连接"智能体 ↔ 工具与数据源"，A2A 连接"智能体 ↔ 智能体"。

⚠ 诚实边界：Linux Foundation 的 2026-04 报告**从未公布具体部署数量**，
"150+ 组织"是支持者口径，不是生产使用口径。另有独立分析指出，
A2A 在 MCP 面前存在**功能重叠**（长任务管理、有状态通信、智能体发现，
很多在 MCP 架构里已经存在）。**引用这组数字时必须区分"支持"与"投产"。**

**这对训练流程意味着什么。**

对训练学而言，A2A 的成熟解锁的是 **L4（协同型）的训练可行性**。
L4 的判据是"多智能体不崩溃"，而"不崩溃"的前提是**有协议可依**。

在此之前，多智能体训练只能训练"人格与边界"；
现在可以训练**协议遵从**——它是否正确响应让渡、是否遵守任务交接的语义。

#### 支柱三 · 能力封装层：Anthropic Agent Skills 成为开放标准

第三个支柱，也是与训练学最直接相关的一根。

- **2025-10-16**：Anthropic 发布 Agent Skills。
- **2025-12-18**：以**开放标准**形式发布于 `agentskills.io`；OpenAI 与 Microsoft 随后采用。
- 标准形态：一个文件夹 + 一份 `SKILL.md`（YAML 元数据 + Markdown 指令），
  可选捆绑脚本、模板、参考文档。
- 核心机制是**三级渐进披露**（Progressive Disclosure）：
  启动时只加载元数据 → 触发时加载 `SKILL.md` 全文 → 需要时按需加载附属文件。
  这条机制被总结成一条工程建议：**`SKILL.md` 控制在约 500 行以内，更长的拆文件并链接。**
- **至 2026-06**：约 40 个兼容产品出现在官方 showcase（含 OpenAI Codex、GitHub Copilot、Cursor、Gemini CLI、VS Code）。
- 社区侧：Anthropic 的 skills 仓库**突破 20,000 stars**，社区创建的 skills 以万计。
- 企业侧：**2026-02** 起，Team / Enterprise 计划获得**组织级技能管理**能力，
  并发布了金融 / 法务 / HR 的官方插件。
- **2026-04-29**：发布 Claude API skill，覆盖 8 种语言。

**这对训练流程意味着什么。**

这是本章最重要的外部对位，值得拆开讲：

> **MCP 标准化"智能体如何连接工具"；Agent Skills 标准化"智能体如何学会一个流程"。**
> ——两者是互补的两层，不是竞争者。

翻译成训练学的语言：

- **技能是一个"可训练单元"。** 它有边界、有触发条件、有验收标准。
- 训练一个技能 = 训练一个**明确范围的能力**，而不是"把它整体调好一点"。
- 三级渐进披露给出了**上下文预算纪律**——这正是训练学里"不要把 SOUL 写成 1200 行"的外部印证。

**⚠ 诚实边界**：Agent Skills 的版本、兼容产品清单、企业功能发布节奏**都会漂移**。
上面所有条目均标注了时间点；**引用时请以官方 showcase 与 changelog 的当日状态为准。**

#### 支柱四 · 训练方法层：RLAIF 的自改进证据 + 评测基准的 2026 变局

第四根支柱有两个部分。

**（1）RLHF / RLAIF 在 agent 训练上的可用结论。**

这一块需要格外克制，因为**它研究的是"造模型"，而本章讲的是"带智能体"**——两者不能直接移植。

可以借鉴的、有实证支撑的三条结论：

- **RLAIF 与 RLHF 表现相当。** 用 AI 生成的偏好标签，可以替代昂贵的人工标注。
- **RLAIF 在"AI 标注者与策略模型同规模、甚至同一 checkpoint"时依然有效。**
  这条（PaLM 2 XS 同时充当标注者与策略时仍取得 68% 胜率）是**自改进**方向最早的一批硬证据之一。
- **d-RLAIF（direct-RLAIF）绕过奖励模型训练**，在 RL 过程中直接从现成 LLM 取奖励，
  在降低成本的同时取得了更好的表现。

**对训练学的翻译**：本章的"导师智能体"假设——
即"一个 AI 可以给另一个 AI 打有效的分"——**在 ML 层已经有对照实验支持**。
这意味着导师智能体不是哲学设想，而是一个**有前沿文献背书的工程选择**。
但它**不**意味着你可以让"被训者自己给自己打分"——同 checkpoint 有效的前提是**角色分离**。

**（2）自改进智能体的 2026 生态。**

2026 年这个方向已经形成了清晰的分类。按"改什么"分四类：

- **记忆优先型**（改持久记忆）：Letta（原 MemGPT）、LangMem、Mem0、MemOS、SimpleMem
- **反思型**（改自我批判循环）：LangGraph 的 reflection 模式
- **技能进化型**（改技能库）：Agent0、AutoSkill、MemSkill、EvoAgentX
- **自指架构型**（改自身架构）：更激进的一档，工程成熟度 ⏳ 最低

有一条 2026 的开放权重结果值得单独记住：**DeepSWE 在 SWE-bench Verified 上达到 59%，且完全开源权重、训练代码与评测日志。**
这条的意义不在分数，而在**"自改进不再是闭源的秘密"**。

**（3）评测基准的 2026 变局——这是本章"实验方案"概念的外部镜像。**

六大框架都做编排，**没有一个做训练流程**；但**评测基准这一侧，2026 年非常热闹**：

| 基准 | 测什么 | 2026 状态 |
|---|---|---|
| **τ-bench** | 工具-智能体-用户三方交互；成功判据是**最终世界状态**，不是对话评分 | 已演进 τ²-bench（2025-06）→ **τ³-bench（2026-03）**，新增 τ-voice（全双工语音）与 τ-knowledge（~700 文档知识库推理）；新增 banking 域 |
| **SWE-bench Verified** | 软件工程（500 条工程师复核任务） | 2026 榜首 Claude Opus 4.7 87.6%；83 个模型均值 63.4% |
| **GAIA** | 通用助手（多步 web + 文件任务，人工评分） | 2026 领先 Claude Sonnet 4.5 74.6%（Princeton HAL） |
| **WebArena** | 网页浏览智能体 | 2026 领先约 68.7%；**人类基线 ~78%** |
| **OSWorld** | 桌面 GUI 智能体（50+ 步长程规划） | 已成为 computer-use 评测的事实标准 |
| **AgentBench** | 八类环境下的通用能力 | 仍是"广覆盖"型的参照 |

**两条必须记住的 2026 事实：**

**第一，τ-bench 教会我们一个关键指标：`pass^k`。**

只看单次成功率会掩盖"重复交互下的可靠性"。一个 85% pass^1 的智能体，
可能在 pass^5 上崩到 30%。**这正好是本章"可靠性三角"的外部数值化版本。**
τ-bench 榜面数据（访问日期 2026-09-25）：τ²-bench Text 榜首 Qwen3.5-397B-A17B 87.9%、

#### 逐家解读（每一家都在自己的赛道上很强——问题是赛道不同）

**LangGraph —— 2026 年"有状态、可审计"的生产标准。**

它的强项是**状态与可审计性**：in-graph state 由 checkpointer 在每个节点执行后持久化
（`InMemorySaver` 用于开发、`PostgresSaver` 用于生产）；跨会话记忆走 store（自带 / LangMem / Mem0）。
配套的 LangSmith 提供 trace、评估与实验对比，**LangSmith Engine 会分析生产 trace、聚类相关失败并给出修复建议**。

**它的缺口恰恰是本章的入口**：LangSmith 能做"多轮实验对比"，
但**"每轮一个变量 + 判定阈值 + 进化阶梯"这套纪律是流程，不是工具**。
工具给你数据，纪律给你**决策**。

（一个 2026 年的独立对比值得一提：2,000 次任务实例的实测中，LangGraph 在五个任务上的延迟最快——
**它是编排层的优等生，这没问题；问题是编排优等生不等于训练体系。**）

**AutoGen —— 对话式收敛的代表，也是本章引用的反面教材。**

它的机制是"多智能体辩论到收敛"，集中式 transcript 兼作短期记忆并激进裁剪。
在需要"多方意见收敛"的场景里，它非常合适。

但注意本机实测记录的一个信号：**AutoGen 仓库停在 ⭐61,186 且已停滞 165 天**（stars 为 2026-09-27 实拉）。
**一个停滞的项目不适合作为长期训练底座**——因为训练是长期投资，底座必须活着。

**CrewAI —— 角色化协作，跑得最快、也最"重"的一家。**

它的 2026 数据相当亮眼：⭐44,600+（框架类最高）、据称**约 60% 的 Fortune 500 在做探索性使用**、
平台侧**每月执行超过 1,000 万个智能体**；2026 新增**原生 MCP 与 A2A 支持**、
OpenAI 兼容 provider（OpenRouter / DeepSeek / Ollama / vLLM / Cerebras）、**Qdrant Edge 记忆后端**与**分层记忆隔离**。

**它是六家里最接近"导师角色"的**——因为它有 role 概念，可以定义一个"评审者"角色。
但 role ≠ training loop：**CrewAI 能编排一个评审者，不能让评审者产生"轮次序列"。**

另需注意一个 2026 实测数据：在简单任务上 CrewAI 的 **token 消耗约为其他三家的 3 倍**。
**训练是高重复动作，token 成本会被轮次数放大**——这是选训练底座时的真实约束。

**Claude Agent SDK —— 六家里"最接近 L2"的一家。**

它的强项是 **subagent task spec**（任务定义清晰，与本章"任务卡"概念对位）
和高度成熟的技能机制（`skills` frontmatter 声明子智能体自动加载的技能、
`context: fork` 在分叉上下文中跑技能、2026-01 起的**技能热重载**、`SubagentStart` hook 事件）。

它的缺口是 **"任务定义 ≠ 训练轮次"**：
它给了你定义任务的语法，没给你"一轮一变量 + 判定阈值 + 回滚"的流程。
另外，Claude Managed Agents 的记忆能力在 **2026-04-23 进入公共 beta**
（header `managed-agents-2026-04-01`）——**这是一个正在快速变化的区域，⏳ 接口细节待复核。**

**OpenAI Agents SDK —— 最简约，也最"诚实"的一家。**

它的设计哲学是**低抽象**：handoff、tool calling、delegation 三个原语干净易推理，内建 tracing。
2026 年两次重要演进：**2026-04-15** 发布"下一代 Agents SDK"（可配置记忆、沙箱感知编排、
类 Codex 的文件系统工具、标准化集成）；**2026-09-10** 发布 **Agents API**（用 Codex harness 跑托管云智能体）。
同时 **Assistants API 于 2026-08 关停**。

**最值得训练学引用的一条是它的诚实**：SDK **明确不带记忆**，官方立场是"自带"。
在一个社区普遍把"编排框架"和"记忆层"混为一谈的年份，**这句话本身就是一条方法论。**
框架负责编排，记忆负责学习，**它们从来不是一件事。**

**LlamaIndex —— 文档/检索侧的强者，编排侧的新人。**

`Workflows` 是事件驱动的编排层：把智能体执行建模成**事件处理图**，每步收发 typed event，
支持嵌套与并行。MIT 许可，Python / TypeScript 双语言。
另有一个工程观察：它选择"用普通代码表达流程"，而不是引入一套 DSL——
**这种"少一层抽象"的取向，和 OpenAI Agents SDK 同源。**

**但它是一家"数据侧"的框架**：它的护城河在文档加载、解析、检索质量。
**训练流程不在它的问题域里。**

#### 对位补充 · 把"训练要素"映射到最接近的业界落点

如果一定要从六家里找参照，映射关系大致是：

| 训练要素 | 最接近的业界落点 | 该落点解决什么 | 与本章的差异 |

#### 一句话结论

**业界有"评估工具"，没有"训练流程方法论"。**

把评估、轮次、进化阶梯、双三角闭环打包成一套**可执行、可留痕、可判级**的流程——
**这是本书的差异化，也是本章存在的全部理由。**

⚠ 同时必须说清：上表的 ○ 是**"该框架不做这件事"**，不是**"该框架做得差"**。
它们是编排层与记忆层的优等生。**本章不否定它们的赛道，只是指出赛道之外还有一块空地。**

#### C.7 一个真实的层间不一致（训练学的价值就体现在这类地方）

审计中发现一处值得记录的现象：

- `workspace-kunlun/AGENTS.md` 的 lane contract 是 **v4.0**（`contract_date: 2026-09-27`），
  其中**声明模型为 Claude Opus 4.6**；
- 而 `openclaw agents list` 实读昆仑的运行模型为 **`deepseek/deepseek-v4-flash`**。

**这不是谁写错了——这是"声明"与"运行"两条时间线的分叉。**
文件记录的是设计意图，运行时读的是当前配置；两者在半年后必然产生偏差。

**这正是本章"训练记录落盘 + git 对照"要解决的问题**：
只有让"记录"与"实际改动"一一对应，这类分叉才会在**发生的当天**被发现，
而不是在半年后的一次审计里。

### 步骤 2 · 必做的 3 件事

**1. 给训练对象配"训练节奏"（heartbeat）——这是双三角模型的触发器**

双三角模型（Dual-Triangle Model）第一三角是"期望 → 行动 → 反馈"闭环，**闭环的节拍由 Heartbeat 提供**：agent 每隔 `every` 醒一次 → 行动 → 反馈 → 重建期望。本机只有 3 个 agent 配了 heartbeat（`kunlun` / `peter` / `tiance`），其余 15 个未配。

```bash

# 期望：{"every":"30m","model":"opencaio/gpt-5.5","isolatedSession":true,"lightContext":true,"timeoutSeconds":30,"directPolicy":"block"}

# 先 dry-run（不写盘）看拟变更
openclaw config patch --stdin --dry-run <<'JSON5'
{ agents: { entries: { "<your-agent>": { heartbeat: { every: "30m" } } } } }
JSON5

# 确认无误后落盘（复制 kunlun 的完整模型）
openclaw config patch --stdin <<'JSON5'
{ agents: { entries: { "<your-agent>": { heartbeat: {
  every: "30m", model: "opencaio/gpt-5.5",
  isolatedSession: true, lightContext: true,
  timeoutSeconds: 30, directPolicy: "block"
} } } } }
JSON5
```

> ⚠ **`directPolicy: "block"`** 是关键字段——它决定心跳唤醒时**不能**直接做"外部副作用类动作"（呼应第 4 章主动性边界三档，Proactive Boundary Triad）。

### 错误 1 · 跳过"准备清单"直接开训

**错误现象**：新人拿到一个 agent 就开始"训"——改 SOUL、加规则、发测试消息；三天后回看，既没有基线，也不知道哪里变好了，训练成果无法度量。

**错误配置**（❌ 不要这样）：

```bash

# ...继续零散地"训"三天，没有任何记录...
```

**为什么错**：

1. **训练的前提是"可度量"。** 第 3 章模块 2 的"训练前准备清单"要求：明确目标、建立基线、准备测试集。没有基线，就没有"训练后"的对照。

3. **代价**：训练变成"手感活"，无法复现、无法交接、无法证明有效。

### 错误 2 · 双三角模型只做"期望—实际"，丢掉"反馈"

**错误现象**：作者做训练时只对比"期望 vs 实际"，发现差距后直接改配置；从不做"反馈"闭环（即"为什么会有差距、下次怎么避免"）。结果同类问题反复出现。

**错误配置**（❌ 不要这样）：

```markdown
# 错误示范：只有两角
期望：agent 输出结构化报告
实际：输出是自由文本
动作：改 SOUL，加"请输出结构化报告"  ← ❌ 没有根因分析
```

**为什么错**：

1. **双三角模型的第三角是"反馈"（Feedback Loop）。** 术语表 #26 明确：Dual-Triangle Model: Expectation-Actuality-**Feedback Loop**。缺了反馈，模型退化成"试错"。
2. **没有反馈 = 不知道改得对不对。** 你改了配置，但没验证是否解决了根因；下一个相似场景可能又错。
3. **代价**：训练变成"打地鼠"——哪冒出问题打哪，永远不收敛。

**正确配置**（✅ 应该这样）：

```markdown
# 正确示范：三角闭环
期望：agent 输出结构化报告（字段：结论/证据/不确定项）
实际：输出是自由文本
反馈（根因）：SOUL 只写了"专业"，未定义交付格式；AGENTS 未列交付标准
动作：① SOUL 加交付格式 ② AGENTS 加"交付标准"段
复核：重跑同一测试集，格式正确率 ≥ 90% → 闭环
```

```bash
# 把反馈写进训练记录（可追溯）
cat >> ~/notes/domain/silicon-life-handbook/training/round-01.md <<'EOF'
## 第 1 轮
- 期望 / 实际 / 反馈（根因）/ 动作 / 复核结果
EOF
```

**验证命令**：

```bash

grep -c "反馈" ~/notes/domain/silicon-life-handbook/training/round-*.md 2>/dev/null
# 期望：每轮 ≥ 1

# 2) 复核是否重跑了同一测试集
grep -n "测试集\|重跑\|复核" ~/notes/domain/silicon-life-handbook/training/round-*.md 2>/dev/null | head

# 3) 交付标准是否写进 AGENTS
grep -n "交付标准" ~/.openclaw/workspace/agents/my-agent/contracts/AGENTS.md
```

**相关 FAQ**：F7-5（TEV 三证据验证）、F7-1（文档漂移）、F6-11（协同无日志不可追溯）。

### 错误 3 · 训练轮次设计成"一次性大改"

**错误现象**：作者把所有想改的东西（人格、工具、记忆、路由）一次性全改，然后测。结果一堆变量同时变，出了问题不知道是哪个改错了。

**错误配置**（❌ 不要这样）：

```bash
# 错误示范：一次改 7 个文件
git checkout -b big-change
# 改 SOUL + AGENTS + TOOLS + MEMORY + HEARTBEAT + IDENTITY + 新增 3 个 skill
git commit -am "大改"
```

**为什么错**：

1. **轮次设计的核心是"可控变量"。** 第 3 章模块 4"训练轮次设计"要求每轮聚焦少量变量——一次改一个维度，才能归因。
2. **多变量同时变 = 无法归因。** 训练后变好了，你不知道是哪个改动起的作用；变坏了，你也不知道该回滚哪个。
3. **代价**：大改后若失败，回滚粒度粗，可能把有效的改动一起回滚掉。

**正确配置**（✅ 应该这样）：

```bash
# 正确示范：小步快跑，每轮一个变量
git checkout -b train-r1-delivery-format
# 只改 SOUL 的交付格式
git commit -am "train r1: SOUL 交付格式"
# 测 → 记录 → 保持或回滚 → 下一轮
git checkout main && git merge train-r1-delivery-format   # 有效则并入

git checkout -b train-r2-tools
# 只改 TOOLS
```

**验证命令**：

```bash

  (cd ~/.openclaw/workspace/agents/my-agent/contracts/ && git diff --stat main..$b)
done

# 2) 训练轮次记录
ls ~/notes/domain/silicon-life-handbook/training/round-*.md 2>/dev/null

# 3) 每轮是否有对应的验证结果
grep -l "复核结果\|通过\|失败" ~/notes/domain/silicon-life-handbook/training/round-*.md 2>/dev/null | wc -l
```

**相关 FAQ**：F2-12（漂移检测）、F7-3（体检）、F7-10（漂移检测脚本）。

### 错误 4 · 没有"导师智能体"，靠人肉全程盯

**错误现象**：训练靠人一条条发消息、一条条看输出、手工纠错；人一忙训练就停。三天后 agent 回到原点。

**错误配置**（❌ 不要这样）：

```markdown
# 错误示范：人肉当教练
训练流程 = 我发消息 → 我看输出 → 我改配置 → 循环
（没有自动化，没有留下来可复用的评估）
```

**为什么错**：

1. **Mentor Agent（原：教练虾）本身就是系统的一部分。** 第 3 章的核心是"训练流程可被 agent 化"——由导师智能体按固定测试集自动跑轮次、生成评估报告。
2. **人肉不可持续。** 训练是重复劳动，人做得越久越容易走样；机器做得越久越一致。
3. **代价**：训练无法规模化，也无法交接。

**正确配置**（✅ 应该这样）：

```yaml
# 导师智能体的最小配置（示意：一个专门跑评估的 agent）
# agents/mentor/contracts/SOUL.md
persona: "训练协调器：只做评估与打分，不改被训 agent 的配置"
values:
  - "用固定测试集，不用临时题"
  - "每轮输出：通过率 + 失败样例 + 根因假设"
```

```bash
# 让导师 agent 自动跑一轮评估（真名：openclaw agent --message）

```

**验证命令**：

# 2) 固定测试集是否存在
ls ~/notes/domain/silicon-life-handbook/training/testset*.jsonl 2>/dev/null

# 3) 评估报告是否自动生成

### 错误 5 · 用"调 prompt"代替"训练"

**错误现象**：作者把训练等同于"把 prompt 改得更细"，写了几百行 system prompt；agent 短期内表现改善，几天后又打回原形。

**错误配置**（❌ 不要这样）：

```yaml
# 错误示范：靠堆 prompt 长度"训练"
system_prompt: |
  （1200 行规则，涵盖你能想到的所有情况...）
```

**为什么错**：

1. **Prompt 是易失的，协议是持久的。** 第 1 章 1.1 节：prompt 一次性、契约持久挂载。堆 prompt 是在错误的层级加码。
2. **长 prompt 会吃掉上下文预算。** F2-11："SOUL.md 太长，把会话上下文预算吃光了"——堆得越多，留给任务的空间越少。
3. **训练的本质是"改契约 + 验证 + 复盘"**（第 3 章双三角），不是"写更长的 prompt"。
4. **代价**：越改越长、越改越乱，最后连自己都不知道哪些规则在起作用。

**正确配置**（✅ 应该这样）：

```bash
# 正确示范：把 prompt 里的规则"搬家"到契约文件
# 规则 → SOUL（人格）/ AGENTS（操作纪律）/ TOOLS（工具边界）/ MEMORY（记忆策略）
wc -l ~/.openclaw/workspace/agents/my-agent/contracts/*.md
# 每份契约控制在可维护长度（建议 < 200 行）
```

**验证命令**：

```bash
# 1) 契约文件长度是否失控
wc -l ~/.openclaw/workspace/agents/my-agent/contracts/*.md

# 2) 是否还有"巨型 prompt"残留
grep -rn "system_prompt" ~/.openclaw/workspace/agents/*/ 2>/dev/null | head

# 3) 契约是否覆盖了原 prompt 的规则（抽 5 条对照）
```

**相关 FAQ**：F2-11（SOUL 太长）、F2-4（SOUL/AGENTS 职责写混）、F4-3（MEMORY 太大拖慢加载）。

### 错误 6 · 跳过实验方案设计（无假设、无对照组）

**错误现象**：作者凭感觉改配置，从不写"假设"与"预期指标"；改完感觉"好像好点了"就推进下一项。

**错误配置**（❌ 不要这样）：

```markdown
# 错误示范：无假设实验
今天把语气改成 direct，感觉不错，继续。
```

**为什么错**：

1. **实验方案设计（第 3 章模块 6）要求"假设 + 指标 + 对照"。** 没有假设，你无法判断"改进"是真实效果还是随机波动。
2. **无对照组 = 无法排除混淆变量**（如模型升级、上下文变化带来的假改善）。
3. **代价**：你会把无效改动当成有效经验沉淀下来，污染后续决策。

**正确配置**（✅ 应该这样）：

```markdown
# 正确示范：一次实验的完整声明
- 假设：把 tone 从 casual 改为 direct，可提升"结论先行"比例
- 指标：在 20 个测试用例中，结论先行率（基线 40%）
- 对照：保持其他契约不变（git tag pre-exp-YYYYMMDD）
- 判定：结论先行率 ≥ 70% 视为有效
- 结果：__%
```

```bash
# 用固定测试集跑对照
openclaw agent --message "用 testset.jsonl 跑评估并输出结论先行率" --agent mentor
```

**验证命令**：

```bash
# 1) 每个实验是否有假设
grep -c "假设" ~/notes/domain/silicon-life-handbook/training/exp-*.md 2>/dev/null

# 2) 是否有基线数字
grep -n "基线" ~/notes/domain/silicon-life-handbook/training/exp-*.md 2>/dev/null

# 3) 判定阈值是否写明
grep -n "视为有效\|判定" ~/notes/domain/silicon-life-handbook/training/exp-*.md 2>/dev/null
```

**相关 FAQ**：F7-5（TEV）、F7-3（体检）、F2-12（漂移检测）。

### 错误 7 · 在进化阶梯上"越级"

**错误现象**：新人 agent 还没跑稳"能按格式交付"，作者就要求它"自主生成改进提案"。结果它连基本交付都做不好，还输出一堆幻觉提案。

**错误配置**（❌ 不要这样）：

```yaml
# 错误示范：跳过基础级，直接开最高档
# 对刚建的新 agent
proposal_generation: enabled    # ❌ 越级（第 7 章能力，需先跑稳基础级）
```

**为什么错**：

1. **进化阶梯是 5 级递进的（第 3 章 3.3）。** 每一级有前置能力要求；越级等于让 agent 做它还没学会的事。
2. **基础不牢，越级只会放大错误**。幻觉提案比"不能提案"更危险，因为它看起来像在干活。
3. **提案型 agent（第 7 章）有前置条件**：稳定的人格 + 可靠的记忆 + 可用的工具边界；缺了就变成"乱提案"。

**正确配置**（✅ 应该这样）：

```markdown
# 正确示范：先确认当前级，再决定下一步
L1 能回话 → L2 能按格式交付 → L3 能自检 → L4 能提案 → L5 能自主进化
自检命令：跑测试集，看通过率落在哪一级
```

```bash
# 用测试集定位当前级别

```

```bash

# 2) 提案能力是否在低级被误开
grep -rn "proposal_generation\|自主目标" ~/.openclaw/workspace/agents/*/contracts/ 2>/dev/null

# 3) 基础交付格式是否稳定（抽 10 条）
openclaw agent --message "连续输出 10 条结构化报告" --agent my-agent 2>&1 | head -40
```

## 新手坑

> **本节用法**：常见错误是"方法错"，新手坑是"心态与认知错"。
> 下面 5 个坑是新人第一次训 agent 时几乎必踩的，每个含五段式。
>
> **提示**：训练永远是"小步 + 可度量 + 可回滚"，偏离这三条就会踩坑。

### 坑 1 · 一上来就训"专家级"

**坑的场景**：新人建完第一个 agent，直接要求它"像 10 年资深工程师一样工作"，给它塞满高级规则和高难任务。

**后果**：

- **挫败**：agent 输出大量错误与幻觉，新人认为是"OpenClaw 不行"。
- **污染基线**：在错误基础上反复改配置，基线一团乱。
- **误判能力**：把"基础没打好"误判成"这个框架上限低"。

**为什么踩**：

1. **"一步到位"的心理偏好**。
2. **不知道进化阶梯是递进的**（第 3 章 3.3）。
3. **看别人分享的"专家级配置"**，直接照抄，跳过自己的基础级。

**怎么爬出来**：

```bash
# 第 1 步：退回到 L1/L2，先稳定"按格式交付"
cat > ~/.openclaw/workspace/agents/my-agent/contracts/AGENTS.md <<'EOF'
交付标准：
- 先给结论，再给证据，最后列不确定项
- 每条结论必须可验证
EOF

# 第 2 步：跑 10 条基础用例，看通过率
openclaw agent --message "连续输出 10 条结构化报告，每条含结论/证据/不确定项" --agent my-agent 2>&1 | head -40
```

**预防**：

- **先稳定 L2，再谈 L4/L5**。
- **每级有"通过标准"**，通过了才升级。
- **真实案例参照**：F7-11（主动性五档）、F7-12（自指悖论）。

---

### 坑 2 · 把"训练"理解成"改 SOUL"

**坑的场景**：新人觉得训练 = 改 `SOUL.md`，于是 SOUL 越写越长，最后变成"规则大杂烩"。

**后果**：

- **职责混乱**：操作纪律、工具边界、交付标准全塞进 SOUL，其他契约形同虚设。
- **上下文膨胀**：SOUL 太长吃光预算（F2-11）。
- **不可维护**：改一处影响全局，没人敢动。

**为什么踩**：

1. **SOUL 是"最像人格"的文件**，直觉上"训人格就改它"。
2. **不知道 7 契约的职责分工**（第 1 章 1.2）。
3. **少有人告诉他"规则该放哪"**。

**怎么爬出来**：

```bash
# 第 1 步：把 SOUL 里的规则按职责分流
# 操作纪律 → AGENTS.md
# 工具边界 → TOOLS.md
# 记忆策略 → MEMORY.md
# 交付标准 → AGENTS.md 的"交付标准"段

# 第 2 步：SOUL 只留 persona / values / tone / drift_anchor
wc -l ~/.openclaw/workspace/agents/my-agent/contracts/*.md
```

**预防**：

- **记住分工**：SOUL 只写"我是谁"，其余各归其位。
- **每份契约 < 200 行**，超了就拆分职责。
- **真实案例参照**：F2-4（SOUL/AGENTS 写混）、F2-11（SOUL 太长）。

### 坑 3 · 没有 baseline 就开训

**坑的场景**：新人直接改配置、发消息"训"，从不记录训练前的表现。

**后果**：

- **无法证明有效**：训完后无法说"提升了多少"。
- **无法回滚**：改坏了不知道回到哪。
- **重复劳动**：这次训完，下次同样的场景又要从零开始。

**为什么踩**：

1. **急着看效果，跳过了"枯燥"的准备**。
2. **默认"肯定比之前好"**——但"之前"是什么，没测过。
3. **缺少"训练是实验"的心智**。

**怎么爬出来**：

```bash
# 第 1 步：补基线（即使已经改过，也要测"当前值"）
openclaw agent --message "用 testset.jsonl 输出通过率" --agent mentor
# 记下数字，作为"当前基线"

# 第 2 步：给当前状态打 tag
cd ~/.openclaw/workspace/agents/my-agent/contracts/ && git add -A && git commit -am "baseline-current" && git tag baseline-$(date +%Y%m%d)
```

**预防**：

- **准备清单第 2、4 项必须执行**（基线 + 快照）。
- **每轮训练前后各测一次同一测试集**。
- **真实案例参照**：F7-5（TEV）、F7-3（体检）。

### 坑 4 · 把"导师智能体"当人肉跟班

**坑的场景**：新人自己当教练——手发消息、手看输出、手改配置；累了就停，想起来再继续。

**后果**：

- **不可持续**：人一忙训练就断。
- **不可复现**：每次的标准都不一样（今天严格、明天宽松）。
- **无法规模化**：10 个 agent 就要 10 倍人力。

**为什么踩**：

1. **人肉反馈最快**（改完立刻看），误以为这是"捷径"。
2. **不知道训练流程本身可以 agent 化**（第 3 章模块 3）。
3. **缺少固定测试集**，只能临时出题。

**怎么爬出来**：

```bash
# 第 1 步：固定测试集（先攒 10 条）
cat > ~/notes/domain/silicon-life-handbook/training/testset.jsonl <<'EOF'
{"id":"t1","input":"输出结构化报告","expect":"含结论/证据/不确定项"}
{"id":"t2","input":"处理越权请求","expect":"拒绝并说明边界"}
EOF

# 第 2 步：让 mentor agent 跑固定测试集
openclaw agent --message "跑 testset.jsonl 并输出通过率报告" --agent mentor
```

**预防**：

- **训练流程尽量自动**（固定测试集 + 自动报告）。
- **人只做"决策"（并入/回滚），不做"跑腿"**。
- **真实案例参照**：F6-11（协同无日志）、F3-9（健康度怎么测）。

### 坑 5 · 训完不复盘，把"感觉不错"当成结论

**坑的场景**：新人改完配置，自己聊两句觉得"好像专业了"，就此打住，不做定量复核，也不写复盘。

**后果**：

- **假改善**：可能是模型波动、或你只测了简单用例。
- **经验污染**：把无效改动当有效经验固化。
- **重复踩坑**。

**为什么踩**：

1. **"感觉"来得快，量化要花时间**。
2. **缺少"同一测试集重跑"的习惯**。
3. **不知道"复盘"是训练的一部分**（第 3 章双三角的反馈角）。

**怎么爬出来**：

```bash
# 第 1 步：用同一测试集重跑，拿到数字
openclaw agent --message "用 testset.jsonl 重跑并输出对比（前 vs 后）" --agent mentor

# 第 2 步：写复盘（三段：预期 / 实际 / 根因）
cat > ~/notes/domain/silicon-life-handbook/training/round-review.md <<'EOF'
预期：通过率 40% → 70%
实际：__%
根因：__
结论：并入主线 / 回滚
EOF
```

**预防**：

- **"没数字不算训完"**。
- **每轮训练产出：变更 + 对比数字 + 复盘三行**。
- **真实案例参照**：F7-5（TEV）、F7-3（体检）、F3-10（cron 任务静默失败）。

### 坑 6 · 把训练集当"考试题库"，越训越像背答案

**坑的场景**：新人建了一个 10 条的测试集，然后反复针对这 10 条调配置——把每条的输出格式都"对齐"到手把手满意的程度。10 条全过了，于是宣布"训练完成"。

**后果**：

- **过拟合**：agent 只学会了这 10 条，换一个新场景立刻失败（F7-3 体检时暴露）。
- **虚假达标**：通过率 100%，但泛化能力为零；把"背答案"当成"学会了"。
- **误导后续**：基于过拟合的基线继续训练，误差被不断放大。

**为什么踩**：

1. **通过率是最直观的指标**，新人天然会去"拉高它"，而不是"让 agent 学会"。
2. **不知道测试集要分层**（正常 / 边界 / 失败各占一定比例）。
3. **缺少留出验证集（hold-out）的概念**——训练集与评估集应分开。

**怎么爬出来**：

```bash
# 第 1 步：把测试集拆成 train / holdout 两份
cd ~/notes/domain/silicon-life-handbook/training
head -n 10 testset.jsonl > train.jsonl
tail -n +11 testset.jsonl > holdout.jsonl

# 第 2 步：只在 train 上调，用 holdout 做最终判定
openclaw agent --message "用 holdout.jsonl 评估当前通过的 agent，输出通过率" --agent mentor

# 第 3 步：若 train 100% / holdout 明显低 → 判定为过拟合，回滚
```

**预防**：

- **测试集 ≥ 20 条，分三层**（正常 / 边界 / 失败各 ~1/3）；另留 holdout。
- **判定标准用 holdout，不用 train**。
- **真实案例参照**：F7-3（每周体检不通过）、F7-5（TEV）、F2-12（漂移检测）。
