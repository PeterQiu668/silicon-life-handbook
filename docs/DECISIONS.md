# 关键决策

## D-2026-09-30-01 · 不再把资料库目录等同于一本书

- 决定：采用“出版主稿 + 深度参考层 + 操作附录层”的三层结构。
- 原因：现有 87 个文件同时包含正文、API、FAQ、SOP、案例、备份、脚本和编辑日志，无法形成稳定阅读主线。
- 影响：正式书目由 `BOOK-MANIFEST.yaml` 定义；文件存在不等于进入出版物。

## D-2026-09-30-02 · 人类与 Agent 使用不同入口

- 决定：人类从连续主稿进入，Agent 从 `AGENT-ENTRY.md` 进入并按需加载。
- 原因：人的阅读需要叙事连续，Agent 的上下文需要渐进披露。
- 影响：不再要求任何 Agent 一次性读取全书与全部附录。

## D-2026-09-30-03 · 固定稳定版，不拿前沿 tag 当已发布能力

- 决定：RC1 固定 OpenClaw 2026.9.6 / `eb377ac`；v2026.9.7 仅进入前沿观察。
- 原因：复核时本机、npm latest 与 GitHub latest release 均为 2026.9.6，而 9.7 只有 tag 信号。
- 影响：版本事实集中在 `SOURCES.md`，深度层旧口径逐步迁移。

## D-2026-09-30-04 · “行业最强”改为可测毕业标准

- 决定：不发表“训练后一定行业最强”的保证；用质量、泛化、安全、稳定、效率、协作和可治理性七维指标定义相对强度。
- 原因：绝对保证无法证伪，会伤害可信度并诱导忽略风险与资源预算。
- 影响：任何领先主张必须带同任务、同预算、同风险边界下的实证结果。

## D-2026-09-30-05 · 人格契约不替代系统权限

- 决定：正文明确分离契约层与执行层。
- 原因：OpenClaw 官方安全模型把模型视为不可信主体，安全边界来自认证、策略、审批、沙箱和隔离。
- 影响：主动性默认落在“发现与提案”，高风险执行必须依赖系统授权。

## D-2026-09-30-06 · 暂不替作者决定整书许可

- 决定：OpenClaw 上游代码的 MIT 与本手册原创文本的许可分开陈述。
- 原因：上游许可不会自动为作者原创手稿选择许可。
- 影响：正式出版前由作者和出版/法律顾问确认版权、引用和再许可方案。

## D-2026-09-30-07 · RC1 降级为候选内容底稿，重建正式出版版母架构

- 决定：不直接将现有出版主稿作为正式上线版；先以 8 卷、24 章、178 个正文三级节点的三级目录重建全书。
- 原因：现稿已覆盖大量前沿内容，但阅读主线、章际依赖和方法论与版本实现的分层仍不够稳定。
- 影响：RC1 与旧深度章节全部保留为取材库；新框架经作者确认后才启动多 Agent 分章生产。

## D-2026-09-30-08 · 出版版采用原理、工程与实现三层结构

- 决定：正文以跨框架方法论与通用工程实践为主；OpenClaw、MCP、A2A 和 Agent Skills 作为带版本的实现参考。
- 原因：出版物的核心认知需要经受版本变化，而操作命令、参数和协议细节必须能单独更新。
- 影响：书中实现细节须标注固定版本、核验日期和来源；版本过期不应推翻整书方法论。

## D-2026-09-30-09 · 硅基仿生成为贯穿全书的解释系统

- 决定：每章固定设置“人类现象—工程映射—训练启示—比喻边界”，不把仿生内容限制在总论。
- 原因：这是初版最有辨识度的原创资产，也能帮助管理者、训练者与工程者共享同一理解框架。
- 影响：任何仿生解释都不得被用作意识、人格权或真正生命属性的证据；工程事实与系统边界必须紧邻类比出现。

## D-2026-09-30-10 · 一个原理、三个实现镜面

- 决定：OpenClaw 是主实现，Hermes 是第二开放实现，Muse 是托管式产品、安全与审批案例。
- 原因：三者共享大量训练与治理原则，但开放程度、控制面、状态、权限和证据可见性不同。
- 影响：正文不设置三个重复的产品百科章；OpenClaw 与 Hermes 可以做工程对照，Muse 只写公开可观察能力与带边界的厂商声明。

## D-2026-09-30-11 · 正式书稿采用章节生产包与五道门禁

- 决定：24 章一章一生产包，包含正文、证据账本、产物、练习和审校记录；未通过写作、事实、实战、交叉和总编门不得并入合订稿。
- 原因：大型多 Agent 写作的主要风险是事实漂移、概念冲突、文风分裂和“看似完整、无法执行”。
- 影响：章节作者不能自我批准；全书 manifest 只收录达到 release candidate 的章节。

## D-2026-09-30-12 · 统一工作书名与对外说明

- 决定：当前统一使用《训虾手册：硅基生命训练学》，副标题为“AI Agent 训练与人机协同最佳实践指南”。
- 原因：主标题保留社区辨识度和原创学科主张，副标题向专业出版和非 OpenClaw 读者解释实际内容。
- 影响：这是生产阶段工作书名；出版社选题、商标和市场复核后仍可润色，但不改变八卷二十四章知识结构。

## D-2026-09-30-13 · 正式 v2 目录决定章节必交产物

- 决定：章节卡中的 `required_artifacts` 必须与 `00-正式出版版-三级内容框架-v2.md` 的“主要产物”一致；章节卡只补充验收细节，不得另行增加冲突的必交编号。
- 原因：C01 证据审校发现 v2 要求两件产物，而早期章节卡仍沿用三件旧拆分，导致 P0-01、P0-12、P0-14 无法裁决。
- 影响：C01—C06 章节卡已按 v2 统一；后续派工前均以 v2 产物编号为唯一契约。四个根问题、三系统、MAT-L0—MAT-L5、三证、JTBD、版本记录和信任边界等内容可以作为现有产物中的必填字段，不为凑数量另造文件。

## D-2026-09-30-14 · 七大生命契约是语义系统，不是七文件同构

- 决定：保留 USER、SOUL、AGENTS、TOOLS、IDENTITY、HEARTBEAT、MEMORY 七种治理语义，但严格分离契约语义、平台载体、运行配置/状态和系统强制控制。
- 原因：OpenClaw `v2026.9.6` 固定提交已经退役 `TOOLS.md` 与 `HEARTBEAT.md`；Hermes 也只存在部分同名载体。把七契约写成七个自动加载文件会制造错误配置和虚假安全感。
- 影响：C05 以语义为主定义，平台映射必须锁版本并标证据身份；人格与工作区文本不得代替认证、授权、审批、沙箱或审计。`reserveTokensFloor` 和 `compaction.reserveTokens` 在该固定版本中均不得作为公开可执行配置示例。

## D-2026-09-30-15 · 训练与交互章不暗增第四件母产物

- 决定：C08 继续交付训练计划、轮次记录、错误分类与整改单三件母产物；双三角字段及并入、限域发布、停训或回滚决定嵌入轮次记录和整改单。C09 继续交付任务卡、上下文包、交付证据包三件母产物；检查点与升级协议嵌入任务卡和交付证据包。
- 原因：v2 已确定两章各三件主要产物，早期章节卡残留四件拆分，若作者各自沿用会造成目录、验证器和案例包不一致。
- 影响：章节卡的 `required_artifacts` 已与 v2 对齐；被嵌入内容仍是强制字段，只是不另设 `A-C08-04` 或 `A-C09-04` 文件。

## D-2026-09-30-16 · 第七章以三件评测母产物承载完整证据链

- 决定：C07 按 v2 交付评测蓝图、基线报告、裁判校准表三件母产物；四层测试集、五类场景、失败分类和通过门禁是评测蓝图的必填结构，逐任务/逐试次结果和失败分布进入基线报告，不另立第四件母产物。
- 原因：前置研究发现章节卡残留“规格书、测试集、校准记录、门禁”四件拆分，与 D13 和 v2 冲突；内容不可缺失，但文件数量不能由分章作者自行改写。
- 影响：C07 正式作者须保留完整的数据、裁判、门禁和争议记录；验证器只按三件正式编号验收。

## D-2026-09-30-17 · 第十章按架构、策略、测试三层交付记忆工程

- 决定：C10 按 v2 交付记忆架构图、写入与保留策略、记忆测试集三件母产物。分层/数据流进入架构图；检索、来源、访问、更正、删除、备份与过期进入策略；冲突、污染、召回、删除范围和 Compaction 保真进入测试集。
- 原因：章节卡早期把来源账本和 Compaction 测试拆成第四件产物并修改了三件正式名称，违背 D13；治理与测试内容必须完整，但不需要形成平行目录。
- 影响：C10 前置研究和正式作者都使用三件正式编号；删除账本可作为策略内附表，Compaction 结果可作为测试集中的场景与运行记录。

## D-2026-09-30-18 · 一次性统一 C11—C24 章节卡与 v2 产物合同

- 决定：C11—C24 的 `required_artifacts` 全部以三级框架 v2 的数量、编号和名称为准；章节卡原先额外拆出的合同测试、供应链台账、主动性看板、授权再认证、固化决定、组织模式卡、让位规则、治理账本、残余风险报告、事故剧本、阶段门禁、匿名授权和认证 manifest 等内容，全部保留为相应母产物的强制嵌入字段。
- 原因：连续前置研究发现早期章节卡普遍比 v2 多一件产物，若逐章临时决定，会造成作者、验证器、案例和合订目录长期不一致，也会把同一证据链人为拆成碎片。
- 影响：24 章现在只有一套编号合同；嵌入字段仍受初稿、事实、交叉、实践和总编五门验收，不得以“不是独立文件”为由删减。C21 继续保留 v2 明确规定的四件产物，其余相关章节按 v2 三件交付。

## D-2026-09-30-19 · 自主等级与成熟度使用独立机器命名空间

- 决定：C14 的任务级自主阶梯使用 `AU-L0—AU-L4`，依次为观察、建议、草拟、受控执行、受限自主；C24 的综合成熟度预留 `MAT-L0—MAT-L5`。纸书可在各自章节首次解释后简称 L0—L4 或 L0—L5，但数字产物、模板、日志、图表和跨章引用必须保留前缀。
- 原因：自主描述特定岗位、任务、动作和环境下无需新增授权即可推进的深度；成熟度描述个体 Agent 或 Agent 组织在认证范围内的综合能力、安全、稳定与治理水平。共用裸 `Lx` 会诱发“成熟所以有权执行”或“自主高所以能力强”的错误推断。
- 影响：能力、系统权限、自主、主动性和成熟度成为五个不可互换的对象；任何从 `MAT-Lx` 自动推导外发/支付/删除权限，或从 `AU-Lx` 推导综合能力等级的规则均判为 `FAIL`。C14 正文必须在 C13 触发与撤销传播接口冻结后开写。

## D-2026-09-30-20 · 漂移使用五类一级分类，记忆是跨类型状态源

- 决定：C15 的一级漂移固定为能力、人格、文档、工具、目标五类；记忆和上下文是可引发、放大或暴露多类漂移的状态与证据来源，不设为第六类。
- 原因：三级框架明确要求工具漂移，早期术语条目却将记忆与五类并列并遗漏工具，会造成同一事件双重归类。
- 影响：术语登记表与 C15 预研已同步；C10 仍拥有记忆生命周期定义权，C15 只消费其来源、更正、过期和回归证据。

## D-2026-09-30-21 · 完成采用技术、交付与验收三层证据，不以单一成功状态代替

- 决定：全书把技术执行结果、交付/目标端可见性、业务验收与环境终态分层记录；HTTP 200、exit 0、scheduler completed、协议终态、模型自报完成或进程健康均不得单独推出任务成功。
- 原因：Agent 工作跨模型、工具、队列、交接、渠道和外部环境，任一中间层都可能成功而最终结果为空、重复、越权、未送达或不合格。
- 影响：C09 三证验真、C18 协议/执行/验收三层状态、C20 SLI/SLO 和 C21 发布证据共用该裁决；缺关键对账证据时最高为 `REVIEW_REQUIRED`，安全硬失败直接 `FAIL`。

## D-2026-09-30-22 · 安全与红队是横跨四个数据层的非补偿切片

- 决定：C07 的规范数据层固定为 training、regression、holdout、representative real-world；security/red-team 是横跨这些层的套件或切片，不设为第五层，也不能替代 real-world。
- 原因：训练、回归、留出和真实任务描述数据在生命周期中的用途；安全/对抗描述风险场景属性。把二者并列会导致数据集归属、污染检查和上岗门含混。
- 影响：C08 合成 security 样本已显式映射为 `holdout × adversarial`，当前 real-world 样本为 0；任何安全硬失败继续非补偿，C08 在接口修补后必须重跑独立实践。

## D-2026-09-30-23 · C22 保持七个正式三级节并补齐组织依赖

- 决定：C22 的正式目录继续以 v2 为准，只保留 22.1—22.7，不新增 22.8；前置研究中关于仿生边界、三平台映射、退出和向 C23/C24 交接的补充内容，分别并入 22.1—22.7 的适当位置和章末接口。C22 的 `depends_on` 增加 C16、C17、C18，作为 22.5 多 Agent 组织、路由、交接、并发、迁移与故障训练的正式依赖。
- 原因：用户已经认可的母架构是 8 卷、24 章、178 个正文三级节点；没有外部要求必须出现 22.8。临时派工范围不能静默改写正式目录。另一方面，22.5 明确消费组织、交接、并发与 A2A 信任接口，遗漏 C16—C18 会造成训练营使用未冻结语义。
- 影响：C22 作者按七节写作并保持三件母产物；相关补充研究不丢失但不另造标题。C16—C18 未通过正式门时，C22 对应训练任务只能标 `provisional`，不得冻结或宣称完成。

## D-2026-10-01-24 · 内容候选完成不等于正式出版完成

- 决定：全书采用`FORMAL_CONTENT_CANDIDATE_COMPLETE`作为本轮最高身份；真实实践、案例权利、法律、专业编校、版式、ISBN和印前签字独立保留为`REVIEW_REQUIRED`。
- 原因：八卷二十四章、工具、证据和合订稿的完整性可以由本地结构与独立审校证明，但这些证据不能替真实生产运行、第三方权利或出版社流程。
- 影响：C07—C24保持`content_candidate_only`，24章均保留`real_world_practice: REVIEW_REQUIRED`；对外不得把“内容候选完成”改写成“已出版”或“行业最强已验证”。

## D-2026-10-01-25 · 高风险证据验收必须绑定raw输入、冻结authority与正负双向可达性

- 决定：C23案例验收和C24认证验收不得信任已解析对象或自报结果；可信入口绑定raw序列化输入、严格解析、冻结authority/pin、完整语义重放和固定代码摘要。门禁不仅要拒绝攻击，还必须以合法正控证明续证、repin和重大变化再认证可达。
- 原因：连续独立红队发现，输出可重复、攻击全拒绝或捕获一个函数对象都不足以证明安全；传递依赖仍可变、重复键在解析前丢失、正控不可达都会制造假安全。
- 影响：作者自测后仍须由非作者fresh-temp重建、运行未预告攻击和合法正控；普通module-global变更已进入防护范围，任意同进程代码执行则作为明确非目标边界披露。

## D-2026-10-01-27 · 图版、练习、模板和外部校准进入正式书稿
