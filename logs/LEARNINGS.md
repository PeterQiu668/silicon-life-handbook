# 可复用经验

## 2026-09-30 · 大型 Agent 手册的出版化

- “内容多但不像一本书”的根因通常不是缺章节，而是主干、参考、操作与编辑过程没有分层。
- 人类与 Agent 可以共享事实源，但不应共享同一种读取方式；Agent 资料应采用渐进披露。
- 行数、章节数和术语数量不应作为主要质量指标；更重要的是生命周期主线、章节闭环、证据边界与可执行验收。
- “前沿”不等于跟随 main。出版物应固定稳定基线，把未发布 tag 和草案放入观察层。
- 隐喻能帮助理解，但每个“生命、灵魂、想要”的隐喻后面都必须补一个工程解释和权限边界。
- 训练体系如果没有留出集、红队集、成本与延迟门禁，很容易只是在训练集上制造更漂亮的演示。
- 上游项目的开源许可与原创手册的出版许可是两个问题，不能因为依赖项目是 MIT 就自动宣称整本书为 MIT。

## 2026-09-30 · 先冻结知识拓扑，再扩大并行写作

- 多 Agent 写书的第一个瓶颈不是写作速度，而是目录是否拥有唯一的概念定义权和清晰的章际依赖。
- 目录未冻结就并行写作，会把速度放大为重复、冲突和语言不一致；作者确认应当是章节生产的强制门禁。
- 长期出版物应把跨版本原理、通用工程实践和产品/协议实现分层，否则一次上游升级就会让整本书显得过时。
- 每章都要产出可执行产物、验收标准和证据索引，否则手册会退化为概念文集。

## 2026-09-30 · 把初稿、复现与发布资格分成不同事实

- 多 Agent 分章能提高吞吐，但作者交付只能证明初稿齐套；事实、交叉、独立实践和总编必须由非作者完成。
- 确定性合成 harness 很适合验证状态机、门禁与证据闭合，却不能外推到真实模型、真实用户、真实平台和生产网络。
- 好的训练实验允许得出“停止并回滚候选”。训练集改善而留出集或安全集未过，拒绝推广比制造漂亮提升数字更有价值。
- 观测系统应固定任务、尝试、授权、产物、交付与验收的关系，不把仍在演进的 OpenTelemetry 或平台字段名写成永久行业标准。
- 任何“完成”至少要区分技术执行、交付可见和业务/环境验收；只看中间成功状态，是 Agent 系统最常见的假成功来源之一。

## 2026-09-30 · 区分可复现判分器与可执行安全控制

- 两次输出哈希一致只能证明固定程序和输入可重复，不能证明程序真的执行了它声称覆盖的安全场景。
- 若 runner 直接读取 `ssrf=true`、`readback=unchanged`、`manifest_valid=false` 等预置结论，它验证的是路由规则，不是 URI、环境、文件、权限或生命周期控制。
- 高风险章节应增加状态化夹具：从原始 URI、文件树、权限差异、访问矩阵、缓存/Worker 状态和外部终态推导观察，再由观察产生门禁结果。
- 安全拒绝可以是控制能力的 PASS，但恶意组件、未授权副作用或已经发生的错误终态仍须保留 FAIL；检测到事故不能追溯抹去事故。
- 真实环境没有获权时，最诚实的最高结论是“离线机器控制 PASS，完整实践门 REVIEW_REQUIRED”，并明确关闭条件。

## 2026-10-01 · 红队要验证传递依赖，也要验证合法路径可达

- 把一个验证函数捕获到闭包，不等于它的全部依赖都被冻结；函数体仍可能动态读取module globals。攻击应沿调用图逐层替换canonical、digest、parser、authority validator和evaluator，而不是只patch最外层入口。
- 严格JSON必须在对象形成前拒绝任意层级重复键、尾随文档和非有限数；一旦先解析成dict，序列化来源和重复键证据已经不可恢复。
- “所有攻击都被拒绝”可能是系统拒绝一切。高风险门禁必须同时有合法正控，证明正常签发、续证、repin、撤销和重大变化再认证在正确因果链下能够通过。
- 作者整改不能自我关闭P0。非作者应从builder开始做两个fresh-temp重建，并把历史攻击、当前攻击和正控一起回放。

## 2026-10-01 · 出版内容、真实实践和发行资格是三套状态

- 一本手册可以在结构、事实边界和离线控制上成为正式内容候选，同时在真实平台实践和法律出版上保持REVIEW_REQUIRED；把三者压成“完成/未完成”会诱发过度声明。
- 生成合订稿必须是规范源的机械产物，状态、看板和审计也要在最后一次构建后统一刷新，否则正文正确而控制面过期仍会造成误发布。
- 读者产物不应暴露内部review路径、临时目录或整改版本；这些信息保留在审校证据层，公开工具只描述稳定的复现合同。

## 2026-10-01 · 训练手册必须同时教会执行、验证与回退

- 只讲契约、授权、安全和审计，会让Agent更规矩，却不一定让它更会完成复杂任务；任务分解、外部化状态、自我验证、反例、死胡同、回退、并行收敛和上下文隔离应形成独立训练层。
- 长任务能力的关键不是模型“记得更多”，而是承诺、事实、假设、待办和恢复点有不同载体、权威顺序和冲突处理；上下文压缩必须对gold slots做保真验证。
- 多Agent并行的收益取决于独立性、共享资源仲裁和收敛合同；增加worker数量而没有上下文隔离、single-writer和合并者，通常只会放大冲突。
- 图、练习和模板不是装饰性配套。只有它们进入manifest、构建器和验证器，才能保证下一版不会再次漏掉。
- 外部课程可以触发原创探索，但没有逐字稿和改编授权时，不能成为正式书稿中枢架构的唯一来源；正确做法是权利隔离、独立重构和可删除依赖测试。
- 公开基准适合外部校准，不适合直接签发岗位胜任；必须同时记录测什么、不测什么、七维覆盖和D22数据身份。
