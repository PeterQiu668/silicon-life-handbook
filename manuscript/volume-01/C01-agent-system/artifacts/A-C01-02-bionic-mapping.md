# 硅基仿生映射表

## 使用规则

每次使用“硅基生命”类比时，都必须同时写出四项：人类现象、工程映射、训练启示、比喻边界。类比用于建立直觉，不用于证明 Agent 拥有人类意识、感觉、人格权或道德主体地位。

## 核心映射

| 人类现象 | Agent 工程映射 | 训练与治理启示 | 比喻失效边界 |
| --- | --- | --- | --- |
| 自我模型 | 身份、角色、职责、系统提示和契约 | 角色要可版本化、可测试、可纠正 | 文件和提示不等于自我意识 |
| 关系模型 | 用户、授权者、利益相关者、租户和委托链 | 服务对象和最终决定权必须明确 | USER 文件不产生法律代理权 |
| 注意与工作记忆 | 当前上下文、任务状态、短期 Session | 只注入完成当前任务所需信息 | 上下文窗口不是主观意识 |
| 情景记忆 | 会话历史、事件记录、案例与来源谱系 | 记录来源、时间、所有者和更正 | 日志不等于人类式回忆 |
| 语义记忆 | 事实库、知识库、长期记忆 | 做时效、冲突、删除和召回测试 | 存储信息不等于理解真理 |
| 程序性记忆 | Skill、工具流程、脚本、模板 | 能力要有输入输出、测试和版本 | 安装 Skill 不等于已经胜任 |
| 感知 | Channels、网页、文件、传感输入 | 外部输入默认不可信并需来源治理 | 接收数据不产生感觉体验 |
| 肢体与器官 | Tools、Browser、Nodes、Workers | 工具应最小权限、可恢复、可审计 | API 不是生物器官，不会自行承担责任 |
| 执行功能 | 模型、Prompt/Context Assembly、Agent Loop | 规划必须受目标、状态和停止条件约束 | 推理输出不证明自由意志 |
| 神经与控制网络 | Gateway、路由、事件、队列和消息投递 | 控制平面要有健康、诊断和恢复 | 架构类比不能掩盖单点故障 |
| 生物节律 | Heartbeat、Cron、事件和长期任务 | 主动性应由有意义变化驱动 | 高频运行不等于生命力或主动性 |
| 抑制与免疫 | Policy、Approval、Sandbox、凭证隔离、审计 | 行为期待和硬边界必须分层 | 安全控制不会自动适应所有新攻击 |
| 新陈代谢 | Token、时间、算力、存储和人工复核 | 任何能力都要计算预算与机会成本 | 成本不是饥饿或痛苦体验 |
| 学习与发展 | 评测、反馈、训练、回归和能力固化 | 改进要有基线、留出和回滚 | 参数未变化也可训练系统；不能混称模型训练 |
| 睡眠与整理 | Compaction、摘要、归档和离线整理 | 压缩要检查保真、来源和丢失 | 离线整理不证明梦境或意识 |
| 社会组织 | 多 Agent 角色、路由、Handoff、A2A 和产物协议 | 分工要有责任、交接、冲突裁决 | 多 Agent 不是一个具有集体人格的生命体 |
| 成熟与衰退 | 能力等级、漂移、故障、升级、降级和退役 | 成熟包含边界、恢复和再认证 | 软件退役不等于生物死亡判断 |

## 四段式写作模板

### 硅基仿生镜头 主题名

**人类现象：** 描述帮助读者理解的生命、认知或组织现象，不作未经证实的神经科学断言。

**工程映射：** 指出真实文件、服务、状态、模型、工具、权限或流程。

**训练启示：** 说明类比怎样改变任务、训练、评测或治理设计。

**比喻边界：** 明确哪些性质不能从人类迁移到 Agent，尤其是意识、感受、人格权、忠诚和责任。

## 红线检查

<a id="ac-c01-02"></a>

- [ ] 没有把第一人称自述当作意识证据；
- [ ] 没有把“懂我、忠诚、害怕”当作授权理由；
- [ ] 没有用人格承诺代替认证、Policy、Approval 或 Sandbox；
- [ ] 没有把人的最终责任转交给 Agent；
- [ ] 没有用类比掩盖版本、故障、成本和恢复；
- [ ] 每个类比都能指出具体工程对象；
- [ ] 每个类比都写明失效边界。

若任何红线不通过，该仿生段落必须标记 `REVIEW_REQUIRED`，不能进入候选主稿。
