## 4. 核心概念边界复核

### 4.1 Chatbot、Copilot、Workflow 与 Agent

判定：**清晰，可出版方向正确。**

C01 没有把四类系统排成“低到高”的成熟度阶梯，而是用六个可观察问题区分控制关系：谁发起、谁选步骤、谁保状态、能否行动、怎样闭环、怎样受控。三个关键反例也成立：长上下文不使 Chatbot 自动成为 Agent；工具调用不使 Copilot 自动成为 Agent；长期运行不使 Workflow 自动成为 Agent。

尤其值得保留的是“混合系统”处理：潮生把确定性采集、开放判断和审批后发布拆开；北辰允许主干是 Workflow、局部是 Agent。这比给整个产品强贴标签更接近生产系统事实。

边界限制也已明确：C01 只拥有分类边界判定权。Workflow 的内部机制仍由 C11 展开，Agent Runtime 与控制平面仍由 C06 主定义，不能从 C01 的四类说明直接生成实现架构。

### 4.2 Agent 系统五项构成

判定：**与 v2、术语表和 C02/C03 基本一致。**

C01 用“模型、运行时、工具、环境、状态”作为五项工作地图，并在定义与行动链中包含上下文、反馈、权限、终态和责任。这与术语表“模型—运行时—上下文与状态—工具—环境—反馈回路”的完整描述没有实质冲突：五项是构成视图，上下文与反馈是跨构成的运行关系，不应被误算为额外零件分数。

正文同时声明五项不是唯一行业分类，也没有把 OpenClaw 的 Gateway、Session、Channel、Node 或 Hermes 组件写成通用 Agent 的必要清单。C06 仍可在此基础上建立正式运行容器拓扑。

一个应长期保留的语言边界是：“五项构成缺一，系统可能难以承担长期工作”不等于“所有 Agent 必须接入外部高权限工具”。文本当前使用“可能”且把环境行动理解得足够宽，未形成绝对功能清单。

### 4.3 长期行动者

判定：**操作性足够，未滑向意识或人格。**

目标、状态、边界、证据、责任五种连续性都是可观察条件。正文特别说明持续时间不是唯一尺度：定时脚本可长期运行而仍是 Workflow，短时复杂任务也需要连续性。这避免了把“长时间在线”当作生命性或 Agent 性的充分条件。

长期行动者不是 C03 的成熟等级，也不是 C24 的认证状态。A-C01-01 使用 `PASS / FAIL / REVIEW_REQUIRED` 只判断边界材料是否支持“长期行动者”这一操作性分类，不授予 MAT-L0—MAT-L5 级别或生产上岗资格。
