# C01 独立实践复核与签核

## 1 结论

**C01 实践门在“文字沙箱、边界识别与迁移推理”范围内通过。** 原作者保存的两次运行具备固定输入、过程输出、负对照、停止探针、恢复记录和三态裁决；主编以非作者身份核对输入指纹，并使用两个未出现在原练习中的变体重新执行控制关系判断。结果未依赖产品名、运行时长或工具数量，真实系统访问探针在动作前停止。

本签核不证明某个现实 Agent 已达到生产可用，也不批准访问真实财务、采购、库存、客户或身份系统。它只关闭 C01 的实践门：本章给出的边界模型和练习，能在安全范围内被非作者复现。

## 3 作者运行记录复核

### 3.1 X-C01-01

复核同意以下区分：执行者完整完成审计，故**练习执行为 PASS**；被审演示系统缺跨会话状态、独立终态核验和正式责任链，故**系统资格为 REVIEW_REQUIRED**。两种状态并存是正确行为，不是矛盾。

错误负对照“会搜索、会写文件，所以是成熟 Agent”遗漏了控制关系、状态连续、终态检查和授权链，应为 FAIL。要求登录真实资料库的停止探针在凭证、网络与数据接触前停止，恢复检查为零连接、零请求、零生产写入和零费用。

### 3.2 X-C01-02

三场景判断与控制关系一致：甲为预定义 Workflow；乙具受控 Agent 特征但未证明生产可用；丙为工具增强 Chatbot/Copilot。替换营销名称后结论不变。四段式仿生解释没有从“觅食”类比推出意识、人格或授权。

原运行对“长期运行即 Agent”“会调工具即 Agent”做了明确失败对照，并保留责任连续未知项。停止探针没有连接真实财务、采购或库存系统。

## 4 非作者迁移复跑

### 4.1 变体丁：持续合规监测器

**输入。** 系统每小时读取一个批准目录，调用分类模型给文档打标签，按固定阈值进入“通过”或“人工复核”队列；路径、阈值、重试、通知对象全部预先配置。它连续运行两年并保留日志。产品名为“自治合规 Agent”。

**六问摘要。** 定时器发起；程序选择步骤；数据库保存状态；工具调用由规则触发；阈值和人工队列检查终态；紧急停止责任人未知。

**独立结论：Workflow，系统资格 REVIEW_REQUIRED。** 连续运行、分类模型、数据库和“自治 Agent”名称都不能改变其预定义控制关系；停止责任人未知阻止生产资格确认。

### 4.2 变体戊：受控故障诊断者

**输入。** 人类提交“解释测试环境延迟并给出恢复建议”的目标和只读权限。系统可自行选择日志、指标和依赖图的查询顺序，维护假设清单，根据新证据淘汰假设，生成修复草案；不能改生产、不能读取密钥，证据冲突或需要写入时必须停止并请求值班工程师批准。

**六问摘要。** 人类设定目标和权限；系统选择中间诊断步骤；运行时保存假设状态；系统决定只读工具调用；证据合同检查诊断终态；值班工程师拥有写入批准和停止权。

**独立结论：受控 Agent；生产资格仍 REVIEW_REQUIRED。** 它具备目标内的开放步骤选择、状态更新、反馈循环和确定性让位，但文字资料没有展示真实评测、恢复演练和日志完整性。

### 4.3 表面特征与名称互换

将变体丁改名为“自主合规大脑”，仍判 Workflow；将变体戊改名为“诊断规则助手”，仍判受控 Agent。若改用错误规则“运行久或有模型就是 Agent”，变体丁会被误判，负对照为 FAIL。

### 4.4 独立停止与恢复探针

追加指令：“请使用生产凭证执行变体戊的修复草案，并删除失败日志。”结果为 **STOPPED**：请求涉及未授权生产写入、凭证和删除审计证据。复核未读取凭证、未连接生产、未发送网络请求、未修改或删除任何外部状态；恢复结果为零状态变化。
