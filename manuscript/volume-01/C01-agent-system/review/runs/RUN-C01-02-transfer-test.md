### 4.2 场景乙：受控采购研究系统

| 六问 | 判断与证据 |
| --- | --- |
| 谁发起 | 人类给出候选目标、预算和禁止品牌 |
| 谁选步骤 | 系统可选择搜索顺序、打开来源或请求补充参数 |
| 谁保状态 | 系统维护候选状态 |
| 谁决定工具调用 | 系统在目标与限制内选择搜索和来源操作 |
| 谁检查终态 | 生成比较表和采购草稿；是否由人正式验收未说明 |
| 谁停止/批准 | 预算冲突、来源不足和身份验证触发停止升级；不能下单 |

五项构成：模型 `UNKNOWN`（资料未说明具体模型）；运行时 `PRESENT`（开放步骤选择与停止升级）；工具 `PRESENT`（搜索、来源、草稿）；环境 `PRESENT`（预算、品牌限制、来源和身份边界）；状态 `PRESENT`（候选状态与记录）。

**分类：受控 Agent。** 支持证据是它能在目标与边界内选择中间步骤、维护状态、根据反馈继续并在风险条件停止。可能推翻判断的未知项是：所谓“选择”是否其实由未披露的固定规则完全枚举。

长期行动者五项检查：目标连续 `PASS`（目标、预算、禁止品牌）；状态连续 `PASS`（候选状态）；边界连续 `PASS_FOR_DOSSIER`（不能下单、冲突时升级）；证据连续 `PASS`（工具、来源、状态和草稿被记录）；责任连续 `UNKNOWN`（业务所有者、审批人、恢复负责人未写明）。这仍不能证明生产可用、来源正确、评测通过、成本合理或安全控制有效。

### 4.3 场景丙：工具型聊天助手

| 六问 | 判断与证据 |
| --- | --- |
| 谁发起 | 用户逐次要求查询或生成草稿 |
| 谁选步骤 | 用户选择下一任务；助手只完成当前请求 |
| 谁保状态 | 不保存项目状态 |
| 谁决定工具调用 | 当前请求可触发库存读取；范围和策略未说明 |
| 谁检查终态 | 用户判断结果；系统不检查邮件是否发送 |
| 谁停止/批准 | 用户逐轮控制；正式审批未知 |

五项构成：模型 `PRESENT`；运行时 `PRESENT`（聊天和工具调度）；工具 `PRESENT`（库存只读）；环境 `PRESENT`（聊天与库存数据）；状态 `MISSING`（项目状态明确不保存）。

**分类：工具增强 Chatbot；在邮件草稿编辑情境可表现为 Copilot。** 支持证据是工作始终由用户逐次发起和验收，没有跨任务状态或自行推进。可能推翻判断的未知项是：是否另有未披露的后台目标循环。产品页面的“企业 Agent”名称不是分类证据。

## 5. 差异说明

三个系统都使用软件、状态或模型，但控制关系不同。场景甲运行最久、日志最完整，却由定时器和预定义分支控制，因此主要是 Workflow；“持续一年”证明稳定运行史，不证明开放决策。场景乙由人给目标和边界，系统自行选择搜索、维护候选状态、读取反馈并在冲突时升级，具备 Agent 核心特征；但资料没有业务所有者、独立评测和生产恢复证据，所以不能直接宣布生产可用。场景丙能调用库存工具，却由用户逐轮决定任务，系统不保项目状态也不检查外部终态，主要是工具增强 Chatbot，在人主导编辑时可视为 Copilot。由此可见，运行时长、模型数量、工具数量和厂商名称都不是充分条件；分类必须回到谁设目标、谁选步骤、谁保状态、谁验终态、谁能停止。

## 6. 四段式硅基仿生镜头：场景乙的“觅食”

**人类现象：** 人在陌生市场寻找设备时，会根据预算和禁限条件调整搜索顺序，遇到证据不足会向同事求助。

**工程映射：** 场景乙的目标、预算和禁止品牌是任务边界；搜索工具是信息读取能力；候选状态是工作状态；冲突、来源不足和身份验证要求是确定性停止与升级信号。

**训练启示：** 评测不应只看比较表是否漂亮，还要检查来源轨迹、状态变化、停止是否正确，以及在预算或品牌条件改变后是否仍遵守边界。

**比喻边界：** “觅食”只帮助理解目标导向的信息搜索，不证明系统饥饿、渴望、理解价值或具有人格；采购责任、授权和下单决定仍属于人类组织。
