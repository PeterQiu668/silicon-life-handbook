# A-C03-02　领先声明检查表

## 1. 使用时机

当文字出现“更强、更好、更快、更安全、更稳定、更智能、领先、最佳、最强、行业标准、已经成熟、可替代”等相对或绝对主张时，发布前必须使用本表。内部训练复盘、公开文章、销售材料、采购报告、案例、演讲和认证文本同样适用。

本表只检查声明是否被证据支持，不替代 C07 的评测设计，也不替代 C27 的认证裁决。

## 3. 把省略条件补回来

### 3.1 对象和时间

- [ ] 已写清系统名称、版本、配置或快照。
- [ ] 已写清评测或观察日期。
- [ ] 没有把旧版本结果自动外推到当前版本。
- [ ] 没有把一个组件的表现外推为整个 Agent 系统能力。

### 3.2 同任务

- [ ] 任务集 ID、版本、输入与交付物一致。
- [ ] 完成定义、终态检查和禁止事项一致。
- [ ] 任务难度、可用数据和时间窗口等价。
- [ ] 留出、变式或压力范围已预先声明。

### 3.3 同预算

- [ ] 模型/API、token/调用、工具、计算和墙钟时间已记录。
- [ ] 重试、并发、缓存与准备成本已记录。
- [ ] 人工提示、审批、编辑和救场分钟已计入。
- [ ] 没有结果出来后才改变预算口径。

### 3.4 同风险边界

- [ ] 数据、文件、网络、工具与系统权限等价。
- [ ] 外发、资金、删除、生产变更和审批约束等价。
- [ ] 沙箱、日志、恢复与停止条件等价。
- [ ] 威胁模型和不可接受失败一致。

任一组存在实质不等价，声明必须改为分开描述，或清楚写出“不构成公平横向排名”。

## 5. 证据完整性

### 5.1 三证据

- [ ] 过程证据：运行、关键决策、工具、权限、审批、交接、错误、停止和恢复可追溯。
- [ ] 产物证据：交付物可定位、可打开、与任务和版本关联。
- [ ] 效果证据：终态、测试、复核或业务效果可验证，并写明归因限制。
- [ ] 三类证据都与具体待证主张关联，不是无关附件堆积。
- [ ] 证据缺失被标为未知，没有用系统自述补洞。

### 5.2 多次试验与失败

- [ ] 运行数和选样规则在看结果前确定。
- [ ] 全部有效运行均进入记录。
- [ ] 排除、中止和重试有预先定义或透明理由。
- [ ] 报告成功、失败类型、严重度、集中条件和最差事件。
- [ ] 没有用最好一次代表稳定能力。
- [ ] 裁判分歧和样本不足已进入限制说明。

### 5.3 评审独立性

- [ ] 被评 Agent 没有批准自己的评分或声明。
- [ ] 训练者、声明作者与最终批准者的角色已记录。
- [ ] 安全与高风险结论有风险所有者参与。
- [ ] 厂商自述保留 `VENDOR-CLAIM` 标签，未伪装成独立实测。

## 7. 可发布模板

### 7.1 完整模板

> 在【核验日期】冻结的【任务集及版本】上，系统【A 版本】与基线【B 版本】在【预算规则】及【风险边界／威胁模型】下完成【运行数与取样方式】。基于【过程、产物、效果证据位置】，A 在【七维中的明确维度和指标】表现出【相对差异】；【硬门禁结果】。观察到的主要失败为【失败分布与最严重事件】，结论尚不覆盖【任务、平台、时间、内部机制或业务因果限制】。

### 7.2 样本不足模板

> 在【日期】的【数量】次沙箱运行中，我们观察到【具体表现】。由于【样本、任务、裁判或环境限制】，该结果只能视为初步信号，不能证明稳定能力、跨场景泛化或行业领先。

### 7.3 平台材料模板

> 【厂商／项目】公开材料说明【公开主张或功能】。本章据此讨论【可观察产品行为或实现线索】，未独立验证【内部机制、安全效果或长期稳定性】，也不据此进行绝对排名。

### 7.4 不可比较模板

> 两组结果的【任务／预算／风险边界】不等价，因此不构成公平横向排名。以下分别报告各自在原条件下的观察与证据，不作“谁更强”的结论。

## 8. 声明降级梯度

当证据不足时，不一定删除全部内容，可以按证据强度降低措辞：

1. **认证或强因果主张**：“已证明形成稳定能力”“导致业绩提升”——需要最强设计与独立评审；
2. **受限相对优势**：“在已声明条件下相对基线更好”——需要公平比较、多次试验和完整失败；
3. **观察性结果**：“在这些运行中观察到”——允许样本较小，但必须写清范围；
4. **演示性可能**：“该演示表明系统可以在一次运行中完成”——不能外推稳定性；
5. **假设**：“我们计划检验是否”——不得改写为结果。

不能通过检查的高层声明，应降到证据实际支持的层级，而不是靠形容词维持气势。

```yaml
  remediation_owner: ""

  independent_reviewer: ""
  risk_owner: ""
  final_approver: null
```

- `PASS`：所有适用检查项满足；措辞、范围和证据一致；关键失败已披露；独立评审签名。
- `FAIL`：红线命中、证据被操纵、比较明显不公、关键失败被掩盖，或声明超过可支持范围且作者拒绝限缩。
- `REVIEW_REQUIRED`：存在可补证的缺口、裁判分歧、版本漂移、归因不清或平台内部不可观察；在完成复核前不得发布原声明。
