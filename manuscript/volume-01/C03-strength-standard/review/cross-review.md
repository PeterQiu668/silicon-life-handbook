# C03 交叉审稿与质量初评

## 1. 总评

C03 已形成卷一所需的统一度量语言：C01 定义“评什么对象”，C02 定义“什么是训练”，C03 定义“怎样描述强、凭什么比较、证据能支持到哪里”。七维、三比较前提、五类归因、MAT-L0—MAT-L5 总阶梯、三证法、多次试验、失败分布和领先声明形成连续论证；正文、两件产物与两项练习语义一致。

本章没有把 C07 的测试集、grader 与统计方法提前写死，也没有越权发布 C24 的认证阈值、有效期和证书。当前可进入实践审校与安全红队，但仍必须保持 `drafting`：练习尚未试跑，跨 Runtime 迁移尚无运行证据，百分制高分不能替代这些门禁。

## 3. 与 C01、C02 的接口

### 3.1 C01 → C03

C03 沿用 C01 的“Agent 系统而非裸模型”对象，没有重画 C01 的五项系统构成或长期行动者定义。七维中的可治理、安全和稳定均落到系统与环境证据，避免把模型能力直接当系统能力。

输入接口有一处表达差异但不构成冲突：C03 章首写“C01 的 Agent 系统边界卡”，对应实际 `A-C01-01`；没有依赖已被 D-13 删除的旧产物编号。

### 3.2 C02 → C03

C03 把 C02 的训练目标、生产目标和双闭环转为比较合同、基线、运行集合与证据判断，没有重定义训练范式或生命周期。C02 明确把七维、三证和 MAT-L0—MAT-L5 交给后章；C03 又把测试集和统计实现交给 C07、完整认证交给 C24，依赖链闭合。

需由总编辑长期保持的一致性：C02 的简写“MAT-L0—MAT-L5 定义属于 C03”应理解为“总阶梯概览属于 C03”；中间等级门禁、阈值、有效期和认证程序仍由 C24 唯一发布。本章已经显式写出该边界。

## 5. 七维、MAT-L0—MAT-L5 与三证法的一致性

三套语言被正确分离：

- 七维回答“强由哪些方面组成”；
- MAT-L0—MAT-L5 总阶梯回答“系统可在多大治理半径内承担职责”；
- 三证法回答“凭什么相信某项表现、能力或等级候选”。

评分卡没有将七维机械相加成通用总分；成熟度候选状态为 `SUPPORTED / NOT_SUPPORTED / UNKNOWN`，最终裁决仍交 C24；三证索引按声明建立，不把“凑齐三个附件”当通过。该结构避免了维度、等级、证据三者互相替代。

## 6. 人类版与 Agent 版一致性

Agent 机器块只允许读取授权记录、关联证据、计算预定义描述性指标和生成草案；明确禁止删除失败、事后改标准、虚构内部机制、平均抵消安全失败、自批领先、自扩权或自授认证。其输出、停止条件、升级条件和完成定义与人类正文一致。

两份产物中的枚举与正文一致：

- 硬门禁：`CLEAR / FAIL / REVIEW_REQUIRED`；
- 七维刻度：`0 / 1 / 2 / 3 / 4 / U / N/A`；
- 成熟度候选：`MAT-L0—MAT-L5 / UNKNOWN`，且只能是候选；
- 最终状态：`PASS / FAIL / REVIEW_REQUIRED`。
