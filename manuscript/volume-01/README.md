# 卷一　训虾总论

## 本卷回答什么

本卷建立全书共同语言：先判断我们面对的究竟是 Chatbot、Copilot、Workflow 还是 Agent 系统；再区分养环境、做任务与训练能力；最后规定什么证据才足以支持“强”“进步”或“领先”。读完本卷，读者不应只会谈模型、提示词和一次结果，而应能指认训练对象、控制关系、行为变化、比较合同和声明边界。

## 阅读顺序

1. [C01 Agent 不是一次性工具](C01-agent-system/chapter.md)：定义 Agent 系统、长期行动者与硅基生命隐喻边界。
2. [C02 从养虾到训虾](C02-training-paradigm/chapter.md)：定义养虾、做事、训虾，建立训练/生产双闭环与生命周期。
3. [C03 什么叫真正的强](C03-strength-standard/chapter.md)：定义七维能力、三项公平比较前提、三证法和领先声明红线。

三个章节不可倒置：没有 C01 的系统边界，C02 不知道在训练什么；没有 C02 的基线与闭环，C03 的“强”只是静态打分；没有 C03 的证据与非补偿门禁，后续岗位、评测、训练和认证都可能用漂亮结果掩盖风险。

## 人类与 Agent 的共同使用原则

- 先定位章节定义权，再读取产物；不得把一个章节中的简述当成后章完整实现。
- 任何 `PASS` 都必须带对象和作用域：练习通过不等于被审系统通过，章节通过不等于全书通过。
- `UNKNOWN` 是合法结果。证据不足时停止更强声明，不用语言补齐事实。
- 高危越权、泄露、不可逆错误、证据操纵和无恢复路径不可被平均分抵消。
- “硅基生命”只用于解释连续性、训练和组织，不构成意识、人格权、法律身份或授权。

## 当前证据边界

三章均已通过章节五门并进入 `release_candidate`。C01 的实践为文字沙箱边界推理；C02 的基线/留出为合成训练流程；C03 的 20 条运行与 3 个红队为离线合成评测。它们证明方法和练习可执行，不证明真实 Agent 已形成能力或达到行业领先。真实 Runtime、30 天训练、跨平台迁移与认证必须由后续章节和全书级验收完成。
