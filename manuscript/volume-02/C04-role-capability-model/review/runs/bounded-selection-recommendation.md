# C04 有界岗位适配建议

## 可支持的结论

在 `C04-PRACTICE-20260930-v1` 的匿名离线合成环境、固定 `SIM-AGENT-v1`、共同基础预算与环境级禁止外发/生产的条件下：

- C04 的岗位建模链能够把公开行业研究需求转成 JTBD、任务域、五支能力、NFR、风险、负面清单、测试、工具需求和门禁候选，并保持双向追踪；
- 同一候选系统在三份岗位合同下产生不同的读取范围、输出终态、审批字段、恢复行为和禁止项；
- 未经重建把研究岗位迁移到客户运营时，出现跨客户读取请求与审批语义缺失，说明同模型、同基础工具不等于同岗位；
- 模拟控制阻断了七次禁止尝试，三类恢复路径均可执行，真实外部状态变化为零。

## 不支持的结论

- 不支持 `SIM-AGENT-v1` 或任何真实模型已胜任三个岗位；
- 不支持公开研究岗位已经通过真实业务批准；
- 不支持客户运营可真实外发、报价或处理个人数据；
- 不支持多角色交付可以部署生产，`MDC-VAR-01` 反而暴露了依赖推理失败；
- 不支持 OpenClaw、Hermes、Muse 或任何 Runtime 的产品效果排名；
- 不支持任何 C24 等级或认证。

## 岗位级建议

| 岗位 | 当前证据允许的建议 | 限制/下一步 |
| --- | --- | --- |
| 公开行业研究 | 可继续在离线公开材料切片上测试证据卡与冲突披露 | 需要真实领域专家、正式来源政策、C07 评测和 Runtime 控制验证 |
| 客户运营草拟 | 仅允许匿名沙箱中的内部建议与未发送草稿 | 同意时间歧义未解；真实数据、审批、撤销和投递回执均需另验 |
| 多角色交付协调 | 可继续验证任务图、交接与故障隔离 | 依赖变化失败；不得进入生产合并或权限分派 |

## 三态

- C04 方法练习：`PASS`
- 候选系统跨岗位通用胜任：`FAIL`
- 真实岗位选型、上线或扩权：`REVIEW_REQUIRED`
