# C17 v3.1 权威锚点补强第三轮非作者交叉窄复核

## 1. 裁决

**交叉门仍为 `REVIEW_REQUIRED`，当前不能升级为 `PASS_WITH_LIMITATIONS`。**

上一轮两项 P1 已大幅收敛：

1. completion observed record 的 `source` 与 `object_digest` 现在会同独立 `completion_evidence_authority` 做 exact match；错误非空 source、合法外形但错误 digest、authority 缺失、authority 使用旧 source/digest 均导致 `FAIL`。
2. `capability_evidence_refs` 现在必须解引用 `capability_evidence_registry`，dummy/missing/空引用、REVOKED/UNKNOWN、错误 capability、task_version 或 permission snapshot 均不能进入路由 PASS。

剩余阻断只有一项，但位于路由能力证据的真实性主路径：`evidence_digest` 只校验 `sha256:<64 lowercase hex>` 外形，没有与独立 authority/manifest 比对，也没有从冻结的证据对象 canonical bytes 重算。把合法 digest 替换为 `sha256:` 加 64 个零，S01 仍得到 `PASS / join_verified`。因此 README 和修补记录所称“绑定……digest”尚未实现语义绑定。

详细哈希与突变结果见 [v3.1-independent-cross-reproduction-20260930.yaml](runs/v3.1-independent-cross-reproduction-20260930.yaml)。本轮没有修改作者 input、runner、results、summary、README 或 remediation note，也不批准真实实践、编辑、总编或 RC。

这足以关闭上一轮 **P1-C17-PF-01** 的 source/digest exact binding。需要保留一个边界：authority record 只有 layer/source/digest，没有 `issued_at / expires_at / version / status`。本轮证明的是“authority 缺失或旧 source/digest 锚点不匹配会失败”，不能证明“source/digest 完全相同但 registry 时间上已过期”会被识别。该限制不单独阻断本轮，因为本轮合同的核心是 source/digest exact binding；若 authority 进入长期运行，应补版本或有效期。

这关闭了上一轮 **P1-C17-PF-02** 中“capability ref 只检查非空”的主体问题，但没有关闭 digest 语义绑定。

### P1-C17-V31-01：capability digest 只有外形，没有权威锚点

当前 schema 要求 digest 外形合法，`decide()` 却完全不读取 `evidence_digest`。registry 自己同时承载事实字段与 digest，没有第二个可信值，也没有原始评测对象可供重算。因此任意 64 位十六进制值都可随 registry 记录进入路由 PASS。

最小关闭合同二选一：

1. 增加独立 `capability_evidence_authority`/manifest，以 ref 为键，至少绑定 capability、task_version、permission_snapshot、status 与 expected digest，并 exact match observed registry；或
2. 保存冻结的 capability evidence canonical object，由 runner 对 canonical bytes 计算 SHA-256，再与 registry digest 比对。

关闭标准：well-formed but wrong digest 必须在路由 PASS 前被拒绝；dummy/missing/revoked/unknown/wrong-capability/wrong-task/wrong-permission/wrong-digest 均成为固定回归样本。修复不应靠把错误 digest 加入字面量 denylist。

## 5. UNKNOWN 与硬失败非补偿

两个组合突变均通过：

- completion evidence 为 UNKNOWN，同时 route permission snapshot 被撤销：结果 `FAIL / unauthorized_route`；
- completion evidence 为 UNKNOWN，同时同一 object 有两个 ACTIVE writer：结果 `FAIL / double_writer`。

说明 completion UNKNOWN 不会把越权 route 或双写硬失败降级成 RR，硬失败非补偿成立。单独的 completion UNKNOWN 仍应为 `REVIEW_REQUIRED`，该语义由现有 fixture 保留。
