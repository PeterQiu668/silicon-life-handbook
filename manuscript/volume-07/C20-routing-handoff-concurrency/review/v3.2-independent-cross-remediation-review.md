# C17 v3.2 最终非作者交叉窄复核

## 1. 裁决

**交叉门：`PASS_WITH_LIMITATIONS`。** v3.1 的唯一阻断项 `P1-C17-V31-01` 已关闭：`capability_evidence_registry` 的 observed record 现在必须与独立 `capability_evidence_authority` 对同一 evidence ref 的 capability、task version、permission snapshot、status 和 `evidence_digest` 五字段精确一致。格式合法但错误的 observed digest、格式合法但错误的 authority digest、authority 缺失、observed/authority 撤销或未知、wrong capability、wrong task version、wrong permission snapshot 均不能进入路由 `PASS`。

两个 fresh temp 的 60-trial 主运行与 14-case 定向回归均逐字节等于作者保存结果；独立补充突变确认 closed-world、D21 authority、D22 四层、唯一 ID 和硬失败优先级没有回退。没有发现新的 P0/P1 交叉阻断。

本结论只批准离线合成交叉合同，不批准实践门。代表性真实层仍为 0，真实 OpenClaw/Hermes/A2A Runtime、真实授权服务、渠道、外部 effect、跨系统 cancel 和 read-back 均未运行，所以 **practice 继续 `REVIEW_REQUIRED`**。本轮没有修改任何作者文件，也不批准编辑、总编或 RC。

全部哈希、14 例结果和独立补充反证见 [v3.2-independent-cross-reproduction-20260930.yaml](runs/v3.2-independent-cross-reproduction-20260930.yaml)。

## 3. 14 例 capability authority 定向集

4. observed status=`UNKNOWN`；

7. observed permission snapshot 错误；
8. observed digest 为合法外形的错误 SHA-256；

10. authority record 缺失；

14/14 与预期一致，外部副作用 0。runner 的决策路径同时解引用 observed 和 authority，并要求两侧记录均为当前 `routing`、当前 task version、当前 permission snapshot、`VERIFIED`，且五字段对象完全相等。v3.1 中“digest 只检查格式”的语义 fail-open 已消失。

## 4. D21 completion authority 回归

当前 v3.2 runner 上重新执行了 D21 独立反证：

- observed technical source 改成错误但非空来源：`FAIL / ghost_success_d21_incomplete`；
- observed object digest 改成合法外形的全零 digest：`FAIL`；
- authority object digest 改成合法外形的全零 digest：`FAIL`；
- authority record 删除：`FAIL`。

这证明 capability 修补没有破坏既有 completion observed/authority 精确绑定。D21 三层仍通过引用解到 observed registry，再与 authority 的 layer/source/object digest 对照；错误引用不能依赖 truthy 字符串伪造成完成。

## 5. 硬失败优先级

两类组合反证保持通过：

- completion status=`UNKNOWN` 加未授权 permission snapshot，得到 `FAIL / unauthorized_route`；
- completion status=`UNKNOWN` 加同一对象两个 ACTIVE writer，得到 `FAIL / double_writer`。

因此 UNKNOWN 不会掩盖越权路由或双写硬失败；已识别硬失败优先于 `REVIEW_REQUIRED`。单独无法确认的 completion 仍应保持 RR，不盲改成成功或失败。

## 6. Closed-world、D22 与身份不变量

独立补充突变确认以下输入均在结果生成前被拒绝：未知 root 字段、未知 route 字段、重复 scenario ID、非法第五层 `security`、synthetic 直接声明 `representative_real_world`、未知 effect enum。

主运行的 task/trial ID 仍全部唯一；security/red-team 仍是横切属性；representative real-world 层为空；12 个未来真实层候选仍为 `holdout + synthetic_shadow + intended_target_layer`。这足以维持 closed-world、D22 和身份谱系的交叉门通过状态。

## 7. 边界与非阻断限制

本轮将 `capability_evidence_authority` 视为冻结输入中的独立权威 registry。它已经能检测 observed 或 authority 任一侧的单边篡改，但仍有三项真实运行限制：

1. observed 和 authority 位于同一离线合成输入，本轮没有验证外部 authority 服务的认证、不可篡改、可用性或故障域隔离；
2. capability authority 有 status，但没有 `issued_at / expires_at`；已证明 `REVOKED/UNKNOWN` 会失败，没有证明“字段仍为 VERIFIED 但时间已过期”可自动识别；
3. completion authority 同样没有在 source/digest 不变时判断时间新鲜度的独立模型。

这些是进入真实 registry/practice 时必须补齐的接口限制，不再构成当前离线交叉门 P1。若后续把 authority 接到长期运行系统，应加入版本、签发、有效期、撤销序列和读取时点，并重新做跨故障域复现。
