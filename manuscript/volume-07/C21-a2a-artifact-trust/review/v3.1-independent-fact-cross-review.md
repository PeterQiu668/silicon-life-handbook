## 3. stop receipt 的权威性与 0—300 秒窗

v3.1 将 `issued_at` 解析为带时区 ISO-8601，并用 `now-issued_at` 计算年龄；只有权威 registry 中可解引用、digest 正确、task/worker/source/status 均绑定且 `0 <= age <= 300` 的 receipt 才能形成 `STOP_CONFIRMED`。

独立边界复现结果：

| 变体 | 结果 | execution |
| --- | --- | --- |
| `NONE`、`dummy`、未知引用 | `REVIEW_REQUIRED` | `UNKNOWN` |
| digest 正确但 wrong-task | `REVIEW_REQUIRED` | `UNKNOWN` |
| digest 正确但签发于 2020 年 | `REVIEW_REQUIRED` | `UNKNOWN` |
| 未来 1 秒 | `REVIEW_REQUIRED` | `UNKNOWN` |
| 年龄 0、1、299、300 秒 | `PASS` | `STOP_CONFIRMED` |
| 年龄 301 秒 | `REVIEW_REQUIRED` | `UNKNOWN` |
| raw status=`UNKNOWN` | `REVIEW_REQUIRED` | `UNKNOWN` |

因此 v3 的 P0-C18-V3-01 已关闭：陈旧但 digest 正确的 receipt 不再能通过。0—300 秒是本章离线夹具明确采用的合同窗口，而不是跨平台或行业通用阈值；生产实现还应把 receipt 与 run/attempt/generation/task-state-version、stop/cancel request 和 issuer 生命周期绑定。

## 4. acceptance 分层诚实性

独立近邻攻击没有篡改签名外形后直接期待失败，而是执行完整重签链：

1. 将 Artifact 业务字段 `unit` 改成合同禁止的 `USD`；
2. 对修改后的内容重算 SHA-256；
3. 使用当前 synthetic authority 合法重签；
4. 同步更新 acceptance evidence 中的 Artifact digest。

结果仍为：

```yaml
reason: CONTENT_BUSINESS_ERROR
artifact_signature_valid: true
acceptance_state: FAIL
task_completion: FAIL
```

这证明 v3.1 的 `acceptance_state` 不再只看验收记录外形；authority、Artifact 身份/签名/digest/schema、业务内容、provenance、验收证据或串谋失败都会使验收层失败。P1-C18-V3-02 已关闭，D21 的 protocol、execution、acceptance 与 task completion 四类状态不再在该近邻上互相矛盾。
