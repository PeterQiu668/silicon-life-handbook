# C19 v2.1 独立事实、交叉与运行控制复核

## 裁决

**v2.1 较初稿有实质进步，但事实门与交叉门仍为 `REVIEW_REQUIRED`。** 固定集、43 项作者负测、schema closed-world、离线拒绝 real-world、自填 real-world manifest、D22 四层、安全横切、动态 effect 计数和 fresh-temp 可重复均已实现；这些通过项继续保留。

独立评审另设计 15 项未出现在作者 regression 中的近邻攻击，15/15 均被误判 `PASS`。核心原因不是字段还少几个，而是 identity/policy/tool/skill/audit 等所谓“authority registries”仍与被测 scenario 同处一份、无外部 root digest 的输入；提交者可以同时改状态与权威表，形成闭环自证。此外，委托父主体、审批主体、secret 引用、egress allowlist、mount canonical path、incident evidence 与恢复状态仍未被完整绑定。

## P0-C19-v2.2-01｜建立输入之外的权威根

关闭条件：runner 单独接收只读 authority bundle 及预注册 root digest；scenario 输入不得定义或改写 identity、policy、credential、egress、tool、skill、plugin、audit-anchor 和 recovery authority。若仍为单文件夹具，至少必须由 runner 内置或第二个不可由 scenario 改写的 frozen authority 文件提供 expected digest，并验证 bundle digest。

## P0-C19-v2.2-02｜补齐主体、审批与凭证链

关闭条件：`delegation.parent_principal` 与 `approval.principal` 必须解引用 active human/service authority，并满足角色、租户、scope、时窗与非自批约束；approval/grant ID 非空且分别唯一；SecretRef 必须解引用 credential registry，而不是仅检查字符串前缀和 broker 名。

## P0-C19-v2.2-03｜补齐 sandbox、egress 与输入来源

关闭条件：mount path 先 canonicalize，再证明位于允许 root 内；egress allowlist 来自 policy authority 而非 scenario 自报；input provenance/content digest 绑定可解引用 fixture/evidence manifest。路径逃逸、状态自填域名和更换 provenance+digest 必须硬失败。

## P0-C19-v2.2-04｜补齐 effect、incident、recovery 与审计语义

关闭条件：audit event type/outcome/顺序/对象绑定具明确 enum 与状态转移，anchor 来自外部权威根；incident evidence refs 必须解引用；`PROPOSED + regression_pass=true` 等矛盾状态硬失败；orphan receipt、`status=NONE + external_side_effect=true` 和未引用 effect/receipt 均失败；`security_red_team_is_cross_cutting` 必须为 true。

## 门禁

- 初稿门：`PASS`。
- 事实门：`REVIEW_REQUIRED`；作者 v2.1 证据不足以关闭新 P0。
- 交叉门：`REVIEW_REQUIRED`；安全权威根、授权链和 D21/D22 状态尚未闭合。
- 实践门：`REVIEW_REQUIRED`；真实 Runtime、OS sandbox、credential broker、DNS/egress、外部 API、多租户和 incident recovery 仍未运行。
- 编辑、总编、RC：`not_authorized`。
