## P0-C19-v2.4-01：effect没有在执行时刻重验授权链

### 复现

以S16为差分控制，只把effect与receipt的`executed_at`、`readback_at`改到`2026-09-29 23:00`。Session、Delegation、Approval与Grant均从`2026-09-30 00:00`才生效，Credential更在`11:30`才签发。receipt按当前schema重算digest后，runner没有新增`EFFECT_EXECUTION_OUTSIDE_AUTHORITY_WINDOW`或等价理由。

### 根因

Session、Delegation、Approval、Grant和Credential均只在全局`evaluation_time`上验证为当前有效；effect只检查`executed_at`不晚于`evaluation_time`，没有在实际执行时刻重新计算五层授权与凭证资格。这允许一条当前有效的权威链为更早的未授权执行提供事后外观。

### 最小关闭条件

对每个terminal effect，以`executed_at`而不是只以`evaluation_time`验证：Session、Delegation、Approval、Grant均满足`not_before <= executed_at < expires_at`；Credential满足`issued_at <= executed_at < expires_at`；撤销记录的`revoked_at <= executed_at`时拒绝。effect、receipt和audit必须绑定同一授权快照digest。

## P0-C19-v2.4-02：readback仍可自封，且没有上界与独立观察者

### 复现

只把S16 receipt的`readback_at`改到`2026-10-02`，保持effect执行时间不变并按当前字段重算receipt digest。该时间晚于`2026-09-30 12:00`评估时刻，但runner没有新增`EFFECT_READBACK_TIME_INVALID`或等价理由。

### 根因

当前只要求`readback_at >= executed_at`，不要求`readback_at <= evaluation_time`。receipt由scenario携带并自行保存`authoritative_readback`与digest，没有独立readback registry、observer身份、authority reference或不可变readback digest。EFFECT audit事件只记录effect ID、receipt ID与outcome，并不绑定receipt digest、执行/回读时间或观察者。因此“日志链已锚定”仍不能证明回读本身来自独立权威源。

### 最小关闭条件

1. 将readback外置到冻结或独立签发的registry，字段至少包括`readback_id、effect_id、receipt_id、object/action/scope、observer、authority_ref、observed_at、terminal status、record_digest`。
2. 强制`executed_at <= receipt.issued_at <= readback.observed_at <= evaluation_time`，执行者与观察者职责分离；UNKNOWN保持`REVIEW_REQUIRED`且不得盲重放。
3. EFFECT audit事件绑定effect digest、receipt digest和readback digest，而不是只绑定ID/outcome；external anchor发行者必须解引用为有效审计主体。
4. 增加至少一个全部授权、receipt、readback、audit与incident/recovery都闭合的terminal effect `PASS`控制。当前唯一PASS是`NOT_EXECUTED`，不能证明执行成功路径。
