# C19 v2.4 effect 执行时授权与独立 readback 整改

## 结论与边界

本轮以修订作者身份关闭 `v2.3-independent-fact-cross-review.md` 提出的两项 P0，不构成独立事实、交叉、实践、编辑、总编或发布候选批准。离线合成 machine-control 现能在 terminal effect 的实际 `executed_at` 重验五层授权，并把 effect、receipt、独立 readback 与 audit 的摘要和时间绑定；真实 OpenClaw、Hermes、Muse、身份服务、凭证代理、网络出口、WORM audit 和外部系统仍未运行。

## P0-C19-v2.4-01：执行时授权重验

每个 `APPLIED / FAILED / UNKNOWN` terminal effect 以 `executed_at` 重验：

- Session：`issued_at / not_before / expires_at / revoked_at / status`；
- Delegation：`issued_at / not_before / expires_at / revoked_at / status`；
- Approval：`issued_at / not_before / expires_at / revoked_at / status`；
- Grant：`issued_at / not_before / expires_at / revoked_at / status`；
- Credential：`issued_at / not_before / expires_at / revoked_at / status`。

runner重算由 identity、tenant/session、delegation、policy、approval、grant、credential 构成的 canonical authorization snapshot digest。effect、receipt 和 readback 必须引用同一摘要；授权记录在执行前尚未生效、已过期、已撤销、状态失效或摘要替换均为硬 FAIL。

原独立逃逸 `effect-executes-before-all-authority-windows` 已在差分 oracle 下新增专属理由 `EFFECT_EXECUTION_OUTSIDE_AUTHORITY_WINDOW`，不能借基线已有 FAIL 冒充命中。

## P0-C19-v2.4-02：独立 readback 与时间链

readback 已从 scenario receipt 移出，进入冻结 authority bundle 的独立 registry。记录绑定：`readback_id、effect_id、receipt_id、object、action、scope、observer、authority_ref、observed_at、terminal_status、authorization_snapshot_digest、record_digest`。

runner强制：

1. `executed_at <= receipt.issued_at <= readback.observed_at <= evaluation_time`；
2. receipt 的 executor 与 readback observer 职责分离；
3. observer 解引用为有效独立审计 authority；
4. readback 的对象、动作、scope、terminal status 与 effect/receipt 一致；
5. EFFECT audit event 同时绑定 effect digest、receipt digest、readback digest 以及三段时间；
6. audit event 的顺序、canonical chain 与冻结外部 anchor 继续闭合。

原独立逃逸 `readback-after-evaluation` 已新增专属理由 `EFFECT_READBACK_TIME_INVALID`。新增 S23 为全部授权、terminal effect、receipt、独立 readback、audit 均闭合的 PASS 控制；因此成功路径不再只有 `NOT_EXECUTED`。
