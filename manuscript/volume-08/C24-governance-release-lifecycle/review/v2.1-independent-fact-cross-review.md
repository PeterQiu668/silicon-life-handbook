# C21 v2.1 独立事实、交叉与生命周期控制复核

## 裁决

**初稿门保持 `PASS`，事实门和交叉门仍为 `REVIEW_REQUIRED`。** v2.1 已关闭上一轮九个明确缺口，64 个固定 trial、61 项非 PASS 回归、closed-world schema、有限数值、角色 owner、migration/backup/restore/rollback/retirement receipts 和 hard+UNKNOWN 理由保留均可重复，属于实质性进步。

但非作者新增的 10 项近邻攻击仍全部得到 `PASS`。主要缺口是 registry 与场景仍共享同一可覆盖 state，D22 layer、rollout scope、runtime effect、暂停/回滚终态和法务/恢复环境缺少跨对象约束。因此，当前 harness 可以验证作者预置异常，却仍无法抵抗“同时改状态与其证明”的闭环自证。

## P0-C21-v2.2-01｜冻结权威根与可变状态边界

scenario override 不得修改 owner、authority、artifact、migration/backup/restore/D21/stop/rollback/retirement evidence 等权威 registry；权威 bundle 必须由 runner 独立接收并验证 frozen root digest。至少要阻断把 `agent-self` 在 owner registry 中自称为 human、同步改 migration/restore/D21 记录后获得 `PASS`。

## P0-C21-v2.2-02｜绑定 rollout scope 与真实运行对象

`allowed_tenants/tasks/actions` 不得为空，且必须与 trial ledger、runtime task/effect、release scope 和 approval 对象逐项对应；runtime task/schedule/webhook owner 必须解引用 active role owner；任何 `authorized=false` 的 effect，无论 internal/external，都必须失败。

## P0-C21-v2.2-03｜闭合 stage、stop、rollback 与 active release

离线 synthetic fixture 不得声称 `PRODUCTION`；`PAUSED/RETIRED/ROLLED_BACK` 必须与 admission、queue、workers、task、schedule、webhook 和 active release 一致。当前“rollback receipt 指向 v1、runtime 仍运行 v2”仍可 `PASS`，必须以硬失败关闭。

## P0-C21-v2.2-04｜为 D22、法务和环境建立可解引用证据

holdout 不能只是 label，必须绑定隔离 manifest、grader/gold 暴露状态、污染记录和 lineage；restore environment 与 legal region/scope 必须来自 registry 与允许集合，不能接受任意字符串或 self-report。真实平台迁移、恢复、canary、rollback、退役和法域合规继续保持 `REVIEW_REQUIRED`。
