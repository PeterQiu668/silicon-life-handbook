# C21 v2.4 作者整改记录

## 关闭合同

v2.4新增并冻结`publication_event_registry`与`lifecycle_event_registry`。发布事件把request、legal review digest、release approval、rollout plan approval、实际execution receipt和独立readback绑定到同一release、plan、主体、authority与canonical digest；退役事件把request、plan approval、retirement approval、实际execution、receipt/readback、逐项证据、residual scan和terminal signoff绑定为单一时间链。`rollout.starts_at`仅是允许窗口，`now`仅是评估时刻，二者都不能替代实际执行时间。

关键顺序合同为：

- 发布：`request <= legal review <= release/plan approval <= actual execution == receipt <= readback`；
- 退役：`request <= plan/retirement approval <= actual execution == receipt <= readback <= evidence <= residual scan <= signoff`；
- authority必须在实际执行时有效，且权威记录的签发时间不得晚于事件声明的批准时间；
- receipt/readback的release、plan、subject、actor/observer必须逐字段闭合，执行者不能兼任独立readback；
- 任一明确失败为`FAIL`，UNKNOWN只形成`REVIEW_REQUIRED`且不能覆盖硬失败。
