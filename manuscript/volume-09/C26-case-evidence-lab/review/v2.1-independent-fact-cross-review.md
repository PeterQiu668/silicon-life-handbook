# C23 v2.1 独立事实、交叉与案例证据控制复核

## 裁决

**v2.1 已把案例身份、授权、来源、脱敏、公开、环境、固定 release、预算、D21 与迁移公平合同改造成完整 raw-state，初稿门通过；事实与交叉门仍为 `REVIEW_REQUIRED`。** 67 项作者负测全部命中，离线拒绝真实案例身份和 real manifest 的边界有效。

非作者新增 10 项近邻攻击中，9 项被误判 `PASS`，撤回预算仅降为 `REVIEW_REQUIRED`。被撤回的 OpenClaw/Hermes release 仍可用于成功迁移；没有 reviewer 角色的人仍可评审；撤回 effect、内部 effect 回执与读回冲突被忽略；非空 adapter difference 不影响结论；scenario task/evidence ID 与 raw state 不绑定；trial/failure 分布可任意自填；公开记录可晚于评估时间。这说明 registry 已存在，但状态、时序、角色和运行分布还没有全部参与裁决。

## P0-C23-v2.2-01｜所有 registry 状态与角色必须生效

baseline/candidate release、budget、reviewer、effect、artifact、source、publication 和 migration 的 `REVOKED` 必须硬失败，`UNKNOWN` 才可进入 `REVIEW_REQUIRED`。reviewer 必须持有适用角色，且 author principal、authority principal、reviewer principal 与 independence group 有独立 registry 绑定。

## P0-C23-v2.2-02｜effect、publication 与时间线闭合

effect kind、external、status、receipt 和 authoritative readback 必须一致；撤回、FAILED、UNKNOWN 和未授权 internal effect 不能静默通过。publication released_at、authorization、redaction、artifact、review 与 suite evaluation time 必须满足单调时间线，未来发布不能成为已完成证据。

## P0-C23-v2.2-03｜scenario、运行分布与失败档案绑定

scenario 的 task/trial/run/evidence ID 必须解引用到预算、artifact、D21、migration 和 failure log；trial_count、failure_count 与完整 trial registry 动态聚合，failures_preserved 由失败档案重算，不能接受自填整数和布尔值。

## P0-C23-v2.2-04｜迁移差异必须进入裁决

`adapter_differences` 非空时至少进入 `REVIEW_REQUIRED`，涉及权限、数据、评测、终态或安全语义差异时硬失败；unsupported 与 NOT_APPLICABLE 必须给出可定位理由。迁移公平不仅比较 digest，还要验证 budget、release status、runtime environment 和结果分布。
