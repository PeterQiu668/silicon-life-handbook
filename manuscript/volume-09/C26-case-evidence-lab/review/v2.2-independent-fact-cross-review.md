## P0-C23-v2.2-FINAL-01｜authority root 未绑定 suite 与 scenario inventory

`root_payload()`只包含 `registries`；`suite_id`、`build_id`、`evaluation_time`、scenario 清单与 scenario ID 均不进入固定摘要。runner 只要求 `scenarios` 非空，不要求它与 builder 的 32 个 scenario 清单一致。

独立结果：

- I04 删除其余 31 个 scenario、仅保留 S01，输出为一个 `PASS`；
- I10 在授权窗口内移动 `evaluation_time`，S01 仍 PASS；
- I11 改名 `build_id`，S01 仍 PASS，result 也不回写 build provenance；
- I12 改名 `scenario_id`，S01 的案例事实不变且仍 PASS。

这不是普通审计字段缺失。scenario inventory 可被删减意味着 FAIL/RR 样本能够被选择性排除，而 `authority_root_digest`仍保持合法。

最小关闭合同：

- 固定根增加 `suite_manifest`，至少绑定 `suite_id`、`build_id`、`evaluation_time`、schema/version 和有序或规范化 scenario manifest digest；
- scenario manifest 对每个 scenario 精确绑定 `scenario_id / case_record_id / subject_id / task_id / trial_id / run_id / evidence_id`及全部 raw refs；
- 输入 scenario 集必须与 manifest 精确相等，不得增删、改名或重复；
- result 回写 suite/build/manifest digest，decision digest 同时覆盖这些 provenance 字段。

## P0-C23-v2.2-FINAL-02｜完整 registry 可被 scenario 选择性投影

当前 schema 只校验 `artifact_refs/effect_refs/trial_refs/failure_refs`是唯一列表，未要求列表非空或等于冻结 manifest 的完整集合。随后运行分布只在输入选择的 `trial_refs`上聚合，effect 检查只遍历输入选择的 `effect_refs`；D21 与 failure artifact 则可直接从全局 registry 解引用，即使该 evidence 没进入 scenario 的交付包。

独立结果：

- I05 从 S01 的 `trial_refs`删掉唯一 FAIL trial，同时清空 `failure_refs`、把计数改为 2/0，仍 PASS；
- I06 把 `effect_refs`清空，receipt/readback 不再执行，仍 PASS；
- I07 从 `artifact_refs`删掉 FAILURE_LOG，失败留痕仍被视为完整，仍 PASS；
- I08 只保留 PUBLIC_CASE，TECHNICAL/DELIVERY/ACCEPTANCE/FAILURE 四类 artifact 均缺失，仍 PASS。

因此 E-C23-039 所称“逐项核对……真实 trial/failure 分布”和第 2621 行所称“闭合 scenario ID、真实运行分布”目前过宽；E-C23-040 的 `2/23/7、79/79`只对冻结输入成立，不能外推为选择性披露控制已关闭。

最小关闭合同：

- 每个 scenario 的固定 manifest 必须列出 exact artifact/effect/trial/failure refs；输入只能完全相等，不能自行裁剪；
- 至少要求一个显式 effect record，即便它表示 `NONE`，receipt/readback 仍必须存在并核对；
- artifact projection 必须按案例合同要求精确覆盖 PUBLIC、TECHNICAL、DELIVERY、ACCEPTANCE，以及存在失败时的 FAILURE_LOG；D21 证据和 failure artifact 必须同时出现在 projection；
- trial/failure 分布从该案例在冻结 manifest 中的完整 trial 集聚合，FAIL trial 与 active failure record、FAILURE_LOG 双向一一绑定；不能由输入先选 trial 再计算；
- 增加“删 scenario、删失败 trial、删 effect、删每一类 artifact”的独立负测，并要求 FAIL 或 schema/root REJECT。

## P1-C23-v2.2-FINAL-03｜author principal 有角色但没有案例级任命

I09 把 S01 的 `author_principal_id`换成 S17 的 active `ROLE.CASE.AUTHOR` principal，仍 PASS。runner 会验证角色与 reviewer independence group，却没有验证该作者被任命到 S01 的 subject/case/version。

最小关闭合同：在 case identity、authorization 或单独 assignment registry 中固定 `principal_id + role + subject_id + case_record_id + case_version + validity/status`；别名必须通过权威 alias graph 归一化后再做 author/authority/reviewer 独立性与任命检查。

## P1-C23-v2.2-FINAL-04｜adapter criticality 仍依赖自由文本子串

当前 hard-fail 分类仅搜索 `PERMISSION/AUTH/DATA/EVAL/TERMINAL/SECURITY`六个英文子串。I18 明确模拟“运营方合法发布并重新钉住一个新 root”的升级路径，将关键权限边界差异写成 `PRIVILEGE.BOUNDARY.DIFFERS`；固定摘要已合法更新，但结论仅为 RR，而不是关键差异的硬 FAIL。

这不是当前输入攻击者可绕过的 pinned-root 漏洞，而是未来合法 root 升级时的规则泛化缺口。最小关闭合同：adapter difference 改为 closed enum/对象，至少包含 `category / criticality / affected_contract / evidence_ref / owner / disposition`；criticality 不得由自由文本关键词推断。非关键差异仍可 RR，权限/授权/数据/评测/终态/安全类别必须由枚举硬失败。
