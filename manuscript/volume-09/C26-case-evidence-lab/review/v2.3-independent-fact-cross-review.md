## 三、历史I18的正确解释

历史18项旧脚本表面输出`17/18`，唯一未命中的是`I18_AUTHORIZED_REPIN_CRITICAL_ADAPTER_SYNONYM`：实际结果为`REJECT / authority_root: canonical digest mismatch`，而旧脚本只把`FAIL`列为期望。

该`REJECT`在v2.3合同下是安全结果，不是逃逸。旧I18仍按v2.2 root形状只计算`{"registries": ...}`摘要，并注入自由文本adapter；v2.3要求root同时绑定schema、suite manifest和registries，adapter又必须是closed enum对象。因此旧样本在进入业务裁决前就应被拒绝。不能为了延续旧`expected=FAIL`而把安全REJECT误报为失败。

作者R23—R30已经用**结构合法、完整重钉的v2.3 root**另行验证closed-enum adapter，8项全部命中。本轮J12—J14进一步证明剩余问题不在“自由文本是否拒绝”，而在合法枚举的`category`与`affected_contract`之间没有一致性矩阵。

按v2.3合同重解释，历史18项为`18/18安全`。

## 四、P0阻断

### P0-C23-v2.4-01｜root冻结了registry，却未保证所有case语义记录被唯一投影

`validate_document`只对artifact/effect/trial/failure四类registry检查全局projection并集；D21和author assignment等registry可以包含未被任何scenario选择的并行真相。

- J01加入同case/task/run/evidence、`technical=FAIL`的第二条active D21，scenario继续选择原PASS D21，结果为`PASS`。
- J02让独立reviewer同时获得`ROLE.CASE.AUTHOR`和同case/subject/version/time的第二条active author assignment；scenario继续选择原作者，reviewer仍被判独立，结果为`PASS`。

因此“root包含了某记录”不等于“case裁决消费了该记录”。最低关闭条件是：对每种case级单值对象建立exact projection或语义唯一键；D21、reviewer、author assignment、publication、identity、authorization等必须按`case + version + task/run/evidence + time`证明唯一有效。评审者若在同一case/version/time拥有任何active author assignment，独立性必须失败，而不能只比较raw_state选中的作者。

### P0-C23-v2.4-02｜case时间线只在评估时点做局部检查，不能证明证据先于发布

J03—J06均在结构合法、完整重钉的root中得到`PASS`：

- 作者任命在publication后30秒才生效；
- trial记录发生在evaluation time之后；
- trial记录发生在authorization有效期之前；
- reviewer与publication均早于全部trial证据。

runner分别检查了author assignment在evaluation time有效、publication晚于review、publication处于authorization窗口，却没有把`authorization → author assignment → trials/evidence → review → publication → evaluation`串成一条因果时间线。结果是“当前均有效”替代了“事实发生顺序正确”。

最低关闭条件：为所有证据对象定义事件时间并按case重放；trial必须位于授权/任命窗口内且不晚于evaluation，review必须晚于所审trial、D21、Artifact和failure evidence，publication必须晚于review且不得早于其证据；未知或缺失时间至少为`REVIEW_REQUIRED`。

### P0-C23-v2.4-03｜FAIL trial、failure record与FAILURE_LOG尚未双向一一绑定

作者整改记录声称三者“双向一一绑定”，但J07—J09全部`PASS`：

- PASS trial可把`failure_ref`指向现有active failure；
- 两个FAIL trial及两个failure record可共用同一个FAILURE_LOG；
- 额外的FAILURE_LOG可以进入精确artifact projection，却不被任何failure record引用。

当前`preserved`只比较FAIL trial与active failure数量，并检查每条failure指向“某个”FAILURE_LOG；没有检查PASS/UNKNOWN trial的`failure_ref=NONE`，也没有检查failure与FAILURE_LOG一一对应及所有FAILURE_LOG被反向消费。

最低关闭条件：PASS/UNKNOWN trial不得指向active failure；每个FAIL trial恰好一条active failure；每条active failure恰好绑定一个唯一FAILURE_LOG；每个投影内FAILURE_LOG恰好被一条failure消费。若设计允许共享日志，必须把“一一”改为显式多对一schema并验证日志payload完整枚举所有failure，不能保持当前文字承诺。

### P0-C23-v2.4-04｜effect类型与`external`布尔量可互相矛盾

J10把`effect_kind`改为`EXTERNAL_WRITE`，同时保持`external=false`，并生成内部一致的receipt/readback与digest。结果为`PASS`，`external_effect_count=0`。

runner只按`external`布尔量计数和触发离线硬门，没有约束：`EXTERNAL_WRITE ⇒ external=true`、`NONE/SYNTHETIC_WRITE ⇒ external=false`。这使合法root可把外部写标成内部写，直接破坏“外部effect为0”的核心证据。

最低关闭条件：用单一closed enum派生external，或建立不可矛盾的映射；外部计数必须从effect kind、receipt、readback和最终裁决共同派生，任何矛盾硬失败。

### P0-C23-v2.4-05｜D21只验证引用存在，不验证证据内容支持状态

J11把`ARTIFACT.TECHNICAL.S01`改为digest正确、绑定正确、active的`{"technical":"FAIL"}`，D21仍声明`technical=PASS`，最终结果为`PASS`。

当前Artifact payload只要求是对象并具有content digest；D21只检查Artifact kind/status/ref，不检查payload schema、裁判结论或状态一致性。因此“签名/摘要正确”仍可承载与D21相反的内容。

最低关闭条件：为TECHNICAL/DELIVERY/ACCEPTANCE evidence定义最小closed schema，至少包含subject/task/run/evidence、observable、verdict、grader/authority与digest；D21状态必须由三份证据派生或逐字段一致。无法自动判断的业务内容应进入独立grader/人类裁决并保持RR，不能仅凭Artifact存在给PASS。

### P0-C23-v2.4-06｜adapter的两个closed enum没有交叉约束

结构化enum关闭了自由文本逃逸，但J12—J14证明`category`和`affected_contract`可以语义冲突：

- `STATE_CARRIER / NON_CRITICAL`搭配`AUTHORITY`只得到RR；
- `TOOL_SCHEMA / NON_CRITICAL / ACCEPTED`搭配`SECURITY_BOUNDARY`得到PASS；
- `MESSAGE_SEMANTICS / NON_CRITICAL / ACCEPTED`搭配`D21_TERMINAL`得到PASS。

runner只按category决定是否属于critical类别，没有按affected_contract识别AUTHORITY、SECURITY_BOUNDARY、D21_TERMINAL等硬合同。closed enum阻止未知字符串，但不会自动保证两个合法值组合正确。

最低关闭条件：建立`category × affected_contract`允许矩阵，并让任一关键合同独立触发critical；category、contract、criticality、disposition四者不一致必须FAIL。不能允许低风险category为关键contract洗白。

### P0-C23-v2.4-07｜`decision_digest`未覆盖导出结果的身份与聚合声明

J15—J19在不改变`decision_digest=b7517aae...3fdea`的情况下完成以下篡改：

- 把首条trial的scenario/case/task/run/evidence身份全部换成另一对象；
- 把分布改为`32 PASS`；
- 把trial_count改为1；
- 把accepted_real_claim_count改为1；
- 把external_effect_count改为1。

当前digest只覆盖`provenance + (trial_id, derived)`，未覆盖每条trial的其余身份，也未覆盖顶层聚合。虽然可信消费者可以从完整trials重算部分聚合，但result没有随附验证器，且scenario/case/task/run/evidence身份无法仅凭当前digest恢复。导出的digest因此不能作为整个result的完整性证明。

最低关闭条件：定义closed result schema和独立verify函数；digest覆盖除自身外的完整规范化result，或至少覆盖完整trial identity、derived、所有聚合和provenance；验证器同时重算分布、计数、真实claim和外部effect，并与逐trial明细一致。
