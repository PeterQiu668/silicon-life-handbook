# C23 v2.4 作者整改记录

本轮只关闭 `v2.3-independent-fact-cross-review.md` 的七组 P0 与 19 项逃逸，不改写历史独立审校，不批准事实、交叉、实践、编辑、总编或 RC 门。正式章保持单一 H1、`23.1—23.7` 与 `fact_baseline`，没有重新嵌入历史长稿。

## 七组控制

1. case 级单值对象实行 exact projection 与语义键唯一。identity、authorization、source、redaction、publication、reviewer、author assignment、environment、D21 与 migration 不允许存在未被场景消费的并行真相；reviewer 在评审时点拥有任何本 case/version 的 active author assignment 即失去独立性。
2. 逐事件重放 `authorization → assignment → trial/evidence/effect/failure → review → publication → evaluation`。所有可裁决对象使用 UTC 事件时间；证据早于授权、晚于评审、晚于评估或发布早于评审均硬失败。
3. FAIL trial、active failure 与 FAILURE_LOG 构成双向闭合图。PASS/UNKNOWN 的 `failure_ref` 必须为 `NONE`；每个 active failure 只能绑定一个 trial 和一个唯一日志，日志 payload 反向声明 `failure_id/trial_id/outcome`，游离日志或共享日志被拒绝。
4. `external` 不再自报，而由 `effect_kind == EXTERNAL_WRITE` 唯一派生，并与 receipt/readback、逐场景计数、全局计数一致。离线外部 effect 继续硬失败。
5. TECHNICAL、DELIVERY、ACCEPTANCE 三类证据使用 closed payload，绑定 dimension、state、case/task/run/evidence。D21 三态与证据内容不一致时硬失败。
6. adapter 使用 category × affected_contract × criticality × disposition 允许矩阵。AUTHORITY、SECURITY_BOUNDARY、D21_TERMINAL 等关键合同不能由非关键 category 降级；关键差异必须为 CRITICAL/FAIL。
7. result 使用 closed schema；decision digest 覆盖完整 trial identity、derived、aggregates 与 provenance。独立 `verify-case-result.py` 重算分布、计数与完整 canonical digest，拒绝字段注入和任何结果篡改。
