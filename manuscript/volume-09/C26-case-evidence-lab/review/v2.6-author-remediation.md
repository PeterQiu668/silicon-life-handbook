# C23 v2.6 作者整改记录

> 状态：`drafting / unapproved`。本记录只说明作者侧整改与合成回归，不构成事实门、交叉门、实践门、编辑门、总编门或RC批准。

## 本轮关闭目标

v2.5非作者终审留下八组机器控制逃逸：FAILURE_LOG可晚于D21；基线与候选可同步伪造task或input；双方可同步扩展生产写权限、替换生产数据或改成作者自评grader；跨scenario可成对互换预算；`RECONSTRUCTED`可不披露缺失项和推断项。另有两项出版污染：正文对D21 payload和result envelope承诺超过实现，`E-C23-042`证明范围过宽；正式章与账本还直接暴露内部历史源稿链接。

## 控制变更

- 新增彼此独立且进入固定authority root的`task_authority_registry`、`input_authority_registry`、`permission_authority_registry`、`dataset_authority_registry`与`grader_authority_registry`。scenario对五类对象执行exact projection，不能只同步改写两侧预算。
- 每份预算绑定`case_record_id / case_version / task_id / run_id / side`、五类authority引用、任务/输入/权限/数据/评测摘要、风险、全部成本构成及`contract_digest`；migration两侧合同再绑定对应预算摘要。跨scenario整组互换因此无法保持case/task/run/side一致。
- 离线permission authority只允许合成读写权限，生产写硬拒；dataset authority同时核对数据摘要、权利状态、环境模式与案例身份，生产数据不能借“双边相等”通过。
- grader authority绑定独立reviewer principal；principal角色、alias、independence group与case级作者任命共同裁决，作者自评即使两侧相同仍失败。
- 因果链新增`failure <= FAILURE_LOG <= D21 <= review <= publication <= evaluation`消费约束；晚到日志不能追溯性支持已形成的D21、评审或公开结论。
- `RECONSTRUCTED`必须同时提供非空`missing_elements`与`inference_list`，且identity与source逐项一致；合法重建仍降级为`REVIEW_REQUIRED`。
- 正文已改为与代码完全一致的六字段D21 evidence payload和实际result closed schema；Artifact信封字段与输入root中的证据引用不再假称进入payload或result row。
- 正式章不再直接链接内部事故长卷或preflight；证据账本通过`review/C23-prepublication-source-index.md`保留材料身份与摘要索引。`E-C23-042`缩窄为固定合成schema、builder、runner及列举攻击的局部证明。

## 回归结果

固定32 trial仍为`2 PASS / 24 FAIL / 6 REVIEW_REQUIRED`，真实claim与外部effect均为0。作者79项、v2.3 30项、v2.4 23项、v2.5 25项、历史19项、独立15项和上一轮独立36项全部重放；上一轮八项逃逸均转为`FAIL/REJECT`，36项零逃逸、两个正邻PASS。v2.6新增24项定向攻击全部命中，合法task authority与input authority重钉两个正邻均PASS。两个fresh-temp从builder重建的input、root、result与v2.6回归文件逐字节一致，摘要见`runs/v2.6-remediation-validation.yaml`。
