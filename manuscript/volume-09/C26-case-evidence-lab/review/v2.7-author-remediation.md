# C23 v2.7 作者整改记录

## 整改范围

本轮只关闭 v2.6 独立终审指出的两项结果语义 P0 与两项出版 P1，不改变案例身份、固定32条分布、真实实践边界或章节定义权。整改者不批准事实、交叉、实践、总编或RC门。

## P0关闭实现

公共 `verify_result` 不再接受 result 或 result+root 的低配验证。调用方必须同时提交 persisted result、冻结 authority root 和完整 source。验证顺序为：

1. 校验result closed schema、身份唯一性、有序manifest投影、聚合、provenance和完整canonical digest；
2. 使用冻结source与authority root重新执行完整 `evaluate`；
3. 对重放结果与持久化result做完整canonical比较；
4. 任一逐trial verdict、reason、计数、聚合、身份或provenance差异均拒绝。

内部 `_verify_result_envelope` 只由 `evaluate` 用于检查刚生成的信封，名称和文档明确不声称语义真实性。`verify-case-result.py` 只调用强制语义重放入口，不再保留先验自洽验证分支。

因此，FAIL→PASS和REVIEW_REQUIRED→PASS即使同时重写reason、distribution、计数与decision digest，也会因source重放不一致而拒绝；修复不依赖具体scenario名称或两个历史攻击样本。
