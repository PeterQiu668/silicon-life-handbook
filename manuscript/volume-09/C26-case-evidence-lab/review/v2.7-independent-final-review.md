## 二、已经关闭且应保留的能力

### 2.1 公开唯一入口的 source 重放

U03—U07 证明公开入口不能省略、置空或调换 source/root；U08—U12 对 verdict、reason、计数、顺序和完整 digest 做一致重写，均被公开入口拒绝。CLI 对伪造结果同样拒绝。说明 v2.7 新增的 source 语义重放在**调用公开入口时**有效，上一轮 P0 的主修复方向成立。

### 2.2 source、root、result 的组合移植与规范化

U13—U24 覆盖 result 身份/manifest/root 移植、source 删除与重排、registry 非等价重排、build identity 替换、source 内容重封、root 非等价重排和 root 内容重封，全部拒绝。等价的 source/result 空白与 JSON key-order 改写均通过正控；合法新 root 重钉以及在新 root 下重放得到的等价结果也通过。该组结果说明实现没有用“拒绝所有新文件”伪装修复，也没有把等价序列化误判成篡改。

### 2.3 解析、数值和重放边界

U25—U30 对 input/root/result 的顶层和嵌套重复 JSON key 均在解析前拒绝；U31/U32 的 `NaN`/`Infinity` 拒绝；U33 的 CLI 结果伪造拒绝。持久化结果与从同一 source/root 重算结果逐字节一致，两次 fresh-temp 重建全部输出相同。

这些通过项是有效回归证据，但不能补偿验证入口旁路这一硬失败。

## 三、P0 阻断项

### P0-C23-V27-01｜交付模块仍存在可调用的低配结果接受入口

作者将 `verify_result(result, authority_root, source)` 定义为公开强验证入口，并让 CLI 使用它；但 `run-case-harness.py` 模块级仍保留 `_verify_result_envelope(result, authority_root)`。它只检查 schema、投影、聚合、provenance 与提交结果自身的 canonical digest，不接收 source，也不重新执行案例语义，并以 `True` 表示接受。

U01 从固定结果选择一个 `FAIL` trial，将 verdict 改为 `PASS`、清空 reasons、重算 distribution 与完整 decision digest；U02 对一个 `REVIEW_REQUIRED` trial做相同改写。两份伪造结果经 `_verify_result_envelope` 均返回接受。函数名前的下划线只是 Python 约定，不是模块访问边界；任何导入该交付脚本的消费者都可直接调用它。这个结论不是把 Python 内部函数当安全边界，而是指出当前交付物所宣称的“所有消费者统一使用不可省略入口、没有低配路径”仍不成立。

精确关闭条件：

1. 从交付模块级命名空间移除可调用的 envelope-only verifier；可把内部自检内联到 `evaluate`，或封装为只在闭包内可达、不能被导入后作为验证器调用的实现细节。
2. 所有包导出、CLI、脚本复用和可被 introspection 发现的“验证/接受”函数，都必须强制接收 source + root 并进行确定性语义重放；任何 envelope-only 辅助函数不得返回可解释为“结果有效”的布尔接受值。
3. 把 U01/U02 保留为回归：直接导入并寻找旧低配入口时，必须得到 `AttributeError`/不可达，或调用统一强入口后 `REJECT`；不能只改名后留下等价旁路。
4. 公开入口、CLI、等价 JSON 规范化、合法 root 重钉与重放正控必须继续通过，避免以删除全部复用能力或拒绝所有新 root 假装修复。

在这条旁路关闭前，`E-C23-043`及正文关于“唯一入口”的证据上限只能理解为：**作者指定的公开入口与 CLI 已闭合**，不能外推为：**交付模块不存在其他可调用的结果接受路径**。
