# C23 v3.0 作者整改记录

## 整改对象

本轮只关闭v2.9非作者终审的两项P0及两项出版P1：

1. `canonical`仍从module globals解析，result-only常量patch可让FAIL→PASS重封结果通过。
2. 已捕获的`_evaluate_with_pin`函数对象仍从module globals解析`validate_authority_root`等传递依赖；把root validator改为空函数后，未授权自洽三元组可借CURRENT pin通过。
3. ledger遗留三个未消费V28 source。
4. A-C23-02仍向读者暴露版本化作者整改生产日志。

## 完整函数图冻结

`_freeze_trusted_semantics`在可信core构建时完成以下动作：

- 复制schema、平台版本、正则、类型和其他不可变运行常量到私有globals字典；
- 用捕获的原始`json.dumps`和`hashlib.sha256`建立私有canonical/digest闭包；
- 将无closure的全部模块函数用原`code`对象重建为以私有字典作为`__globals__`的新函数；
- 保留已自包含的strict parser closure；
- 从私有函数图取出`_evaluate_with_pin`，与私有canonical、strict parser、冻结pin rows和Path类型共同交给raw verifier closure；
- 删除模块中用于组装core的临时引用。

因此，运行后普通重绑公开`canonical / digest / validate_authority_root / validate_document / root_payload / exact / sha / validate_record / index_records / dt / evaluate / _evaluate_with_pin / strict_json_loads / _read_pin_registry`等名称，都不会改变既有core解析的引用。最终result比较也只调用闭包捕获的私有canonical。

## 定向回归

v3.0新增26项in-scope攻击，全部拒绝：

- v2.9两项真实逃逸：FAIL与RR两类result-only canonical、root validator no-op；
- canonical、digest、root_payload、exact、sha、document/record/index校验、时间函数逐项重绑；
- public/private evaluator、parser、`json.dumps`、`hashlib.sha256`、schema常量、pin reader和伪pin rows；
- canonical+validator、digest+exact两组组合patch；
- 保存的旧core、fresh reload、未授权CURRENT root、错误授权pin与fresh CLI forged result。

七项合法正控全部通过：raw text、bytes、Path、fresh CLI、合法repin raw/CLI，以及canonical和root validator同时被破坏时合法固定集仍由冻结core验证。v2.9非作者45项在当前实现上重放为`45/45`安全、六项正控全部通过。

两项直接改写`verify_raw_documents.__closure__` cell的演示仍能改变裁决。这需要任意同进程对象写能力，明确属于非目标边界；本轮没有隐藏或宣称防住。正式信任仍要求固定runner/verifier/pin registry摘要与fresh subprocess CLI。
