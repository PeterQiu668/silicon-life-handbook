# C24 v2.5 作者整改记录

## 整改结论

本轮针对v2.4独立终审的四组P0重构了离线控制，并保留58项固定集的`4 PASS / 52 FAIL / 2 REVIEW_REQUIRED`与五态分布。作者新增37项回归，当前为`37/37`拒绝；v2.4独立终审29项在当前版本重放为`29/29`拒绝，原ACTIVE、合法续证与完整三层再认证三个正控全部PASS。

这只是作者侧合成控制证据，不是事实、交叉、实践、编辑或总编门批准。真实OpenClaw/Hermes Runtime、代表性生产任务、外部认证authority与真实撤销传播均未运行，实践门继续`REVIEW_REQUIRED`。

## P0-01：完整因果时序

runner现显式验证以下偏序：

1. holdout lineage与grader preregistration不晚于首个相关trial；
2. 每个trial output不早于对应trial completion；
3. application signature、Artifact、manifest、failure archive与cost ledger不晚于独立review；
4. maturity、namespace、D21三面、所有trial及output均不晚于review；
5. review不晚于certificate issuance，lifecycle event不早于certificate；
6. material change之后，逐层trial完成后才能签发对应output，独立review晚于全部post-change trial与output。

固定夹具原先11:00签发trial output而11:11—11:13才完成trial，现改为每个output晚于对应trial且早于11:30独立review。时序矛盾进入明确FAIL reason，不再靠证书时点的一次性有效检查掩盖。

## P0-02：所有authority进入冻结root

authority root新增完整`authority_registry`。每个本地authority按ID冻结scenario、epoch、完整projection、projection digest与root record digest；`evaluate`先检查所有本地authority的精确投影，`auth_ok`再检查action、actor、subject、object digest、scope、status、时窗、principal role和root撤销状态。

因此issue、operate、appeal、lifecycle、material change及role-conflict exception不能借用root中REVOKED ID后在本地重建ACTIVE shadow。未被事件消费的authority也不能静默漂移。root另保留`revoked_authority_ids`，但它不再是唯一撤销控制。

## P0-03：D22逐适用层安全与变更谱系

root新增冻结`d22_policy`：training、regression、holdout为本离线控制的必需层，representative_real_world明确为离线不适用；`certification-redteam`是必需横切slice。重大变化的每个required layer都必须独立覆盖全部required security slices，不能以training层的并集覆盖替代regression或holdout。

root同时新增逐scenario `release_registry`，绑定application、subject、scope、change、pre-change release、post-change release、status与epoch。manifest的`pre_change_release`必须解引用该冻结记录；任意非NONE字符串不再被当成历史版本。逐entry继续绑定trial、output、layer、affected scope和release，并新增`trial completion <= output issuance < independent review`。

## P0-04：result来源摘要不可清空或互换

`input_sha256`现在是去除循环`authority_ref`后的完整输入canonical语义摘要，写入authority root；`authority_sha256`是完整authority canonical摘要。verifier无论是否收到source，都会把两个字段分别与各自权威来源比较；收到source时还会验证输入摘要并重新执行逐scenario语义。

空值、零摘要、input/authority互换、错误合法格式及重封完整decision digest均被拒绝。字段统一为`sha256:<64 hex>`。`authority_root_digest`继续独立绑定pinned root，三者不能互相代替。

## 主张降级

正文不再声称v2.4或v2.5普遍“零逃逸”或控制已经完全闭合。E-C24-052改为：作者37项与v2.4独立29项在当前离线合成版本重放未出现逃逸，范围只限列明套件；真实Runtime、未枚举攻击和外部认证程序均不在证明范围。
