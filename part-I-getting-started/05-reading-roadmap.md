## 0. 背景 · 为什么第零章之后最容易迷路

第零章给了你三样东西：一个能跑的 agent（0.2/0.3）、一张术语地图（0.4）、一个章节骨架（0.5）。**但从第 1 章开始，手册会分叉**：

- 想搞懂「为什么」的人，需要哲学线；
- 想马上动手的人，需要工程线；
- 想管团队的人，需要治理线；
- 想接入生态的人，需要接口线。

不分叉地一路读到底，大概率会在第 5 章「长期表现」处卡住。所以本节给你**四条路线 + 一张全景图 + 一个 30 天计划**。

结构：**背景 → 配置（路线图）→ 验证 → 实测环境 → 排坑 → 进阶**。

### 1.2 四条阅读路线（按角色选一条）

#### 路线 A · 哲学线（想先理解「为什么」）


```text

```

**适合**：开发者、运维。
**耗时**：约 6 小时。
**关键产出**：一个接入 MCP 工具、可被 plugin 安装的 agent。

#### 路线 C · 治理线（想管团队 / 管集群）

```text
0.5 四根问题 → 第五章 长期表现 → 第六章 治理系统 → 第七章 协同军团
```

## 3. 验证 · 你该读哪条路线

做一个 4 题自测（每题 +1 到你最像的选项）：

1. 你更想先搞懂原理还是先跑个 demo？ 原理→A / demo→B
2. 你的日常是写代码还是带团队？ 写代码→B / 带团队→C
3. 你要不要对接外部工具/协议？ 要→D / 不要→A/B/C
4. 你未来三个月会不会搞多 agent？ 会→C / 不会→A/B

得分最高的路线 = 你的起点。**没有唯一正确路线**，但**第三章必读**。

## 5. 排坑 · 阅读 6 坑

### 5.1 坑：从第一章开始逐字读
**纠正**：跳过第零章直接读哲学章，会因为没跑过 agent 而读不懂。

### 5.2 坑：把四条路线读成「必须全读」
**纠正**：路线是**起点**不是**全部**。按需交叉。

### 5.3 坑：跳过第三章直接看第九章 MCP
**纠正**：不懂系统骨架，MCP 绑定会变成「抄配置」。

### 5.4 坑：只读不跑
**纠正**：本书标「复制粘贴可跑」的代码块，**必须真跑**。跑过的和读过的，是两个世界。

### 5.5 坑：忽略 ⚡ 三章
**纠正**：第 5/7/8 章是差异化优势所在，是本书「为什么值得读」的答案。

### 5.6 坑：把本路线图当目录**全文**
**纠正**：完整的 12 章目录见 [../README.md](../README.md) 与各章目录页。

## 8 · 常见路线误区（4 条）

1. **「我全都要」**：四条路线全读一遍再动手 → 读完就忘。**纠正**：选一条，边读边做。
2. **「只读 ⚡ 三章」**：跳过地基直奔护城河 → 看不懂。**纠正**：第 2 章系统骨架必须先在。
3. **「按目录顺序死读」**：从第 1 章一路到第 11 章 → 在第 4-5 章卡住放弃。**纠正**：按角色路线跳读。
4. **「读完再动手」**：把手册当小说 → 零产出。**纠正**：每章至少产出一个可验收物。
